# 三方协作规程（人 × A × B）

本规程与具体项目无关：任何仓库把 `.trio/` 复制过去、改 `config.json` 里两三个参数就能用。

## 0. 一句话

**人只跟 A 说话；A 出解决方案、定判据、驱动并**全程监督**B、独立验收；
B 只负责实现，绝不判断自己做完没有。机械闸不许被任何人说服。**

## 1. 角色与边界

| 角色 | 负责 | 明确不做 | 边界靠什么保证 |
|---|---|---|---|
| **人** | 提需求、在群里发言、**最终验收** | 不中转消息、不直接指挥 B | 总线的角色权限（`HUMAN` 唤不醒 B） |
| **A**（Codex） | 理解需求 → 解决方案 → 判据 → 工作集+契约冻结 → 拆任务 → 驱动 B → **真机验收** → 判断闸 → 提交/升级 | 不写实现代码；不放宽判据让任务通过 | `roles/A.md` + 路由器的机械闸兜底 |
| **B**（Claude Code） | 技术方案 → 实现 → 交回说明 | 不写不跑测试、不判断完成、不碰工作集外的文件、**不响应 HUMAN** | **工具白名单 + 工作集 + 总线权限矩阵**（三重机制） |

三者里只有 A 对人负责。

## 2. 一次任务的链路

```
人在群里提需求（role=HUMAN，只能唤醒 A）
  → A 有歧义就问人
  → A 写解决方案（.trio/solutions/NNN.md）
  → A 拆任务，每个任务写任务书（.trio/tasks/T-NNN.md，含工作集 + 契约冻结）
  → A 驱动 B：python .trio/router.py drive --task T-NNN --brief .trio/tasks/T-NNN.md
        │
        ├─ 路由器起 B（headless Claude Code，工具白名单，回合预算硬闸）
        ├─ 全量事件流落 .trio/log/raw/b-T-NNN.jsonl（A 可随时看）
        ├─ 机械闸盯着：重复 / 空转 / 墙钟 / 花费 → 触发即掐断 + 发 SYSTEM/gate 唤醒 A
        └─ 人可按群界面上的掐断按钮（写 log/kill.flag，路由器轮询到就停）
  → B 交付（as.py b --kind deliver）
  → A 独立验收：既有测试 + 自己的验收测试 + 真机验证；证据发进群（--kind verify）
  → 不通过：A 回灌（只带失败原文 + 一条小要求）
  → 通过：A git 提交，在群里给结论
  → 人最终验收 → 反馈 → 下一轮
```

一次任务的收敛标准：**A 的证据能被人独立复现**（命令 + 原始输出 + diff），而不是"实现方说好了"。

## 3. 目录契约

```
.trio/
  PROTOCOL.md      本规程
  DESIGN.md        设计决策记录（为什么这么做）
  KICKOFF.md       给 A（Codex）的会话开始提示词
  config.json      所有可调参数（闸门、白名单、端口）
  bus.py           群总线：唯一的通信通道 + 角色权限矩阵
  router.py        路由器：机械闸 + B 的驱动
  serve.py         群界面（浏览器，人在里面看 + 说 + 掐）
  check.py         B 唯一的自检入口（只能 import）
  verify.py        A 唯一的验收入口（判据落成文件，一条命令跑完）
  a_ledger.py      A 侧花费台账（只读 Codex 线程库，**代理指标不是账单**）
  as.py            B/A 固定身份的发言入口（不能冒充）
  roles/           A.md / B.md / CONTRACT.md
  tasks/           任务书（A 写）+ `T-NNN.checks.py` 判据文件（A 写，verify.py 跑）
  solutions/       解决方案（A 写）
  reports/         每个任务的**证据包**（A 写：探针脚本、真机截图、实测数值）
  tests/           零成本自检（总线 / 机械闸 / 群界面渲染）
  log/             群消息 + 全量事件流 + 运行状态（**不进 git**）
```

### 什么进版本库（判据只有一条）

**这块数据是不是每次都长得不一样？**

| | 例子 | 进 git？ |
|---|---|---|
| 是 —— 过程的残渣 | `.trio/log/`（事件流、group.jsonl、kill.flag、live.json）、`reports/**/*.jsonl` | **不进** |
| 否 —— 证据 | `reports/` 下的探针脚本 `.py`、真机截图 `.png`、实测数值 `.json`、闸门报告 `T-*.json` | **进** |

这条规则曾经被我写错过一次：整个 `reports/` 都被挡住了，理由是"跑出来的不是写出来的"——
而上面这张表里 `reports/` 明明写着"证据包"。**证据不进版本库，§6 第 4 条的"人能独立复现"
就是一句空话**：换台机器就没得复现了。

给 A 的具体要求：

- 真机验收的证据（截图、探针脚本、命令原始输出）**落到 `reports/<任务号>/`**，别只贴在群里。
  群消息是给人读的，`refs` 指过去的文件才是能复现的东西。
- 探针脚本写**成文件**，不要用一次性命令。`reports/<任务号>/` 下的 `.py` 会进版本库，
  下一个人（或下一个项目）能照着跑。
- 单轮几百 KB～几 MB 的原始事件流（`raw-*.jsonl`）不要往里放，那是 `.trio/log/raw/` 的事。

## 4. 群的协议

**语义节点**（`log/group.jsonl`，给人看）与**全量事件流**（`log/raw/`，给 A 和审计读）是**两条流**。
给 A 读的永远不美化，给人看的永远不当数据源。

### 谁能唤醒谁（红线）

```
HUMAN  --只能唤醒-->  A        ← B 永远收不到人的消息
A      --只有 task/kill 唤醒-->  B
B      --任何发言唤醒-->  A
SYSTEM --gate/escalate 唤醒-->  A
```

这不是约定，是 `bus.wake_targets()` 的返回值；B 的驱动侧只订阅 A 的 `task`/`kill`。

### 权限矩阵（`bus.PERMISSIONS`，越权抛 `PermissionError`）

| 角色 | 能发 |
|---|---|
| HUMAN | `say` `kill` `evidence` |
| A | `say` `task` `verify` `escalate` `note` `kill` |
| B | `say` `plan` `deliver` `note` ← **没有 verify/escalate/task/kill** |
| SYSTEM | `gate` `kill` `note` `escalate` |

**判据权与验收权归 A 独占，机制强制。**

## 5. 两道闸

### 机械闸（`router.py`，**不用模型、瞬时生效**）

四条触发条件，每条都是两级（软告警 → 硬掐断）：

| 条件 | 软告警 | 硬掐断 | 治什么 |
|---|---|---|---|
| 同一命令/只读动作重复 | — | ≥ 3 次 | "改一版跑一版" |
| 连续动作无任何文件写入 | ≥ 12 次 | ≥ 30 次 | 探索空转 |
| **距上次写入的事件量** | ≥ 2000 | ≥ 8000 | **烧钱**（事件数≈花掉的钱：上一版烧掉的那轮有 22620 个事件、只有 12 次工具调用） |
| 单回合墙钟 | — | > 600s | 挂死 |
| 真实花费 | — | > ¥1.5/单次 drive、> ¥3/一轮需求 | 账单 |

> **两个花费闸量的口径不同，别混**：
> *「单次 drive」= 这一次 drive 前后两次余额读数之差（滞后大，短回合常读成 0.00）。
> *「一轮需求」= **同一任务**的全部 drive（含回灌）累计——**换任务就重开基线**，
>  旧基线进 `log/spend.json` 的 `history`；怀疑账户里别处的用量顶了这道闸时，
>  用 `router.py drive --reset-session` 显式重开。
>
> 余额是**账户级**的：本机任何 DeepSeek 用量（人在别的项目里跑 Claude Code）都会算进来，
> 所以这道闸**会误杀**，2026-09-23 咬过两次（B 0 动作、¥0.00，闸报 ¥3.85 / ¥4.30）。

软告警**不掐断**，只往群里发 `SYSTEM/note`——**这是 A 在烧完之前介入的机会**。
稍大的任务本来就需要先读一批文件，一刀切会误杀。

> 阈值在 `config.json` 里，按项目调。**在贪吃蛇上调出来的值不一定适用于大项目。**

### 判断闸（在 A 里）

收到 `SYSTEM/gate` 后，A 决定：回灌重试 / 换策略 / 升级给人。**"怎么办"永远不由路由器决定。**

## 6. 三重边界（B 侧）

上一版的教训：`PROMPT.md` 写了"禁止自写自测"，但白名单里开着 `Bash(python -c *)`——
**任意代码都能跑**，纪律形同虚设。所以 B 的边界做三重：

1. **工具白名单**（`config.json:b_allowed_tools`）：只有读 / 写 / `check.py` / `py_compile` / `as.py b`。
   **`python -c` 已经拆掉。** B 能跑的 Python 只剩三条，每条的身份和用途都写死。
2. **工作集**：任务书声明只准动哪些文件，越界即判本轮失败。
3. **总线权限矩阵**：B 发不出 `verify`/`escalate`/`task`/`kill`；`as.py` 不接受 `--role`，冒充不可能。

**判据**：把 `roles/B.md` 删掉，系统还拦不拦得住越界？拦得住 → 文件是有效的纪律；拦不住 → 文件是许愿。

## 7. 验收规范（A 侧）

每轮至少三件事，缺一不可：

1. **跑判据 + 既有测试**：`python .trio/verify.py <任务号>` 一条命令跑完——
   判据来自 `.trio/tasks/<任务号>.checks.py`（照任务书 §2 直译的纯数据），
   基线是既有测试套数（对 `config.json` 的 `test_baseline`）。
   数量不能降；新增功能由 A 自己写验收测试（`tests/` 归 A 独占，B 无权改）。
2. **真机验证**：真实进程 / 真实窗口 / 真实设备。**只在假对象上跑通不算通过。**
   （本项目就是这样发现"音频其实一点没响"的：`winsound` 不支持 `SND_MEMORY|ASYNC`。）
3. **留证据**：命令原文 + 原始输出 + 截图 + `git diff`，写进 `.trio/reports/` 并 `--kind verify` 发进群。
   `verify.py` 自己写的 `reports/<任务号小写>/verify.json` 就是判据那部分的汇总证据。

主观项（好不好看、手感如何）写 `verify: manual` **并列进 checks 文件的 `MANUAL`**——
它会以「需人工」出现在报告里、**永远不计入自动通过**，然后交给人判，不要硬塞给自动判定。

### 为什么要有 `verify.py`（说清它治什么，免得用错期待）

2026-09-23 实测标定：全库 3445 条 A 命令里，跑测试只占 **1.5%**、跑探针 **2.5%**，
真正的大头是 A **读源码**（**60.5%**，2083 条 / 7.89 MB 输出）。

所以 **`verify.py` 不会让 A 的总动作数明显下降**，别把它宣传成那个。
它治的是**回灌**：T-005 交付 5 次、回灌 4 次，每轮回灌 A 都要把判据面重新探索一遍；
判据落成文件之后，回灌能带原文，A 不必重走一遍。
（"读源码那 60%"是另一个问题，`AGENTS.md` 里有对应的纪律：验收只读工作集 diff。）

## 8. 大项目对策（小项目里看不出问题，所以必须提前写进 v1）

| 病根 | 小项目为什么没暴露 | 对策 |
|---|---|---|
| 上下文预算 | 相关代码一次全能读进来 | **工作集**（框住 B 的读取范围，禁探查） |
| 判据可判定性 | "179 个测试全绿"就判完了 | 判据必须写成命令/断言；编排器只认退出码，写不严就会假通过 |
| 耦合 | 一个文件里改完就完了 | 工作集越界即失败 + **契约冻结**（文件+符号+语义） |
| A 的验收带宽 | diff 几十行，能逐行读 | 验收从"读全量 diff"改成"**审越界 + 跑契约 + 真机**" |

## 9. 成本模型

- Claude Code 自报的 `costUSD` 是按 **Anthropic 价目表**算的客户端估算，不是账单。
  本项目实测：真实 DeepSeek 花费 ≈ 估算的 **1/35**。
- 所以闸门全部按**真实余额差值**算（`router.deepseek_balance()` 读 `~/.claude/settings.json`
  的 token 打 DeepSeek 余额接口），绝不采信 CLI 的估算值。

### 9.1 两笔账：B 有钱、A 只有代理指标（2026-09-23 加）

真实项目里，人的总花费是**两笔**：B 的 DeepSeek + A 的 Codex。以前只看得见一笔。

| | 有没有"钱" | 能读到什么 | 工具 |
|---|---|---|---|
| **B**（Claude Code / DeepSeek） | **有**：真实余额差值 | 单轮差值 + 本轮需求累计（换任务重开基线） | `router.py drive` 自动记进 `log/spend.json`；`router.py status` 看 |
| **A**（Codex） | **没有**：本机 `~/.codex/logs_2.sqlite` 里没有任何 token/cost 列（探针 `.trio/reports/readiness/peek_codex_usage.py`） | **代理指标**：每轮时长 + 逐条动作（命令 / 改文件 / 思考 / 消息），来自 `~/.codex/thread_history_1.sqlite` | `python .trio/a_ledger.py`（**只读**，`--json` 可机读） |

每一轮 `drive` 结束时，路由器会把当轮 A 侧台账的**会话级累计快照**写进
`log/spend.json` 的 `tasks[任务][i].a_ledger`，并把"这两轮之间涨了多少"打到 stdout
（给 A）与群界面（给人）；相邻两轮相减 = A 在这两轮之间干了多少。

**口径的边界写在明面上**：A 侧只有动作数与时长，**没有钱**；而且它要**A 主动去读**
（不像 B 的闸是路由器自动轮询）——这是弱机制，别当成闸。
真实项目的预算要按"B 的余额差 + A 在 Codex 用量面板上看到的额度"两笔一起看。

### 9.2 A 侧成本：唯一的杠杆是**换会话**（2026-09-23 加）

A 的花费 ≈ **动作数 × 上下文大小**——每条动作背后一次模型调用，每次调用都重发整段上下文。
所以这是**二次**的：会话越长，同样的动作越贵。压它有两条路，实测下来差得很远：

| 做法 | 打的是哪一项 | 实测占比 |
|---|---|---|
| 让验收变成一条命令（`verify.py`） | **回灌**时的重探索成本（T-005 是 5 次交付 / 4 次回灌） | 验收本身只占动作数 **4%** |
| **换会话**（`rotate-a`） | **上下文大小**这个乘数 | 会话已涨到 **9.58 MB** |

**别把上面两条说成"少跑命令"**——2026-09-23 实测 A 的动作构成：读源码/grep/列目录
**60.5%**、git 12.2%、trio 4.4%、探针 2.5%、跑测试 **1.5%**。真大头是 A **读源码**，
框架管不着；框架能管的只有"别让它在一个越来越大的上下文里反复读"。

**一个被推翻的旧口径**：不能按单个 `thread_id` 量 A 的上下文。会话会**换 rollout 文件
续写**（`rollout_ordinal` 跨文件连续可证：`[1..1705]` → `[1703..3658]`），单文件口径
既会漏计，又会**恰好在换文件那一刻归零**——那正是最该报警的时候。`a_ledger.summary()`
按会话把各文件的 `max(rollout_end_byte_offset)` **相加**。

| 动作 | 命令 |
|---|---|
| 看会话累计（人 / A 都能跑，只读） | `python .trio/a_ledger.py --session <a_session>` |
| 看候选会话、不写任何东西 | `python .trio/router.py rotate-a --show` |
| **换会话** | `python .trio/router.py rotate-a` |
| 群里还有什么欠着没做 | `python .trio/bus.py todos` |

阈值在 `config.json` 的 `a_rotate_context_mb`（实测会话总量 7.4–9.9 MB，故取 4.5）
与 `a_rotate_actions`（350）。**按项目重标**，见 `PORTING.md` §2。

**它是提示，不是闸**：过线只发一条 `SYSTEM/note`——`note` **不唤醒任何人**，
不会为"提醒换会话"再烧 A 一次额度。换不换、什么时候换，是 A 与人的决定。
（框架替 A 做决定 = 越权。）

**换会话时的交接用 `A/todo`，不要另建文件**：`bus.py` 的 `todo` 已经完整接线
（`PERMISSIONS` 给 A 与 HUMAN 都开了，有 `open_todos()`、有 `todos` 子命令、有界面渲染），
它的 docstring 原文就写着用途是"A 换会话、被压缩之后还欠着谁什么"。
收尾发 `python .trio/as.py a --kind todo --text "…" --ref reports/<任务>/verify.json`，
新会话第一件事读 `todos`。另建一个 `HANDOFF.md` 只会变成它的劣质复制
（单文件、每次覆盖、无勾选状态、无读者）——这个仓为"同一件事两处写法不一致"付过代价。

**`rotate-a` 的四道校验**（它比手改 config 多出来的价值全在这里，细节见 `router.rotate_a`）：
候选会话的 `cwd` 必须是本仓（`session_index.jsonl` 是**机器全局**的，实测 24 条横跨 4 个项目）、
原子写、写后**再用 `bus.config()` 读一遍**（那才是 `wake_a` 走的同一条路）、失败回滚。
投递能力**默认不验**（验它要真发一条唤醒，A 会醒来跑一轮 = 花钱）；要验加 `--self-test`。

`--bare` 砍底噪、`--resume` 吃缓存、角色文件保持短（它每轮都会随上下文重发）、
小回合 + 禁探查——这些仍然有效，但它们治的是**每一轮**的成本，换会话治的是**乘数**。

## 10. 可见性

- **主视图**：群界面（聊天式，浏览器）。看 + 说 + 掐 + **截图内联**——
  四件事终端都做不好，所以主视图是浏览器。

  > **由 `router.py` 保证打开，不靠人记得点。** `ensure_group_ui()` 在每轮 `drive`
  > 之前跑：端口活着就用现成的，没活着就起一个，并把浏览器弹出来。
  >
  > 这一条曾经断过，代价是人彻底变成瞎子：界面建好了、30 条消息一条不少，
  > 但没人在监听端口，**没有人被要求去开它**——旧版这份文档写的是
  > "双击 `start.cmd`"，`KICKOFF.md` 又让 Codex 别碰浏览器，于是三方都以为别人会开。
  > 教训还是那一条：**写在文档里求谁去做，就没有任何东西保证它成立。**
  > 现在它是机制，并且 `tests/test_group_ui_comes_up.py` 真的起进程、真占端口、
  > 真看浏览器有没有被叫到——不是查源码里有没有那行字。
  >
  > 手动开（调试、换端口、或想在 A 还在问需求时就先看一眼）仍然可以：
  > 双击 `.trio/start.cmd`，或 `python .trio/serve.py --open`。

## 12. 已知软边界（说清楚，不假装堵住了）

0. **★ 人在浏览器群里发言，唤不醒 A。**（2026-09-23 定案，人选了"就用 Codex 说"这条；
   ——**但 B 的交付与机械闸现在能唤醒 A 了**，见 §11 的实测与接线。）
   `bus.wake_targets({HUMAN, say})` 返回 `[A]`，但**没有任何代码去执行这个唤醒**——
   `router.py` 只轮询 `kill.flag`（`kill_requested()`），它**不读群日志**。
   A 只有在"这一轮自己想起来了 `bus.py tail`"的时候才会看到，那是**纪律，不是机制**。

   所以三方的实际通道是：

   | 方向 | 通道 | 有没有保证 |
   |---|---|---|
   | 人 → A（需求、澄清、验收反馈） | **Codex 会话里直接说** | **有**（同一轮对话） |
   | 人 → 群（记录、备注） | 浏览器发言 → 群日志 | 进得了日志，**A 不一定看** |
   | 人 → B | **不存在**（`wake_targets` 硬性返回 `[A]`） | 机制强制 |
   | 人 → 掐断 B | 浏览器「掐断」→ `kill.flag` → router 轮询 | **有**（唯一真机制） |
   | A → B | `A/task` `A/kill` → router `drive` | **有** |
   | B → A | `B/deliver` 等 → 群日志 | A 下一轮读群时看到 |

   这不是 bug，是**划清边界**：界面上的输入框已如实标注"这里说的话不会叫醒 A"。
   要变成真机制，走 §11（`codex queue`）。

1. **A 可以冒充 HUMAN**：`bus.py post --role HUMAN` 在 A 的权限内。
   这是**信任边界，不是机制边界**。修法（未做）：给 HUMAN 消息加签名 token，只有界面持有。
2. 群界面**没有鉴权**，只绑 `127.0.0.1`。本机上的任何进程都能发言。
3. B 理论上能**读** `.trio/log/group.jsonl`（它不在工作集内，但没有机制禁止读）。
4. `--inject`（长驻会话中途注入）代码路径存在，但**未验证**，见 §11。
5. 机械闸用事件量当"烧钱"的代理。换 provider 或模型后，1 个事件的真实成本会变，阈值要重标。
6. **界面的活动条不是机制。** 它只是给眼睛看的（`.trio/log/live.json`），
   丢了/坏了/写重了都不影响任何一次判定。人关掉浏览器不会让任何东西停下来。
7. **A 侧轮换提醒是代理指标，而且 `note` 唤不醒人。**（2026-09-23 加）
   两个原因叠在一起：(a) 它数的是**动作数与字节**，不是钱——本机读不出 Codex 的 token 费用
   （§9.1）；(b) 过线只发 `SYSTEM/note`，而 `note` **不唤醒任何人**（这是故意的，
   免得"提醒换会话"本身又烧 A 一次）。所以它**只能靠人自己看群界面**——
   人不在看页面的时候，提醒就是躺在日志里的一句话。这是"框架不替 A 做决定"的代价，
   说清楚，不假装堵住了。
   由此还有一条推论：`rotate-a --show` 挑出来的候选**只是候选**。它已经校了 `cwd`，
   但校不了"这个会话是不是你打算用的那个"——开两个都对本仓的会话时，它会取 `updated_at`
   最新的那个。拿不准就先 `--show` 看一眼再决定。

## 14. 红旗清单（出现就停下来问人）

- 判据无法写成命令或断言（说明需求还没想清）。
- 需要图形界面/硬件/主观判断，但任务书里没提前声明。
- 同一轮 B 被拒权限 3 次以上（白名单或任务边界错了）。
- 被机械闸掐断两次（任务切大了，要再拆）。
- 既有测试数下降，或 B 改了 `tests/`（越界，直接判本轮失败）。
- **A 在没有机械闸告警的情况下，连续两轮没看过 B 的事件流**（撒手不管的前兆）。
