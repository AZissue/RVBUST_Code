# T-009 任务书（A → B）— 读机器人位姿不许冻住界面

> 判据 `.trio/tasks/T-009.checks.py`。**先读 §5 工作集与 §6 契约冻结**（§1 末尾有个坑先说给你）。

## 1. 背景（A 已在真机上复现）

机器人这条链的每一次网络动作都跑在 **UI 线程**上，而且是阻塞式的：

- `MainWindow::onRobotConnect()` → `reader->connect(host, port)`
  → `QTcpSocket::waitForConnected(1500)`（`RobotPose.cpp:71`、`URRealtimeReader.cpp:34`、`NrcJsonReader.cpp:300`）；
- `MainWindow::readRobotPose()` → `reader->readPose()`
  → `waitForReadyRead(1500)`（`RobotPose.cpp:93`、`URRealtimeReader.cpp:68/88`、`NrcJsonReader.cpp:313/339`）；
- 而 `readRobotPose()` 有三个调用点：两个按钮（`onRobotRead` / `onRobotReadTouch`）
  和**拍照后自动读位姿**（`MainWindow.cpp:845`，最长用于连拍的那条路径）。

**A 的复现**（`reports/T-009/ui_stall_probe.py`）：把机器人地址填成一个黑洞地址
（10.255.255.1）再点「连接」——程序**自带**的 UI 卡顿看门狗（阈值 500 ms）当场记了一条：

```
[20:55:44] [WARN] [WATCHDOG] UI stall 1575 ms (预览=否 拍照=否 3D上传=否 点数=0)
```

也就是"点一下连接，界面僵 1.5 秒"，而且这条卡顿**连 `beginHeavyOp` 都没包**，
`[UI] … 耗时` 里看不到它。

**做完之后人能看到的**：点连接 / 读位姿 / 连拍时，界面不再僵；失败提示与现在的文案一样可读。

> ⚠ **坑先说**：`QTcpSocket` 有线程亲和性（属于创建它的那个线程），
> **不能**把同一个 socket 轮流丢给 `QtConcurrent::run` 的不同线程用。
> 正确形状是"让整条机器人通道住在一个专属线程里"——例如在 `MainWindow.h/.cpp` 里放一个
> worker QObject（自带那 4 个 reader、`moveToThread` 到一个 `QThread`），
> UI 线程只通过信号/槽与它来往。**worker 类就写在 MainWindow.h/.cpp 里**（见 §5：不许动 CMakeLists）。
