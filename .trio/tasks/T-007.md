## 1. 背景

来源是 A 代码审查第 1 条。四种机器人协议（Modbus / UR / 博纳斯 NRC / 埃夫特）
**已经把 `RobotPose::Reader` 接口实现了**（`src/logic/RobotPose.h:47`，
`URRealtimeReader` / `NrcJsonReader` / `EfortPoseReader` 都 `: public Reader`），
但 `MainWindow` 没用它，而是持有四个具体成员 + 一个 `int m_robotProtocol`，
把这套 if 链**抄了四遍**：

- `onRobotConnect`（`MainWindow.cpp:1109`，四段各约 28 行，只有字符串与读卡器不同）
- `readRobotPose`（`:1259`）、`robotLastError`（`:1279`）
- `onRobotDisconnect`（`:1228`）、`onRobotSimulateConnect`（`:1242`）

代价不是"难看"，是**加第五种协议要改五处**，而漏掉一处的表现是"连上了但读不出位姿"
这种要现场排查的怪毛病。

**做完之后人能看到的**：行为一个字都不变（连接/读取/断开/模拟都还是原来的效果），
但"加协议"只改一处。

## 3. 明确不做

- **不动四个适配器**（`RobotPose.*`、`URRealtimeReader.*`、`NrcJsonReader.*`、
  `EfortPoseReader.*`）—— 它们不在工作集里，一行都不许改。
- 不改协议号语义：`1=UR`、`2=博纳斯 NRC`、`3=埃夫特`、其它＝Modbus（带 format/scale/unitId/startAddress）。
- 不改任何界面文案、按钮显隐规则、日志级别；不改 `ToolsPanel` 的信号接线语义。
- 不改"模拟连接"的行为：无真机、每次读位姿数值 **+10**、恒成功。
- 不新增文件、不改 CMakeLists。

## 4. 不能破坏的既有契约

见 §8。核心：`RobotPose::Reader` 的四个方法签名不变；四个适配器类的公开 API 不变；
`MainWindow` 里与 `ToolsPanel` 相连的槽（`onRobotConnect` / `onRobotDisconnect` /
`onRobotSimulateConnect`）**参数个数与类型不变**（接线在 `MainWindow.cpp:384-390`，
你可以改实现，但改了签名就得同时改接线，且外部行为不变）。
