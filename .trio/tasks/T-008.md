# T-008 任务书（A → B）— 清理包 r1：两处"会说错话"的地方

## 1. 背景

T-008 是审查 #6/#8/#10/#11 的清理包。A 把它切成两轮，**这一轮只做两件"用户会被误导"的事**
（纯清理的行数/配色/缩进放 r2，不在这轮）：

**（b）SDK 崩了，界面却说"参数无效"。**
`HandEyeSDKBridge::safeCall`（`src/sdk/HandEyeSDKBridge.cpp:18`）捕获 SEH 后返回 false，
而 `handEyeCalibrationMarker` / `handEyeCalibrationTcpTouch` 把 `ret` 预置成 **-1**、
`safeCall` 失败时不再改 —— 于是 `CalibrationService::errorText(-1)`
（`CalibrationService.cpp:31`）把它翻译成「参数无效（文件夹/位姿文件/参数）」。
DLL 内部崩了、函数根本没跑，用户却去反复检查文件夹和位姿格式。现场排查方向被带偏。

**（g）PLY 的 list 属性让坐标整体错位。**
`PlyPointReader.h` 里 `p.size == 0` 的属性会被 `if (p.size > 0)` **悄悄丢掉**，
不进 `recordSize` → 后面 x/y/z 的偏移整体前移。T-006 已经把标量类型补全了，
但**顶点元素上的 `property list ...`** 仍走这条路（T-006 的 EVIDENCE §5 记的就是这条）。

**做完之后人能看到的**：SDK 真出问题时提示说的是"SDK 异常"而不是"参数无效"；
带 list 属性的第三方 PLY 不会再给出静默错值。

## 2. 判据

| # | 判据 | 怎么验 | 期望 |
|---|---|---|---|
| 1 | PLY 的 list 属性不再静默错值 | `verify: auto` —— `python reports/tools/qt_class_probe.py pixel_to_3d 19` | exit 0 且打印 `PASS` |
| 2 | SDK 内部异常与"参数无效"分开（文案层） | `verify: auto` —— `python reports/tools/qt_class_probe.py calibration_service 6` | exit 0 且打印 `PASS` |
| 3 | 桥接层真的用上了那个独立的码 | `verify: auto` —— `python reports/T-008/bridge_sentinel.py` | exit 0 且打印 `PASS` |
| 4 | 既有测试不退化 | `verify: auto` —— `ctest --test-dir build -C Release --output-on-failure` | exit 0 |
| 5 | 只动了工作集里的文件 | `verify: auto` —— `python reports/tools/workingset_guard.py` + §7 的四个文件 | exit 0 |

判据 1、2、3 都要求**一个明确的符号/行为**，它们写死在 A 的验收测试里，所以是契约：

1. `HandEyeSDKBridge.h` 里必须有一个 `constexpr int kSdkInternalError`，
   值**不能是 -1 或 0**（A 的测试直接引用这个名字，改名字两边一起断）；
2. 两个标定入口（`handEyeCalibrationMarker` / `handEyeCalibrationTcpTouch`）
   在 `safeCall` 失败时必须返回它；
3. `CalibrationService::errorText(kSdkInternalError)` 的文案要跟 `errorText(-1)` **不同**，
   不能含「参数无效」，并要说明是 SDK 侧的问题（含「SDK」「异常」「崩溃」任一）；
   `errorText(-1)` 保持现在的「参数无效」不变。
4. PLY：顶点元素上的 list 属性要么被正确跳过（x/y/z 仍解出真值），要么**明确拒绝**
   （`ok=false` + 非空 error）。**不许 `ok=true` 而坐标错**。

> ⚠ 验收测试会引用 `HandEyeSDKBridge::kSdkInternalError` —— 这个名字**现在还不存在**，
> 所以你第一次 `cmake --build` 会在编译 `tests/test_calibration_service.cpp` 时报缺符号。
> 那不是环境问题，是本任务要你加的第一个东西（`HandEyeSDKBridge.h` 里加常量）。
