# T-010 任务书（A → B）— 2D 浮层模糊：先量，再决定改不改

> 判据 `.trio/tasks/T-010.checks.py`。工作集与契约冻结见 §5/§6。

## 1. 背景

A 的审查（第 9 条）：`Image2DView::overlayBlurUnder()`（`src/ui/Image2DView.cpp:355`）
每画一次浮层就 `copy()` 一次背后画面、两次 `scaled()`（降采样 + 平滑放大）、再新建一张
QImage；而 `ViewOverlay::GlassOverlay::paintEvent`（`src/ui/ViewOverlay.h`）是**每次
paintEvent 都调用它**。2D 视窗上现在有 8 个浮层控件，预览 30 fps 时就是每秒 240 次。

**A 当时的结论是"先量再改"**：这笔开销可能是几十微秒（那就不该动它，动了是白改），
也可能是毫秒级（那就该按帧缓存）。**现在没有任何测量**——这就是本任务的红判据。

## 2. 判据

| # | 判据 | 怎么验 | 期望 |
|---|---|---|---|
| 1 | 有仪表，且实测浮层开销 ≤ 0.5 ms/帧 | `verify: auto` —— `python reports/T-010/overlay_cost.py` | exit 0 且打印 `PASS` |
| 2 | 既有测试不退化 | `verify: auto` —— `ctest --test-dir build -C Release --output-on-failure` | exit 0 |
| 3 | 只动了工作集里的文件 | `verify: auto` —— `python reports/tools/workingset_guard.py …（见 §5）` | exit 0 |

判据 1 的探针会真起程序、连相机、开预览、跑 12 秒，然后读 runtime 日志里的
`[OVERLAY] … per_frame_us=…` 行：**读不到就算失败**（说明没有仪表）；
读到之后取**中位数**，必须 ≤ 500 µs/帧。

**两种结局都算通过**：

- 量出来 ≤ 500 µs/帧 → **不要**再去优化（那是白改），把仪表留下 + 在交回说明里写出实测值；
- 量出来 > 500 µs/帧 → 按帧缓存（一帧内的 8 个控件复用同一次降采样；帧号/几何变了才重算），
  再让探针量一次。

## 3. 明确不做

- **不改浮层的样子**：模糊底仍是"控件背后那块画面的模糊副本"、仍然是 70% 合成
  （T-002/T-003 定下来的观感），圆角仍是 8px。
- 不改 2D 视窗的缩放/拖动/冻结、ROI 拖框、页签切换、点击取点的像素映射。
- 不动 3D 侧（`VisSceneView`）；不动 `ToolPanel`/`MainWindow`。
- 不引新依赖、不新增文件、不改 CMakeLists（仪表写进现有文件）。
- **别碰** T-012 的暂停 WIP（`MeasureTools.*` / `MeasurePage*` / `MeasurePages.cpp` / `ToolsPanel.h`）。
