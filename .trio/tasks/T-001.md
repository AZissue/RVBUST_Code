## 2. 判据（逐条可验证）

1. **选中「像素→3D」不再让程序退出。** 用 `python reports/T-003/repro_crash.py`，
   退出码必须为 0（探针会在进程消失时返回 1），且 6 个工具页全部 `alive: true`。

   > **根因（A 已证）**：`ToolsPanel::buildPixelTo3DPage()` 对同一个 `page` 调了**两次**
   > `wrapScrollable()`：`m_p2dPage = wrapScrollable(page, stack);`（第 246 行附近）
   > 与结尾的 `stack->addWidget(wrapScrollable(page, stack));`（第 345 行附近）。
   > 第二个滚动区把 `page` 从第一个滚动区手里抢走并进栈，第一个滚动区成了**永远没进栈的孤儿**，
   > 选中该页时进程以 `0xC00000FD`（STATUS_STACK_OVERFLOW）退出。
   > 旁证：`m_p2dPage` 指向那个孤儿滚动区 ⇒ `updateOfflineFreeze()` 的
   > `m_stack->currentWidget() == m_p2dPage` 恒假 ⇒ **离线冻结自第 12 回合起就是死代码**。
   > A 的实验：把第二处换成 `stack->addWidget(m_p2dPage)` 重新编译后**连点 6 页都不崩**；
   > 之后已把源码改回原样并重编译，所以探针打的就是现场那一版。
   > 你要做的是给出**正确的**修法（不是照抄 A 的实验补丁），并说明为什么它同时修好了冻结判据。

2. **工具页顶部那条横向滚动条不再压住标题 / 按钮。** 验收看图：
   `reports/T-003/`、`reports/T-002/` 里**修复后**重拍的截图（默认 820x620、
   放大 1500x860、最小 656x479 三个尺寸各一张，欧氏距离页 + 再加一个有横向内容的页）。
   要求：标题「欧氏距离」完整可读、不被任何条压住；`计算 / 复制` 不被压住；
   窗口从大拖到小再拖回大，横条不复现。

   > A 观察到的事实（供你定位，**不是结论**）：该页在 820x620 与 1500x860 **都有**这条横条，
   > 位置贴近页面左上、约 17px 高；同一份 UIA 控件树里**没有**控件横向溢出滚动区
   > （见 `reports/T-002/inspect_tree.py` 的输出：Group 欧氏距离 = `[739,196,1353,422]`，
   > 滚动区 = `[730,187,1362,775]`）。而同一套 `wrapScrollable()` 包出来的「手眼标定」页，
   > 横条出现在**底部**且只在窗口小的时候出现（`reports/T-002/03_660x460.png` 那种是真需要）。
   > 所以"内容太宽"解释不了欧氏距离页那条。**不许用"把横向滚动条策略设成 AlwaysOff"糊过去**——
   > 那会把文字切掉（§3 明确不做）。请找出它为什么会出现在那个位置。

3. **2D / 3D 视窗的浮层按钮与标签：无边框、无实心底色、背景是背后画面的模糊副本。**
   人眼看真机截图（2D 一张、3D 一张，必须能看出按钮位置背后的画面"糊了"而按钮外是清晰的）。
   现状与差距：

   - `src/ui/Theme.cpp::viewOverlayButtonStyle()` 现在是 `border: none` +
     **恒定** `background-color: rgba(0, 0, 0, 0.20)`；`viewOverlayLabelStyle()` 同样 0.20。
     **恒定 alpha 填充 = 人眼看到的"一块底色"**，这就是"上次没实现"的地方。
   - `src/ui/VisSceneView.cpp::setupToolbar()` 里的 `m_pickHint` 更是硬编码了
     `background: rgba(0,0,0,0.5)`（3D 视窗底部那条长提示），最显眼。

   > 技术约束（A 先查过，省你一次弯路）：3D 的浮层按钮带着
   > `WA_NativeWindow + WA_DontCreateNativeAncestors + WA_TranslucentBackground`——
   > 它们是盖在 OSG 的 OpenGL 原生子窗口上的原生窗口，Qt 侧 `grab()` **抓不到 GL 画面**。
   > 2D 侧是本进程画的 pixmap（`Image2DView` 的 canvas），真模糊可行。
   > 若 3D 侧在本方案内做不到真模糊：**必须在交回说明里写清"为什么"和你的替代做法 + 截图**，
   > 不许默默退回半透明底色。
   - 性能红线：2D 视窗是**实时预览**（相机 ~30fps），模糊实现不许把 UI 线程拖住
     （项目硬约束："Vis/3D 同步命令绝不放 UI 线程"是同一类风险）。若需要缓存/降频，说明你的选择。

- 不改按钮文字 / 顺序 / 位置 / 快捷键；不改 2D 页签的互斥选择语义；不动 `清除 ROI` 的禁用逻辑。
- 不动 `logic/`、`sdk/`、`app/`、`tests/`、`.trio/`、`third_party/`、`build/`（生成物）。
- 不为了模糊引入新的第三方依赖；不引 Qt 模块（如 QtQuick/QML）到本项目。
- 不改离线冻结的四条判据本身（只是让它**第一次真正生效**）。
- 不动 `reports/T-002/`、`reports/T-003/` 下 A 已有的文件（它们是**修复前**的证据）；
  修复后的截图请放 `reports/T-001/`。

## 4. 不能破坏的既有契约（同 §8，防漏，正文再点一遍）

- 工具窗口 15 个页面仍然**各自独立滚动**，缩到最小尺寸时不被切内容；
- 3D 浮层按钮的原生窗口属性不许丢（丢了会被 GL 子窗口盖住）；
- 2D 页签按钮 `checkable + autoExclusive`；`清除 ROI` 无 ROI 时禁用；
- `viewOverlayButtonStyle()` / `viewOverlayLabelStyle()` 的**所有既有调用点**要么继续编译通过，
  要么你同步改完并说明（默认：签名不变）。
