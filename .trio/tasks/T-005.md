## 1. 背景

来源是 A 代码审查第 3 条（本轮排第二，因为它是**唯一会让现场拿错数据**的一条）。

两个洞，都在保存路径上：

1. **假成功**。`CaptureFlow::save()` 调 `m_data->writeHandEyeOutput()` 之后
   **丢掉了返回值**（`src/logic/CaptureFlow.cpp:496`，undo 在 `:516` 同理）；
   而 `DataManager::writeMarkerOutput()` / `writeTcpOutput()`（`DataManager.cpp:157/172`）
   写 `pose.txt` / `cameraCapturePointXyz.txt` / `tcp.txt` 失败时只有 `qWarning`
   —— 进的是 runtime 技术日志，**不进界面**。于是磁盘满、文件被 Excel 锁住、
   目录只读时，界面照样弹「第 N 组数据保存成功」。应用内标定用的是内存里的位姿，
   所以当场看不出来；错的是**交付出去的那个文件夹**（现场拿它喂 SDK / 别的工具时
   才发现 pose.txt 是旧的或缺的）。
2. **备份不是原子的、恢复不验内容**。`writeBackupNow()`（`DataManager.cpp:228`）用裸
   `QFile` 写、不检查结果、没有版本字段；`findLatestBackup()`（`:323`）只按 mtime
   挑最新，**不验内容** —— 写一半被杀的半截 JSON 会在下次启动时被选中。

**做完之后人能看到的**：保存时写不下会**明说**（并且说清是哪个文件），不再说"保存成功"；
半截的备份不会被当成好的恢复。

判据 1 跑的是 A 已经写好的验收测试 `tests/test_save_export.cpp`（`tests/` 归 A 独占，
你不用改也不许改）。它钉死这些行为：

- `DataManager::writeHandEyeOutput()` 在任一导出文件写不下去时返回 **false**，
  且 `DataManager::lastExportError()` 给出可读原因**并包含失败的文件名**（用例里是 `pose.txt`）；
- 正常路径不回归：返回 true、`lastExportError()` 为空、`pose.txt` 内容与记录一致；
- `CaptureFlow::save()` / `undo()` 在这种情况**不许**发 `success=true` 的 toast，
  必须发一条 `success=false` 的 toast（文本含失败文件名）**和**一条 `level=="error"`
  的 `logRequested`（文本含失败文件名）；并且记录本身照常留下（数据没丢）；
- 备份 JSON 里 `version == 1`，且文件本身是**完整合法**的 JSON；
- `findLatestBackup()` 在两个候选里（老的完好、新的是截断的）必须返回**完好那个**。

> ⚠ 验收测试会调用 `DataManager::lastExportError()` —— 这个访问者现在**还不存在**，
> 所以你第一次 `cmake --build` 会在编译 `tests/test_save_export.cpp` 时报缺失的成员函数。
> 那不是环境问题，是本任务要你加的第一个东西（`DataManager.h` 里加声明、`.cpp` 里加实现）。
