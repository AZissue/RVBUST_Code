# MCC 操作逻辑测试台（批次 0 / 1a）

依据：`docs/UI全功能操作流程与一致性优化建议_20261110.md`。

独立 PySide6 原型，第一批验证统一操作外壳与离线任务闭环。
不连接相机、不调用配准算法、不读写正式会话。输入、候选、进度与结果均为模拟。
其他四种工作区是明确标记的迁移占位，尚未接入正式业务。

## 启动

在项目根目录执行：

```powershell
& 'D:\Program Files\Anaconda\envs\rvc\python.exe' prototypes/task_workbench/app.py
```

双击本目录 `run.cmd` 也可启动。关闭窗口后演练状态丢弃。

## 手工验收

1. 左侧勾选两个输入；单击第三项查看，确认右侧输入不变。
2. 取消“显示”勾选，确认只改变预览，不改变输入。
3. 进入配准任务，修改最大距离，返回目录后重新进入，参数保留。
4. 计算候选，等待约四秒；先检查模拟预览，再勾选确认并生成结果。
5. 新结果在左侧被选中；原输入保留；导出说明准确显示选中目标。
6. 候选生成后修改参数或处理输入，确认不能发布旧候选。
7. 勾选“本次演练失败”，计算后保留输入和参数，取消勾选后可重试。
8. 计算中切换专注视图，底部仍可安全停止；在途步骤结束后才停止。
9. 计算中修改输入，结束时拒绝过期结果；计算中关闭窗口被阻止。

## 后续迁移顺序与接线边界

1. 本批：固定三栏 + 离线演练任务 + 状态/Qt 测试，等待人工试用反馈。
2. 下一批：在本原型新增正式离线适配器，使用只读真实输入；任务快照携带输入 ID、来源修订、参数和 job ID。
3. 原型真实离线任务链通过后，迁入正式离线工作区；所有调用复用正式工作流，不复制算法。
4. 再逐个接入移动拼接、多相机、转台、机器人，每批独立验收；并发会话各自负责一个适配器，共享外壳由单个会话维护。
5. 最后迁移后处理与复杂检查页。

业务适配器需要提供：启动、请求安全停止、阶段进度、完成/失败；
回调必须校验 job ID 与来源修订。原型的 `QTimer` 仅作交互演练，不能带入正式采集。
原型通过不代表算法、实体设备、GPU、打包或客户机验证通过。

本批仅修改 prototypes，不升级产品版本，不修改 src、CHANGELOG 或启动入口。
