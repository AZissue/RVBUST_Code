# 005 — 测量说明只留在操作日志，工具窗口不再讲一遍（用户反馈 5）

## 背景

用户原话：「测量工具的一些测量方法和显示的数据怎么用和说明了什么并不清楚，有时候用户不容易理解，
可以在操作日志里进行操作和操作后显示说明，**工具窗口里面就不用说明了**。」

现状（第 10 回合 P4 做了前半段）：选中方法时会往操作日志写一条 `[测量-说明]`，测完写一条 `[测量-结果]`
（`MeasureMethods.h` + `LogPresentation.h`）。但 `MeasurePage` 里还挂着一个「说明」GroupBox
（`measure_spec_<id>`，五行：用途 / ROI 怎么画 / 输出 / 可信度 / 常见错法），占了工具窗口一大块。

本轮：**工具窗口删掉那一块，把该说的话说进日志**，并且日志要真的讲清"怎么用 + 这些数说明了什么"。

## 判据（逐条可验证）

1. `cmake --build build --config Release` 退出码 0；`ctest` 2/2 通过；
   `unit_tests` 不低于 **24 类 / 270 passed**（`tests/` 不许改）。
2. `src/ui/MeasurePage.cpp` 不再创建说明区：`rg "measure_spec_|QGroupBox\(QStringLiteral\(\"说明\"" src/ui/`
   无匹配；每个方法页仍然保留「测量」区（公差 + 运行）与结果区，不能把页面删空。
   `MeasurePage::explainLine()` 继续存在（工具页换方法时仍写日志）。
3. 日志文案升级：`MeasureTools::methodExplainLine(method)` 的返回文本必须同时讲清四件事，
   且每一件都用一个固定小标题作为可断言的关键词：

```text
用途：…        （这个方法在测什么）
怎么用：…      （ROI 怎么画、画几个、要注意什么）
输出：…        （会给出哪些数、单位是什么）
怎么看结果：…  （数值说明什么、可信度与常见错法）
```

   即：对**每一个**方法，`methodExplainLine()` 都必须包含 `用途：`、`怎么用：`、`输出：`、`怎么看结果：` 四个子串。
4. `[测量-结果]` 那条日志在原有数值之后，必须补一句"这组数说明了什么"（例如面面夹角的角值/平行度含义、
   孔径与公差的关系、重复性 σ 与样本数的关系），且**不改变**已有数值的格式与顺序（既有断言要能过）。
5. 日志落屏规则不变：`LogPresentation::shouldShowInPanel()` 仍只放行 `[测量-说明]` / `[测量-结果]`。
6. 真机（Codex 做）：选中一个测量方法 → 操作日志出现一条 `[测量-说明]` 且含上述四个小标题；
   跑一次测量 → 出现 `[测量-结果]`，数值后面带解释句；工具窗口里看不到原来那个「说明」块。

## 明确不做

- 不动测量算法（`MeasureTools.cpp` 的计算与数值一个都不许改）
- 不动 `LogPresentation.h` 的落屏策略、不动 `SidePanel`
- 不动像素→3D（刚验收）、不动机器人/标定/埃夫特（后面的任务）
- 不改 `tests/`、`codex_testData/`

## 不能破坏的既有契约

- 既有日志前缀不变：`[测量-说明]`、`[测量-结果]`
- 结果日志里的**数值与格式**不变（`measure_*` 相关既有单测必须继续通过；你只能往后面加句子）
- 页面上的控件 objectName 不得改名（`measure_tol_enable_<id>`、`measure_result_<id>`、
  `measure_roi_note_<id>` 等）
- `tests/` 归 Codex 独占

## 本轮允许的自检限制

- 最多 **1 条**编译自检：`cmake --build build --config Release`
- 不要跑 `ctest`、不要启动 GUI、不要拼接命令

## 交回格式（写到 `.pair/outbox/005.md`）

1. 文件清单与改动点
2. 一个方法的完整 `[测量-说明]` 文案（贴原文）+ 一个 `[测量-结果]` 文案
3. 判据 3 的四个关键词在代码里怎么保证每个方法都有（贴关键代码）
4. 实际执行的命令 + 原始输出
5. 不确定点
