# 010 — 埃夫特 SDK 缺 log4cpp.conf：把它部署到可执行文件旁边

## 背景（Codex 真机抓到的原文）

009 修完异常壁垒后，点「连接」不再崩，但日志给出真因（同一台机器、真实 exe）：

```text
[提示] 机器人连接失败：埃夫特：连接 192.168.0.1 失败（SDK 抛出异常：File log4cpp.conf does not exist）
[提示] 机器人连接失败：埃夫特：连接 192.168.0.1 失败（SDK 抛出异常：File log4cpp.conf does not exist）
```

**埃夫特 SDK 内部用 log4cpp，连接前要读当前目录的 `log4cpp.conf`**；缺文件时它直接抛异常
（这也是 008 那次整程序崩溃的根因）。SDK 自带的样例配置是
`third_party/EfortSDK/lib/log4cpp.nt.property`；Codex 已把它复制成
`third_party/EfortSDK/bin/log4cpp.conf`（1673 字节，内容就是 log4cpp 的 properties 格式）。

本轮只做一件事：**让这个文件在运行期出现在可执行文件旁边**，并顺手把这条依赖写进部署逻辑，
免得下次又踩。

## 判据（逐条可验证）

1. `cmake --build build --config Release` 退出码 0；`ctest` 2/2 通过；
   `unit_tests` 不低于 **25 类 / 279 passed**（`tests/` 不许改）。
2. 构建后 `build/src/Release/log4cpp.conf` 必须存在（post-build 部署，
   与既有的 Qt5/RVC/HandEyeSDK/OSG DLL 部署同一套写法；源文件用
   `${CMAKE_SOURCE_DIR}/third_party/EfortSDK/bin/log4cpp.conf`，
   找不到源文件时给清晰 CMake 报错，不要静默跳过）。
3. **真机（Codex 做）**：协议=埃夫特、默认 IP、点「连接」→
   ① 进程必须活着；② 失败原因**不再是** `File log4cpp.conf does not exist`
   （允许是连不上/超时这类网络原因）；③ 点两次仍不崩。
4. 回归：协议=Modbus TCP 点「连接」→ 与改动前一致（不崩、失败可读）。

## 明确不做

- 不改 `EfortPoseReader` 的异常处理逻辑（009 刚验收过）
- 不调 log4cpp 配置内容（先用 SDK 自带样例；真要改日志行为是以后的事）
- 不改其它三种协议、不改 `tests/`

## 本轮允许的自检限制

- 最多 **1 条**编译自检：`cmake --build build --config Release`
- 不要跑 `ctest`、不要启动 GUI、不要拼接命令
