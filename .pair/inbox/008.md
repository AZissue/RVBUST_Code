# 008 — 埃夫特（EFORT）机器人通信接入（用户反馈 7）

## 背景

用户找到了埃夫特的机器人 SDK：「在 D:\MyCode\EfortSDK，同理集成到机器人通讯那里」。
Codex 已把 SDK 拷进仓库的第三方目录（`third_party/` 已在 .gitignore 里，不进 git）：

```text
third_party/EfortSDK/include/   EfortSdk.h、EfortSdkNet.h、Robox*.h、SdkStructDef.h …
third_party/EfortSDK/lib/       EftSdk.lib / EftSdk.dll（+ log4cpp / rlibcpp 等依赖）
third_party/EfortSDK/bin/       运行期 DLL
```

机器人通信页现在有三种协议：`Modbus TCP` / `UR Realtime (30003)` / `博纳斯(纳博特) JSON/TCP`。
本轮照 `RobotPose::Reader` 的既有约定加**第四种：埃夫特**。
**没有真机可连**（用户已确认），所以验收只到"编译通过 + 代码走查 + Codex 单测"，不谎报真机通过。

## 判据（逐条可验证）

1. `cmake --build build --config Release` 退出码 0；`ctest` 2/2 通过；
   `unit_tests` 不低于 **24 类 / 271 passed**（`tests/` 不许改）。
2. 新增 `cmake/FindEfortSDK.cmake`，写法与 `cmake/FindHandEyeSDK.cmake` 同构：
   搜索 `${CMAKE_SOURCE_DIR}/third_party/EfortSDK`、`$ENV{EFORTSDK_DIR}`、`D:/MyCode/EfortSDK`；
   找到后导出 imported target `EfortSDK::EfortSDK`（`IMPORTED_LOCATION` 指向 `EftSdk.lib`，
   `INTERFACE_INCLUDE_DIRECTORIES` 指向 `include`）。`CMakeLists.txt` 里 `find_package(EfortSDK REQUIRED)`。
3. 新增 `src/logic/EfortPoseReader.{h,cpp}`：
   - 实现 `RobotPose::Reader`（`connect/disconnect/readPose/lastError`）；
   - **同时**导出一个纯函数给 Codex 写单测（不需要真机、不需要连 SDK）：

```cpp
namespace EfortPoseReader {
// SDK 读到的 6 个原始值 → 项目约定（位置 mm、姿态度、静态 XYZ，R = Rz*Ry*Rx）。
// rawIsMillimeter / rawIsDegree 说明原始单位；输出永远归一化成 mm + 度。
// 任一坐标非有限值 → 返回 false 且不改 out。
bool normalizePose(const double raw[6], bool rawIsMillimeter, bool rawIsDegree,
                   RobotPose::Pose& out);
}
```

   - `readPose()` 里用 SDK 读当前 TCP 位姿，再交给 `normalizePose()`；SDK 失败要映射成
     `RobotPose::Status`（`NotConnected/Timeout/ProtocolError/ConfigError`）而不是崩。
4. 机器人通信页的协议下拉新增一项，文本 **`埃夫特（EfortSDK）`**（放在 UR 之后、博纳斯之前都可以，
   但顺序一旦定下不要动），并在选中它时**隐藏 Modbus 专用字段**（与 UR 的处理一致）；
   默认端口给 SDK 的默认值或留空，并在界面提示里写清"埃夫特走 EfortSDK，IP 必填"。
5. `MainWindow` 里 `protocol == 3` 走埃夫特适配器（连接/断开/读位姿），
   `m_toolsPanel->setRobotConnected/ setRobotStatus` 与日志、侧栏提示沿用现有 UR/NRC 那套写法；
   连接失败要有可读中文提示（`lastError()` 带出来），不要静默。
6. 运行期 DLL 部署：像 HandEyeSDK/RVC 那样把 `third_party/EfortSDK/bin/*.dll` 拷到可执行文件目录
   （沿用现有 post-build 部署写法）；**不要把 DLL 提交进 git**。
7. 交回里必须单独写一段：**埃夫特位姿的欧拉角约定**（顺序/单位/是否和 FANUC WPR 那样反着），
   标明是"从 SDK 文档/头文件推断"还是"未确认"——项目里已经踩过 FANUC WPR 顺序相反的坑
   （见 PROJECT.md ADR / 全局记忆 `rvc-handeye-fanuc-wpr-convention.md`），
   没有真机就必须显式写"未确认"，不许含糊。

## 明确不做

- 不改 Modbus / UR / 博纳斯 三条既有链路的行为
- 不改 `RobotPose.h` 的接口与 `Pose` 结构语义（新适配器只是实现者之一）
- 不动像素→3D、测量、标定（都是刚验收过的）
- 不提交 `third_party/` 下任何二进制；不改 `tests/`、`config/`

## 不能破坏的既有契约

- `unit_tests` 全绿、数量不降（24 类 / 271 passed 是底线）；`tests/` 归 Codex 独占
- 机器人通信页既有控件 objectName 不变（`robot_protocol` 之类的现有命名不要改）
- 没有埃夫特 SDK 的机器上，**其它三种协议**仍必须能编、能连（即 SDK 缺失时要给出清晰的 CMake 报错，
  而不是连累别的目标）

## 本轮允许的自检限制

- 最多 **1 条**编译自检：`cmake --build build --config Release`
- 不要跑 `ctest`、不要启动 GUI、不要拼接命令

## 交回格式（写到 `.pair/outbox/008.md`）

2. `normalizePose()` 完整实现 + 你用到的 SDK 读位姿 API 名字（贴头文件里的声明原文）
3. 判据 7 的欧拉角约定说明（推断 or 未确认，写清楚）
4. 实际执行的命令 + 原始输出
5. 不确定点
