# 011 — 埃夫特 SDK 读 log4cpp.conf 靠"当前工作目录"，要跟 exe 目录对齐

## 背景（Codex 真机复现）

010 已把 `log4cpp.conf` 部署到 `build/src/Release/`（exe 旁边，部署本身没问题：
`Test-Path build\src\Release\log4cpp.conf` → True，ctest 2/2）。

但真机点「连接」仍报同样的错：

```text
[提示] 机器人连接失败：埃夫特：连接 192.168.0.1 失败（SDK 抛出异常：File log4cpp.conf does not exist）
```

原因已定位：**SDK 是按"当前工作目录"找这个文件的**。本仓库的启动脚本 `run.bat` 是
`cd /d "%~dp0"`（仓库根）后再启动 exe，所以 CWD ≠ exe 目录；双击 exe 或绿色版包内启动时
才碰巧对上。程序自己的运行日志也印证了这一点（`cwd: D:\MyCode\MyHandEyeTools`）。
靠"用户从哪儿启动"来碰运气不行，要由代码保证。

## 本轮只要求一件事

**在调用 SDK 之前，把当前工作目录临时切到可执行文件目录，调用完立刻还原**——
只在 `EfortPoseReader` 内、只包住那几次 SDK 调用：

```text
1) 进入前记下 QDir::currentPath()
2) QDir::setCurrent(QCoreApplication::applicationDirPath())
3) 调用 SDK（ConnectRobot 等）
4) 无论成功/失败/抛异常，都要还原成 1) 记下的路径（RAII 或 try/catch + 恢复）
```

要求：

- 还原必须可靠：SDK 抛异常也要还原（009 的 catch 分支里同样要还原）；
- 只影响埃夫特这条链路，**不许**在程序别处改全局 CWD；
- 保留 010 的部署（不要删 log4cpp.conf 的 post-build 拷贝）。

## 判据（照这个验收）

1. `cmake --build build --config Release` 退出码 0；`ctest` 2/2 通过；
   `unit_tests` 不低于 **25 类 / 279 passed**（`tests/` 不许改）。
2. **真机（Codex 做，必过）**：从**仓库根**（模拟 run.bat 的 cwd）启动 exe →
   协议=埃夫特、默认 IP、点「连接」两次：
   - 进程必须活着；
   - 失败原因**不再是** `File log4cpp.conf does not exist`（允许是连不上/超时等网络原因）；
   - 操作日志里必须看得到那两行"机器人连接失败：埃夫特…"。
3. 进程的 CWD 在连接前后不变（证明还原生效；Codex 会用启动日志里的 `cwd:` 行核对）。
4. 回归：协议=Modbus TCP 点「连接」→ 不崩、失败可读。

## 明确不做

- 不改 009 的异常壁垒逻辑（只在其外层加"CWD 切换 + 还原"）
- 不改 `run.bat`、不改打包脚本、不改其它协议
- 不调 log4cpp 配置内容、不改 `tests/`

## 本轮允许的自检限制

- 最多 **1 条**编译自检：`cmake --build build --config Release`
- 不要跑 `ctest`、不要启动 GUI、不要拼接命令
