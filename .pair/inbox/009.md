# 009 —（回灌）埃夫特连接把整个程序打崩了：SDK 异常不许逃出去

## 失败原文（Codex 真机复现，三次里复现三次）

操作序列与观测（真实 exe，Release 构建）：

```text
1) 启动程序 → 工具 → 机器人通信
2) 协议下拉选「埃夫特（EfortSDK）」（IP 保持默认 192.168.0.1）
3) 点该页的「连接」按钮（实测坐标 L837,T355,R915,B395，确实是机器人页那个，不是顶栏相机连接）
4) 5 秒内进程消失。程序自己的崩溃处理器留下：

   [CRASH] SEH 0xE06D7363 at 0x00007FF8A50D5369 module=KERNELBASE.dll
   [CRASH] time=2026-09-20 18:35:20.241
   [CRASH] ThreadId=12012 — 进程将立即退出以释放相机；无模态框、无等待。
   [CRASH] emergencyRelease: RVC::SystemShutdown() begin
   [CRASH] 相机释放尝试结束 finished=1 (<= 2000 ms)
```

`0xE06D7363` 是 MSVC 的 C++ 异常（`RaiseException`），从 KERNELBASE 抛出说明**有 C++ 异常
穿出了 Qt 槽**——Qt5 遇到槽里逃出来的异常会直接终止进程。原始日志在
`build/src/Release/logs/runtime_20260920.log`（18:32:52 与 18:34:44 两次同样的崩溃）。

对照：同一台机器上「协议=Modbus TCP」点连接不会崩；「协议=埃夫特」必崩。
**没有任何埃夫特真机**，所以这次连接注定失败——失败可以，但不能把程序带走。

## 这一次只要求一件事

**把埃夫特适配器里所有对 SDK 的调用都关进异常壁垒**：`connect()`（以及 `readPose()`/`disconnect()`）
里凡是调用 `EfortSdk`/`EfortSdkNet` 的地方，一律 `try { ... } catch (const std::exception& e) { ... }
catch (...) { ... }`，把异常翻译成返回值：

- `connect()` 失败 → 返回 `false`、`lastError()` 给出可读中文（例如
  `埃夫特：连接 192.168.0.1 失败（SDK 抛出异常：<what>）`），**绝不 rethrow、绝不调用 abort/terminate**；
- `readPose()` 抛异常 → 返回 `RobotPose::Status::ProtocolError`（连接类错误再细分 `NotConnected`），
  `lastError()` 同样带原文；
- `disconnect()` 抛异常 → 吞掉并记 `lastError()`，因为它在析构路径上。

另外：`MainWindow::onRobotConnect()` 里走埃夫特分支时，**任何 `false` 返回都要落到既有的失败 UI**
（`setRobotStatus(连接失败)` + 侧栏 tip + 日志），不许让槽函数带着异常返回。

## 判据（照这个验收）

1. `cmake --build build --config Release` 退出码 0；`ctest` 2/2 通过；
   `unit_tests` 不低于 **25 类 / 279 passed**（`tests/` 不许改）。
2. **真机（Codex 做，必过）**：协议=埃夫特 + 默认 IP 点「连接」→ **进程必须活着**，
   界面出现「连接失败」与可读原因（侧栏提示 + 操作日志各一条）；点两次也不许崩。
3. 回归：协议=Modbus TCP 点「连接」→ 与改动前一样不崩、有失败提示；
   协议=UR 点「连接」→ 同样不崩。
4. 代码复核：`src/logic/EfortPoseReader.cpp` 里每个 SDK 调用点都在 `try` 块内
   （grep `EfortSdk` / 连接函数名，逐个看是否被包住）。
