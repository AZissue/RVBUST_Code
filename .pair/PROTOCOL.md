# 双智能体协作规程（Codex × Claude Code）

本规程与具体项目无关：任何仓库把 `.pair/` 复制过去、改两个参数（验证命令、工具白名单）就能用。

## 0. 一句话

**人只跟 Codex 说话；Codex 拆任务、驱动 Claude、独立验收；Claude 只负责实现，绝不自证。**

## 1. 角色与边界

| 角色 | 负责 | 明确不做 |
|---|---|---|
| 人 | 提需求、真机实测、反馈体验与问题、拍板取舍 | 不直接指挥 Claude |
| **Codex** | 理解需求 → 拆成大小合适的任务 → 写判据 → 驱动 Claude → **独立测试/真机验证** → 通过才汇报 | 不把验收权交给实现方 |
| **Claude** | 按 `inbox/` 那一条任务实现代码，写交回说明 | **不写测试、不跑测试、不判断自己做完没有** |

## 2. 一次任务的链路

```
人提需求
  → Codex 写 .pair/inbox/NNN.md（背景 / 判据 / 明确不做 / 不能破坏的契约 / 交回格式）
  → python .pair/run-turn.py --turn NNN --inbox .pair/inbox/NNN.md
        （起看板 → 跑一轮 Claude，带回合内硬预算 → 自动跑验证命令 → 出证据包 → 关看板）
  → Codex 读 diff + 跑真机验证（截图 / 真实进程 / 真实音频等）
  → 不通过：Codex 写 NNN+1，**回灌只带失败原文 + 一条小要求**
  → 通过：Codex 提交 git，并向人汇报（附证据）
  → 人实测 → 反馈 → Codex 重定边界 → 下一轮
```

一次任务的收敛标准：**Codex 的证据能被人独立复现**（命令 + 原始输出 + diff），而不是"实现方说好了"。

## 3. 目录契约

```
.pair/
  PROTOCOL.md     本规程
  KICKOFF.md      给 Codex 的会话开始提示词（人复制粘贴用）
  PROMPT.md       注入给 Claude 的常驻系统提示（纪律）
  run-turn.py     一轮的执行器（起看板/跑 Claude/跑验证/出证据包/关看板）
  orchestrate.py  批次编排：多任务逐条跑到通过，失败自动回灌
  live.py         看板服务（只读日志，不调用模型）
  view.py         终端版合并视图（--role all）
  inbox/          任务书（进入 Claude 的唯一入口）
  outbox/         Claude 的交回说明
  queue/          批次队列（一次反馈多个问题时，Codex 拆成的任务清单）
  reports/        runner 生成的证据包（每轮一份）
  tests/          编排器自己的测试（不调用模型）
  logs/           原始事件流 + codex.live.log（不进 git）
  ledger.md       台账：每轮改了什么、验收结论、真实花费
```

## 4. 任务书（inbox）必须有的六块

1. **背景**：一段话，说明为什么做、现在的状态。
2. **判据**：编号列表，每条都是可验证的（能写成一个断言或一条命令）。
3. **明确不做**：把最容易顺手扩大的范围写死（"不要顺手重构 X"）。
4. **不能破坏的既有契约**：现有测试数、既有 API 语义、源码级契约（例如"某字符串必须还出现在 app.py"）。
5. **本轮允许的自检限制**：通常"最多 1 条语法/导入检查"，防止它自己进入调试循环。
6. **交回格式**：文件清单 / API 一览 / 实际执行的命令与原文 / 逐条对照 / 不确定点。

> 判据写得越像"机器能判的"，回合越短。**"实现了 X"不是判据，"命令 Y 退出码 0 且输出含 Z"才是。**

## 5. 回合执行规范（硬闸）

`run-turn.py` 固定这些参数，缺一不可：

| 闸 | 取值 | 作用 |
|---|---|---|
| `--bare` | 恒定 | 每次调用底噪从 ~17k 降到 ~1.4k tokens（实测 12×） |
| `--max-budget-usd` | 默认 4.0 | **回合内**硬闸：超限立刻 `error_max_budget_usd` 中止 |
| `--wall-timeout` | 默认 900s | 墙钟闸，超时杀进程 |
| `--effort low` | 默认 | 抑制长思考（DeepSeek thinking 会吃很多输出 token） |
| `--permission-mode acceptEdits` + `--allowedTools` | 精确白名单 | 写文件自动放行；shell 只放行明确需要的 |
| `--permission-prompts none` | 恒定 | 没人应答时**直接拒绝**而不是挂起等待 |
| `--resume <session-id>` | 自动 | 同一任务的上下文续用，吃 prompt cache（命中价便宜 50×） |

## 6. 权限模型

三档，按任务性质选：

1. **默认（推荐）**：`acceptEdits` + 精确白名单。写文件放行；只读命令（`ls`/`cat`/`grep`）本来就不需要审批；其余被拒。
2. **收紧**：`--permission-mode dontAsk` + 白名单。任何会弹窗的一律拒绝，并返回 `permission_denials` 记录。
3. **放开**：`--permission-mode auto`（本机实测可用，分类器代你审批）。只在你确定任务需要大量杂项命令时用。

**被拒的处理**：Claude 只记录、不绕过；Codex 在下一轮决定是否放行（写进白名单或加一条 `permissions.allow` 规则）。
需要人工点确认的场景（图形界面、硬件、真实相机）**事先从任务里剥离**，不要让它空转。

## 7. 验收规范（Codex 侧）

每轮至少做三件事，缺一不可：

1. **跑既有测试**：数量不能降；新增功能由 Codex 自己写验收测试（测试目录归 Codex 独占）。
2. **真机验证**：真实进程 / 真实窗口 / 真实设备。**只在假对象上跑通不算通过。**
   - 例：音频必须用真实 `winsound` 后端跑一次——本项目就是这样发现"音频其实一点没响"。
3. **留证据**：命令 + 原始输出 + 截图 + `git diff`，写进 `.pair/reports/` 与台账。

**不采信实现方的自述**：`outbox` 只是它的说法，只有 Codex 复现过的才算数。

## 8. 成本模型（重要）

- Claude Code 自报的 `costUSD` 是按 **Anthropic 价目表**算的**客户端估算**，不是账单。
  本项目实测：真实 DeepSeek 花费 ≈ 估算的 **1/35**（3 个实现轮真实 ¥1.75，估算累计 ≈ $9）。
- 真正要管的是**回合长度与上下文增长**，不是美元数字：
  - `--bare` 砍掉每轮 15.7k 固定开销；
  - `--resume` + prompt cache（命中比未命中便宜 50×）；
  - 小回合 + "禁止探查"（第 001a 轮就是死在探索空转上）；
  - 每轮用**余额差值**核对真实花费（runner 自动做）。

## 9. 可见性

**一个视图、同一时间轴、按角色分列**（`CLAUDE` 绿 / `CODEX` 品红）：

- 应用右侧面板的浏览器标签 `http://127.0.0.1:8760/`（Codex 可代你打开）；
- 或面板终端里跑 `python .pair\view.py --role all`；
- 或单窗口 `.pair\open-view.cmd`。

看板**只读日志、不调用模型、不消耗 token**；每轮结束由 runner 关闭，另有空闲自动退出兜底。

### 会话第 0 步（每个新会话只做一次，Codex 负责）

右侧面板**只能由 agent 的 tool call 打开**（Python 工具做不到），而且标签的常驻标记是回合级的，
新会话不会自动恢复。所以每个新会话开始时，Codex 必须先做这三件事：

1. 起看板（幂等，已经在跑就不会重复起；给整场会话一个较长的空闲上限）：

   ```bash
   python .pair/start-view.py            # 等价于 live.py --port 8760 --idle-exit 3600
   ```

2. 用浏览器工具把 `http://127.0.0.1:8760/` 挂到右侧面板，并标记为常驻
   （`cua.createBrowserTab(url, {visible: true})` + `tab.markDeliverable()`）。
   **开之前先 `cua.listTabs()` 看有没有同 URL 的标签**：已经有就复用；**每个会话最多新建一个标签**。
3. 确认面板里恰好一个 `Codex x Claude live` 标签后再开始拆任务。

**工具限制（实测）**：`cua.listTabs()` **只能看到 agent 自己创建的标签**，
看不到用户手动打开的标签（实测 listTabs 返回 `[]`，而用户面板里明明开着两个）。
所以：如果人已经开着一个看板标签，agent 再开就是第二个——**优先让人复用自己那个**，
agent 只在确认没有标签时才新建，并在汇报里说明"我新建了/沿用了你的"。

服务是可重启的：页面发现自己连不上时显示"服务已停止"，恢复后会自动重新加载；
看板服务重启（每轮都会）后页面会检测到编号回绕并自动刷新，不需要人手动重开。

## 10. 已知失败模式与对策（上一版踩过的）

| 失败模式 | 现象 | 对策（本规程） |
|---|---|---|
| 自写自测 | Claude 长自主循环，改一版跑一版 | 明令只实现；测试归 Codex；单轮墙钟 + 预算闸 |
| 假成功 | 它报告"已完成"，实际功能是坏的 | 必须真机验证 + 证据包；不信自述 |
| 成本失真 | 按 Anthropic 价目表算，误判成"烧钱" | 用余额差值核对真实花费；限制的是回合长度 |
| 白名单摩擦 | 复合命令每段都要放行 | 用只读命令集 + 精确白名单；必要时 `auto` 模式 |
| 可见性 | 两个 AI 的工作混在一个彩色日志里 | 一个视图、按角色分列；数据源是会话事件流（不看 stdout） |
| 角色模糊 | 分不清谁改的、谁验的 | 交接物是 commit + 证据包；台账逐轮记"谁做了什么" |

## 11. 新项目接入（5 步）

1. 复制 `.pair/`（`PROTOCOL.md`、`PROMPT.md`、`run-turn.py`、`live.py`、`view.py`、四个目录、`ledger.md`）。
2. 改 `run-turn.py` 里的 `--verify` 默认值（本项目的测试命令）。
3. 改 `--allow` 默认白名单（本项目要放行的命令）。
4. 在第一轮任务书里写清"不能破坏的既有契约"（现有测试数 / 既有入口 / 源码级契约）。
5. 把 `KICKOFF.md` 的提示词粘给 Codex，开始第一轮。

## 11.5 批次编排（人一次反馈多个问题时用这个）

人一次给一堆问题，Codex 先拆成任务清单，再交给编排器逐条收敛：

```markdown
# 批次 001

## 1. 修 R 重开错关卡的缺陷
- inbox: .pair/inbox/005.md
- verify: python -m unittest tests.test_restart_level -v
- max_attempts: 3

## 2. README 补协作说明
- inbox: .pair/inbox/006.md
- verify: python -c "import pathlib; t=pathlib.Path('README.md').read_text(encoding='utf-8'); assert '.pair/PROTOCOL.md' in t; print('ok')"
- max_attempts: 2
```

```bash
python .pair/orchestrate.py --queue .pair/queue/001.md \
    --budget 1.5 --total-cny 2.0 --total-wall 3600 --max-turns 12
```

编排器行为：

1. 逐任务执行：跑一轮 → 跑该任务的 `verify` → 退出码 0 就 PASS，进下一个任务；
2. 不通过就**自动生成回灌任务书**（`inbox/NNN-retry.md`：只带失败原文 + 一条小要求 + 交回格式）再来一轮，
   直到 `max_attempts`；
3. **连续两次同一个失败**就判 `BLOCKED` 并**停止整批**——不硬撑、不烧钱；
4. 前一个任务没通过，绝不继续下一个；
5. 停止条件：单轮预算、`--total-cny` 真实花费、`--total-wall` 墙钟、`--max-turns` 总轮数、任务书缺失；
6. 输出 `reports/batch-<id>-summary.md`：状态/尝试次数/最终退出码/轮次 + 未通过任务的残留失败原文；
7. `verify: manual` 的任务只跑一轮后标 `NEEDS_HUMAN`（主观/真机项永远留给人或 Codex 复核）。

**边界**：编排器只认"验证命令退出码"，即**机械通过**。面向人的结论仍要 Codex 读 diff + 真机验证后下判断；
任务书的判据写不严，编排器就会给出假通过，所以判据必须写成可执行断言。

编排器自己的测试（不花 token）：

```bash
python -m unittest discover -s .pair/tests -t .pair
```

## 12. 红旗清单（出现就停下来问人）

- 判据无法写成命令或断言（说明需求还没想清）。
- 需要图形界面/硬件/主观判断，但任务里没提前声明。
- 同一轮里 Claude 被拒 3 次以上（说明白名单或任务边界错了）。
- 被预算闸或墙钟掐断两次（说明任务切大了，要再拆）。
- 既有测试数下降，或它修改了 `tests/`（越界，直接拒绝本轮）。
