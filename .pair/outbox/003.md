## 2. 五条状态转换分别由哪段代码保证

| 状态转换 | 触发路径 | 生效代码 |
| --- | --- | --- |
| 打开面板但当前页不是像素→3D → 不冻结 | `showEvent` → `updateOfflineFreeze(false)` | `onPixelTo3DPage == false`（`m_stack->currentWidget()` 仍是「欧氏距离」页）→ 走 ended 分支，不发 request |
| 面板内从像素→3D 切到别的页 → 立刻解冻 | 列表 `currentRowChanged` → `onToolChanged` 首行 | 同上判据：切换后 `currentWidget() != m_p2dPage` → `emit …Ended()` |
| 从别的页切回像素→3D（离线、目录有效）→ 重新冻结 | 同上 | 三条全真（可见：面板开着；页面：`currentWidget() == m_p2dPage`；模式/图像：`!m_p2dOnline && hasImage`）→ `emit …Requested(path)` |
| 关掉面板 → 解冻 | `hideEvent` | 原样保留的 `emit pixelTo3DOfflineImageEnded()`（未改） |
| 模式切到在线 → 解冻 | `p2d_mode` `currentIndexChanged` → `applyPixelTo3DMode()` | `m_p2dOnline = true` 后调 `updateOfflineFreeze()` → `m_p2dOnline` 判据为假 → ended |

补充：`m_toolList::currentRowChanged → m_stack::setCurrentIndex` 这条连接是在
`buildUi()` 里**先于** `onToolChanged` 注册的，Qt 按注册顺序派发，所以 `onToolChanged` 里读到的
`m_stack->currentWidget()` 已经是切换后的新页。

## 4. 不确定点

- **只有代码级确认**，没有真机复现（限制里禁止启动 GUI）。上面 5 条是按「谁调用、哪个条件为假」
  静态推出来的，最终仍需 Codex 用同一条 UIA 脚本复测亮度值。
- **`showEvent` 期间的 `isVisible()`**：Qt 语义上 `showEvent` 里 `isVisible()` 到底是不是 true
  我不确定，所以 `showEvent` 显式传 `requireVisible = false`，把"可见"当作已知条件，
  避免"重新打开面板且当前页是像素→3D 却不冻结"回归。其它入口一律用默认的 `requireVisible = true`。
- **多次重复 emit**：`updateOfflineFreeze()` 在任何状态变化时都会发一次信号，因此「切回像素→3D」
  会重新 `setFrozenImage()`（主视窗重新加载 png 并把缩放重置为自动适配）。功能正确，
  但用户此前的手动缩放/平移会被重置；任务书没要求保留，未做处理。
- **`refreshPixelTo3DImages()` 空目录时不清 `p2d_hint`**：沿用 002 的既有行为（原本也不清），
  可能出现上一句「该目录下没有 png 图像」残留；不影响判据，未改。
- 002 遗留的「越界像素提示文案」差异（`像素坐标超出图像范围`）本轮依旧未动。
