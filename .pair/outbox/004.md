## 2. `Source` 三种情况的填法

```cpp
bool MainWindow::queryPixelFromCurrentFrame(int pixelX, int pixelY,
                                            std::array<double, 3>& point,
                                            QString& message)
{
    if (!m_camera->isConnected()) {
        message = QStringLiteral("请先连接相机并拍照后再点击取点");
        return false;
    }
    FrameBuffer::DoubleBuf grid;
    int gw = 0, gh = 0;
    if (!m_camera->lastGrid(grid, gw, gh)) {
        message = QStringLiteral("请先拍照采集数据");
        return false;
    }

    PixelTo3DService::Source src;
    src.xyzMm = &(*grid);                 // shared_ptr<const vector<double>>，只取引用

    if (m_camera->lastGridAligned()) {
        // ① 对齐帧：不给对应图、不给内参 → 服务走 xyz.size()==w*h*3 的直查分支
        src.imageWidth = gw;
        src.imageHeight = gh;
    } else {
        // ② 线扫未对齐：填对应图（沿用既有"每次采集只取一次"的缓存标记）
        FrameBuffer::DoubleBuf cmap;
        int cw = 0, ch = 0;
        if (!m_correspondBuilt) {
            if (m_camera->lastCorrespond(cmap, cw, ch)) {
                m_correspondW = cw;
                m_correspondH = ch;
                m_correspondBuilt = true;
            }
        }
        if (!m_correspondBuilt
            || !m_camera->lastCorrespond(cmap, m_correspondW, m_correspondH)) {
            message = QStringLiteral("线扫未对齐模式下未获得对应图，无法取点");  // ③ 拿不到
            return false;
        }
        src.correspondMap = &(*cmap);
        src.imageWidth = m_correspondW;    // 用对应图尺寸
        src.imageHeight = m_correspondH;
    }

    const PixelTo3DService::Query q = PixelTo3DService::query(src, pixelX, pixelY);
    if (q.status != PixelTo3DService::Status::Ok) {
        message = QString::fromStdString(PixelTo3DService::statusText(q.status));
        return false;
    }
    point = q.pointMm;
    message.clear();
    return true;
}
```

- 对齐 / 对应图两条分支都在 `cmap`、`grid` 的 `DoubleBuf` 作用域内完成查询（引用计数保持，
  不复制大缓冲）。
- 「拿不到」有三处，全部给中文提示且不静默：未连相机 / 未拍照（`lastGrid` 失败）/
  线扫未对齐且没有对应图。

## 5. 不确定点

- **有一次改动落在编译自检之后**：`captureComplete` 里补的 `m_view2d->clearMarkers();` 是在
  唯一那次 build 之后加的。该调用在 `Image2DView.h` 里是公开且简单的无参方法、`MainWindow.cpp`
  已 include 它，我判断无编译风险，但按纪律没有第二次 build，请 Codex 编译时确认。
- **线扫路径每次点击都会重建对应索引**：服务 API 只能吃 `correspondMap`（内部自己
  `buildCorrespondIndex`），所以 25 MB 量级的对应图每次点击会重建一次像素索引（旧实现缓存了
  `m_correspondIndex`）。`m_correspondBuilt` 的"每次采集只取一次"策略仍在，但 `m_correspondIndex`
  成员现在没人用了（未删除，避免动既有声明）。如果这条路径的点击延迟不可接受，需要给服务加
  「传入已建好的索引」的入口——那是改 `logic/`，本轮明令不动。
- **在线点击不填 `p2d_pixel`**：判据 4 只要求结果行 + hint，所以没回填像素输入框（离线路径的回填未动）。
- **失败 toast 文案**：原来固定是「该像素无有效 3D 点（背景或无效深度）」，现在统一用
  `PixelTo3DService::statusText()`，越界像素会变成「像素坐标超出图像范围」。这是 001 就存在的
  文案差异，本轮沿用未改。
- **线扫未对齐且没有对应图**时，旧代码会先 toast「线扫未对齐模式下未获得对应图，无法取点」、
  紧接着又被「该像素无有效 3D 点（背景或无效深度）」覆盖（用户实际看到的是后者）。新实现只给
  前者这一条更有信息量的提示，语义同向但可见文案不同。
