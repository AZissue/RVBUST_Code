## 4. 逐条对照判据

1. **满足（部分不确定）**：`cmake --build build --config Release` 退出码 0，输出见上，
   我确认编过。`ctest` 我按限制**没有跑**（2/2 及用例数是否不变我无法确认，需 Codex 复核）。
2. **满足**：头文件 API 逐字照抄任务书。
3. **满足（按任务书文字实现）**：实现顺序为
   ① `hasData()`（`xyzMm` 为 null/空 或 `imageWidth<=0 / imageHeight<=0`）→ `NoData`；
   ② `correspondMap != nullptr` → `buildCorrespondIndex` + `queryIndex`；
   ③ `xyz.size() == w*h*3` → `alignedIndex` + `pointAt`；
   ④ 否则先查 `hasIntrinsics`（→`MissingIntrinsics`）再查 `fx<=0||fy<=0`（→`InvalidIntrinsics`），
   然后 `buildProjectedIndex` + `queryIndex`；
   ⑤ 索引路径查不到时，像素不在 `[0,w)x[0,h)` → `OutOfRange`，否则 → `NoPointAtPixel`。
   注意 `hasData()` 里的 "尺寸非法" 只按 `w<=0 || h<=0` 判定；`xyz.size()` 为 1 或 2（不足一个点）
   时我不返回 `NoData`，而是走后续路径自然落到 `NoPointAtPixel`。任务书没写这一档，见第 5 节。
4. **满足**：`grep -rn` 上述 5 个名字对 `src/ui/` 输出为空（输出见第 3 节）。
   （`src/app/MainWindow.cpp` 仍在直接调这 5 个函数，但那是本轮明令不动的「在线」链路；
   判据只要求 `src/ui/` 为空，未动它。）
5. **满足**：`formatPoint()` 用 `snprintf(buf, sizeof(buf), "%.3f, %.3f, %.3f", ...)`，
   与工具页原来的 `QStringLiteral("%1, %2, %3").arg(..., 0, 'f', 3)` 完全同格式；
   `statusText(NoPointAtPixel)` = `该像素无有效 3D 点（背景或无效深度）`（含要求的子串）。
6. **大体满足，一处措辞变化（见第 5 节）**：合法输入下工具页走的是同一条 `query()`，
   Ok 分支的数值与格式与改前逐位相同（同一组 `PixelTo3DTools` 纯函数、同一公式）；
   内参缺失/非法两档的文案与改前逐字一致（`MissingIntrinsics` 会拼回原来的 `parseErrorText` 细节）。
   唯一差异：改前「像素越界」在对齐/投影路径都报 `该像素无有效 3D 点（背景或无效深度）`，
   现在 `query()` 把它单独标成 `OutOfRange`，工具页提示因此变成 `像素坐标超出图像范围`。

## 5. 不确定点 / 发现但没做的事

- **越界像素的提示文案**：如上，`OutOfRange` 是新引入的状态（判据 3 明确要求），工具页沿用
  `statusText()` 就必然换文案。若 Codex 要求与改前逐字一致，可把 UI 里 `OutOfRange` 也映射成
  `该像素无有效 3D 点（背景或无效深度）`，但那会丢掉状态信息——需要你定夺，本轮没擅自这么做。
- **不足 3 个 double 的点云**：`hasData()` 未把 `xyz.size() < 3` 并入 `NoData`，理由见上。
- **外参解析失败的处理**：工具页现在**无条件**解析内参/外参文本，但只在 `query()` 真需要它们时才报错
  （对齐数据 + 合法像素时，即使内参/外参文本是垃圾也照样出结果，与改前一致）。
  例外：对齐数据 + 合法像素 + 外参文本非空但解析失败 → 仍会出结果（与改前一致）；
  对齐数据 + 越界像素 + 外参文本坏 → 现在报 `OutOfRange` 而不是外参错（改前报「无有效点」）。
  这是极端组合，未处理。
- **correspondMap 的接线**：服务实现了 ② 分支，但工具页本轮不产生对应图（`correspondMap` 保持 null），
  所以这条分支目前只有单测/在线链路（下一轮）能覆盖。没动 `PlyPointReader` 去读对应图。
