# 009 交回 — 埃夫特连接把程序打崩：SDK 异常不许逃出去

## 1. 文件清单与改动点

只改 **1 个文件**：`src/logic/EfortPoseReader.cpp`（新增 1 个文件内助手 + 3 处 try/catch）。
`EfortPoseReader.h`、`RobotPose.h`、`ToolsPanel`、`MainWindow`、`tests/`、`config/`、
`CMakeLists.txt` 与 `src/CMakeLists.txt` 一个字符都没动。

**(a) 匿名命名空间新增 `exceptionText()`**（只能在 catch 块里调用）：

```cpp
QString exceptionText()
{
    try {
        throw;
    } catch (const std::exception& e) {
        // what() 是窄字符串，Windows 上按系统 ANSI 代码页解（中文异常文本多为 GBK）。
        return QString::fromLocal8Bit(e.what());
    } catch (...) {
        return QStringLiteral("非 std::exception 的未知异常");
    }
}
```

`#include <exception>` 一并加上。`throw;` 在"被 catch 调用的函数"里重抛当前异常是标准行为
（异常在处理器返回前一直处于 active 状态），这样两处 catch 不用各写一遍取 `what()` 的代码。

**(b) `EfortReader::connect()`**：`RobotAPI::ConnectRobot(addr, devId)` 包进 try；
`catch (const std::exception&)` 与 `catch (...)` 都翻成 `thrown` 文本，然后：

```cpp
    if (!thrown.isEmpty()) {
        m_devId = 0;
        m_connected = false;
        m_error = QStringLiteral("埃夫特：连接 %1 失败（SDK 抛出异常：%2）")
                      .arg(address, thrown);
        return false;
    }
```

即**返回 false + 可读中文**（任务书里给的文案原样），不 rethrow、不 terminate。
原来的"SDK 返回码 != ERROR_OK"分支一字未改（仍在异常分支之后）。

**(c) `EfortReader::disconnect()`**：`RobotAPI::DisconnectRobot(devId)` 包进 try，
两处 catch 都**吞掉**并记 `m_error = "埃夫特断开时 SDK 抛出异常：<what>"`
（`disconnect()` 在析构路径上，`~EfortReader()` 会调它，所以绝不能外抛）；
之后照旧 `m_connected = false; m_devId = 0;`。

**(d) `EfortReader::readPose()`**：`RobotAPI::GetBaseCoordinatePos(pos, m_devId)` 包进 try；
异常时 `m_error = "埃夫特读取位姿失败（SDK 抛出异常：<what>）"` 并返回
`RobotPose::Status::ProtocolError`。原有的 `if (!m_connected) → NotConnected` 判断在
try 之前（未连接时根本不碰 SDK），返回码映射分支也原样保留。

`MainWindow::onRobotConnect()` **没有改**：008 里埃夫特分支已经是「`connect()` 返回 false →
`setRobotStatus("连接失败", true)` + `m_sidePanel->setTip(...lastError()...)` + `m_logger->error(...lastError())`
+ `updateRobotReadBar()`」，异常既然已经在适配器内被翻成 false + lastError，槽函数就不可能带着异常返回；
再包一层只会把同一段失败 UI 复制一遍（明确不做里也写了"不顺手重构机器人页代码"）。

## 2. 异常从哪来，以及它之前为什么能逃出去

- **来源**：三次复现都发生在点「连接」后的 5 秒内，协议=埃夫特时必崩、Modbus 时不崩 ——
  时间点与协议唯一对应的代码就是 `EfortReader::connect()` 里的 `RobotAPI::ConnectRobot(addr, devId)`
  （`EftSdk.dll` 的导入库调用）。同一份 SDL 里 `DisconnectRobot` / `GetBaseCoordinatePos` 是同类入口，
  所以一并包了。008 的实现里这三处**都是裸调用**：没有任何 try/catch。
- **为什么能逃出去**：`0xE06D7363`（`__cxx_exception`）说明是 DLL 内部抛的 C++ 异常，
  008 的 `connect()` 没有 catch，异常从 `EfortReader::connect()` → `MainWindow::onRobotConnect()`
  →（Qt 的 `QMetaObject::activate` 调用栈）一路穿出去。**Qt5 的槽调用没有异常屏障**：
  `qFatal` 式的处理是在异常离开 `QObject::event`/signal 激活后走 `std::terminate`，
  于是进程直接消失——这正好解释了你日志里的现象：没有模态框、没有等待，
  崩溃处理器（自装的 SEH handler）只来得及跑 `emergencyRelease` 就退出。
  也就是说：**不是埃夫特没有真机导致的"连接失败"，而是"连接失败的方式"（抛异常）没有被接住。**
- 顺带一提：`EfortSdk.h` 是 `__declspec(dllexport)` 的全局声明，SDK 也带 log4cpp/rlibcpp 依赖，
  这类厂商库用异常报错的概率不低，所以这里不是"防一个偶发"，而是"这条链路必须自带边界"。

## 4. 不确定点

- **被拒的命令**：`grep -n "RobotAPI::\|try {\|} catch" src/logic/EfortPoseReader.cpp`
  被权限系统拒绝（提示 "This command requires approval"），本轮没有重试，改用 Read 逐行核对，
  上面那张表就是核对的结论。需要这条 grep 只是为了自证"每个 SDK 调用点都在 try 内"。
- **`catch(...)` 只能接 C++ 异常**：工程是默认的 `/EHsc`，所以 `catch(...)` 接的是 C++ 异常
  （`0xE06D7363` 这类），**接不住 SEH 型崩溃**（例如 DLL 里真出现 0xC0000005 访问违例，
  进程仍会被带走）。如果 Codex 希望连 SEH 也拦，需要给这个 .cpp 单独开 `/EHa`
  （`set_source_files_properties` 里加 `COMPILE_OPTIONS "/EHa"`）——但那会把访问违例也当普通异常吞掉，
  可能掩盖 SDK 的真实内存 bug，所以我**没有**擅自加，留给你决定。
- **异常类型没写在日志里**：现在 `lastError()` 里是 `SDK 抛出异常：<what>`，`what()` 为空的异常
  会变成空白（MSVC 的 `std::exception::what()` 一般有内容，但第三方库可能抛自定义类型）。
  若真机验证时发现提示是空的，可以在 `exceptionText()` 里加一句 `typeid(e).name()` 兜底——
  这轮没加，避免给用户看一堆重整名。
- **`fromLocal8Bit` 解 `what()`**：中文异常文本按系统 ANSI（GBK）解，若 DLL 的 what() 是 UTF-8
  会出现乱码。真机看到乱码就把这里换 `QString::fromUtf8`；两种都属可读性，不影响"进程活着"。
- **真机行为仍需 Codex 复验（判据 2/3）**：我这边无法启动 GUI，只保证异常被翻成 false/ProtocolError；
  「进程活着 + 侧栏与操作日志各一条可读失败提示」必须真机点一次才算数。
  另外如果 SDK 在 **DLL 内部另起线程**里抛异常（不是我们从调用栈抛出的），那 Qt 仍然会 terminate——
  这种情况本轮无法覆盖，需要看 `build/src/Release/logs/runtime_*.log` 里崩溃栈是否仍在我们的调用路径上。
