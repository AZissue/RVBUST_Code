## 2. 文案原文

**一个完整的 `[测量-说明]`（平面度，选自 `methodExplainLine(Method::Flatness)`）**

```text
[测量-说明] 平面度 —— 用途：看一个面平不平：拟合一个基准平面，给出面上最高点与最低点之差。；怎么用：ROI 怎么画：只在被测的那一个面上拖一个 ROI A，别跨到台阶、孔或别的面上。；本方法只需 ROI A（被测面）；输出：最小区域 PV = 最高−最低（mm，判定用这个）；LSQ PV / RMS = 最小二乘的参考值（mm）；倾斜角 = 这个面相对视线的倾斜（°）。；怎么看结果：可信度：点数越多越稳；报告值已按 MAD 剔除粗大点，单个毛刺不会撑大 PV；点数很少时只看趋势。；常见错法：ROI 跨了两个不同高度的面、或框进孔里的空点，PV 会明显变大。
```

**一个 `[测量-结果]`（平面度，数值沿用既有格式）**

```text
[测量-结果] 平面度：最小区域 PV = 0.0312 mm；RMS = 0.0049 mm（40000 点，高）；口径：PV = 最大偏差 − 最小偏差；最小区域 MZ ≤ LSQ PV；凸起为正（朝向相机）；这组数说明：PV 就是这一面最高点与最低点的高度差，也就是这一面的形状误差：越小越平，平不平常看它，跟这个面整体离相机多远无关。
```

（`；这组数说明：…` 之前的部分与改动前逐字相同。）

## 3. 四个关键词怎么保证每个方法都有

关键词全部由 `methodExplainLine()` **一份代码**拼出，方法差异只来自数据表，所以 8 个方法逐一成立：

```cpp
inline std::string methodExplainLine(Method m)
{
    const MethodSpec& s = methodSpec(m);
    std::string out = s.name;
    out += " —— 用途：";            // ← 关键词 1
    out += s.purpose;
    out += "；怎么用：ROI 怎么画：";  // ← 关键词 2
    out += s.howTo;
    if (s.roiCount > 0) {
        out += "；";
        out += roiRequirementText(m);
    }
    out += "；输出：";              // ← 关键词 3
    out += s.outputs;
    out += "；怎么看结果：可信度：";   // ← 关键词 4
    out += s.confidence;
    out += "；常见错法：";
    out += s.pitfalls;
    return out;
}
```

`methodSpec()` 对未知方法回落到 `table[0]`，所以连非法枚举值也带这四个标题。

**为什么保留 `ROI 怎么画：`/`可信度：`/`常见错法：` 三个旧小标题**：它们现在嵌在对应分段内部
（`怎么用：ROI 怎么画：…`、`怎么看结果：可信度：…；常见错法：…`）。
`tests/test_log_presentation.cpp::explainLineKeepsExactlyOneTag` 明确断言这三个子串存在，
而 `tests/` 归 Codex 独占、本轮不许改；保留即"旧断言 + 新四标题"同时成立。正文里没有新增
ASCII 方括号，`countOf(line, "[测量-说明]") == 1` 仍成立。
