# codex_testData — 已知真值的测量数据（第 7 回合 P1）

测量面板以前没有可比对的真值：⌀ 值错 10 mm 和错 0.01 mm 看起来一模一样。
这个目录里是**每一个数字都由构造决定**的合成数据，用来把「测量错了」拆成
「ROI 取点错了」还是「算法错了」。

- `*.grid` — 与相机 `CameraManager::lastGrid()` 交到面板的网格**逐字节同构**：
  ASCII 头 `<w> <h>\n`，随后 `w*h*3` 个小端 float32 (x, y, z)，单位 mm，行主序
  （`cell = y*w + x`），NaN = 该格无效（未测到 / 通孔）。
- `*.ply` — 同一批点的二进制小端 PLY，方便用 MeshLab / CloudCompare 直接看。
- `manifest.json` — 每个场景的真值、公差、判定语句、ROI 像素矩形、
  **该用哪个方法**（`scenes[].method`）、**该画哪个 ROI**（`scenes[].roiHint`），
  以及「哪一条检查对应哪个算法」。**这是本目录唯一的真值来源**，数据文件是它的产物。
  顶层的 `methods` 数组是 `src/logic/MeasureMethods.h` 里那张方法目录的副本
  （id / 名字 / ROI 需求），`methodUsage` 说明这两个字段怎么用。
- `*.grid` / `*.ply` 不入库（见根目录 `.gitignore`），`manifest.json` 与
  `README.md` 入库。

## 重新生成 / 校验

生成器与校验器都是 C++，注册为 ctest 用例，无 GUI、无相机、无 SDK：

```bat
cmake --build build --config Release --target measure_truth
ctest --test-dir build -C Release -R measurement_truth -V
```

一次运行会：**就地**重新生成全部 `*.grid`/`*.ply`/`manifest.json`，再从磁盘读回，
按 `ROI 像素矩形 → roiImageToGrid → pointsInRoiIndexed → 测量算法` 的**完整链路**
逐条测量，打印 实测 / 真值 / 偏差 / 公差，最后输出汇总表。
全部通过时 exit 0；任一条失败 exit 1 并列出失败项。
常用参数：`--no-generate`（只校验现有文件）、`--verbose`（打印 ROI 映射轨迹）。

数据是确定性生成的：`std::mt19937_64` 原始输出 + 手写 Box-Muller，固定种子
20260920，不含时钟、不含平台 RNG，所以同一份源码在任何编译器上生成同样的字节。

### 该用哪个方法 / 该画哪个 ROI

`scenes[].method` 是**界面左侧工具列表里的条目 id**（== `MeasureTools::methodId()`），
`scenes[].roiHint` 是用大白话写的操作说明。工装会断言 `method` 一定在
`MeasureMethods.h` 的方法目录里（否则界面上根本没有这一项），并且需要 ROI 的方法
不许缺 `roiHint`——所以这两个字段不会随界面改名而悄悄失效。

| 场景 | 该选哪个工具条目 | 该画哪个 ROI |
|---|---|---|
| `plane_flat` / `plane_tilt` | 平面度 | 一个框盖住整块平面（ROI A = 被测面） |
| `step_3mm` | 高度段差 | 第 1 框 = ROI A 基准面（x ≤ 60），第 2 框 = ROI B 被测面（x > 60） |
| `angle_89_613` | 面面距离夹角 | ROI A 框水平面，ROI B 框近竖直墙（夹角 > 3°，不报间距属正常） |
| `holes_*` | 孔径(孔洞边界法) | 紧贴每个孔各一个近正方形框（孔 + 孔外约 2 个点距）；**不要用圆环拟合测孔** |
| `box_*` | 包围盒 | 一个框盖住整个物体 |
| `repeat_series` | 重复性 | 本方法不要 ROI：先用别的方法逐帧测并「加入重复性」 |
| `roi_map_boss` | 任一方法页（场景本身校验框选映射） | 框拖在方台上/旁边，看取点数与偏差图落位 |

### 孔径公差（为什么不是一条固定值）

孔壁只能**按点距采样一次**：每个方向上最内侧的材料格中心落在真值边缘外
0～1 个点距之间，所以孔径的可分辨度本身就随点距变差。实测（`孔洞边界法`）：

| 点距 | 公差 | ⌀5 偏差 | ⌀10 偏差 | ⌀20 偏差 |
|---|---|---|---|---|
| 0.250 mm | ±0.050（Python 一致性目标） | −0.035 | −0.024 | −0.014 |
| 0.500 mm | ±0.200 | −0.165 | −0.089 | −0.029 |
| 1.000 mm | ±0.600 | +0.541 | −0.242 | −0.198 |

⌀5 在 1 mm 点距下只有 5 个采样点横跨直径，±0.6 mm 是**数据**的分辨极限，
不是算法的余量：同一批点上旧的「一个圆拟合所有 ROI 点」偏差是
1.17 / 1.71 / 2.80 mm（0.25 mm 点距），新法是它的 0.5%～3%。

## 已知的、故意保留的边界条件

- 孔洞边界法要求**紧贴孔画 ROI**（孔 + 约 2 格材料）。ROI 取得很大时，
  「每扇区最内侧点」会变成二维填充的次序统计量而不是孔壁，报出的值偏大；
  此时 `可靠` 会变成「参考」。
- 相机朝 +z 看，所以「凸起」是 **z 变小**；`step_3mm` / `roi_map_boss` 都按这个
  约定构造，与 `tests/test_measure_tools.cpp` 的 `凸起为正` 一致。
