# 阶段 27（3.0）— 测量帧：把一次测量完整落盘并可回放

> 2026-11-02。3.0 测量收口的第一步（3.0 规划 M-02）。
> 用户拍板的顺序是「证据链 + 可靠性」先行、交互与批量后置，本文只做证据链。

---

## 1. 为什么先做这个

测量工具目前"能算"，但**一次测量留不下任何证据**：会话里只有 png + ply，
测量页真正使用的 organized grid 从未落盘；离线模式也只服务「像素→3D」。
后果是 2026-10 的 P1 改动：合成 32 场景全绿，真机 Ø26 报 42.66、Ø5 报 ~10，
只能整笔回滚（`866fcd3` → `e65a3c1`）。

没有可重放的真件数据，改算法就是没有标尺；可靠性标记（M-04）也无从设计——
"这条边是不是选错了"必须在真件的网格 + 图像上才看得出来。

## 2. 交付内容

### 2.1 一种帧格式，三份文件

一帧 = 一个目录（默认 `<会话>/measure_frames/<方法>_<yyyyMMdd_HHmmss>/`）：

| 文件 | 内容 | 为什么 |
|---|---|---|
| `frame.grid` | 组织化点云网格，**与 `tests/measure_truth` 的 `.grid` 字节同构**：ASCII 头 `<w> <h>\n` + `w*h*3` 小端 float32，行主序，NaN 为无效单元 | 现场一帧可以直接喂给现有真值回归链路，不需要转换脚本 |
| `frame.png` | 同一次拍照的 2D 图像 | 亚像素边缘只能用这张图 |
| `frame.json` | 方法 id、采集时间、ROI（图像像素）、结果行、主值、`extra` 口径 | 决定"回放时按哪个方法、框在哪、当时判据是什么" |

`frame.json` **最后写**：中途失败的目录没有清单，`load()` 读不出来，所以不会
出现"看起来像一帧、其实是半截"的数据。

`extra` 里保存的是判据而不是装饰：基类写公差与偏差色标区间；「3D 孔洞」额外写
探测方向、覆盖率、圆度、是否亚像素、中心与扇区数。**回放时"当时按哪条边量的"
不会丢**，这正是后面做歧义标记（M-04）要对照的东西。

### 2.2 保存 / 打开

- 每个测量页都有「保存测量帧」「打开测量帧」（「3D 孔洞」是自绘页，按钮在底栏）。
- 保存目录：优先当前会话目录（`MainWindow` 注入 provider），没有会话时用
  上次位置，再没有就用"文档"目录；写盘后日志写一条
  `[测量-帧] 已保存：<路径>（方法 …，ROI n 个，结果 m 行）`。
- 打开：选择 `frame.json` → 读回 → 装回面板（所有页一起换帧）→ 切到帧里的方法页
  → 恢复 ROI → **自动复测一次**；日志先写"保存时的结果"，再写本次的
  `[测量-结果]`，两者可直接对照。
- 帧里的方法在当前版本没有对应页时：点云与图像照常装回，**不恢复 ROI 也不复测**，
  日志说明原因——不拿别的方法去套它的框。

### 2.3 边界与拒绝

| 情况 | 行为 |
|---|---|
| 还没拍照（无网格） | 不写盘，日志 `未保存：尚未采集点云` |
| 网格点数与 `w*h*3` 不符 / 方法 id 为空 | 拒绝并给出具体数量 |
| 清单尺寸与网格头不一致 | 拒绝（防止"清单说 A、数据是 B"） |
| 网格头非法 / 数据长度不符 | 拒绝并指出应为多少字节 |
| ROI 越出图像范围 / 矩形非法 | 拒绝 |
| 清单文件名带路径（`../x`） | 拒绝（只允许帧目录内的纯文件名） |
| 清单版本不认识 | 拒绝并写明本程序读哪个版本 |

## 3. 单测（tests/test_measure_frame.cpp，8 passed）

| 用例 | 断言 |
|---|---|
| `roundTripKeepsEverything` | 网格（含 NaN）、图像尺寸、ROI、结果行、主值、`extra` 全部原样回来 |
| `saveRejectsGridSizeMismatch` | 点数不符 / 缺方法 id 均拒绝，且原因点名 |
| `loadRejectsManifestGridMismatch` | 清单与网格头不一致时拒绝 |
| `loadRejectsBadGridHeader` | 头非法、长度不符两种都拒绝 |
| `loadRejectsRoiOutsideImage` | ROI 越界拒绝 |
| `suggestDirKeepsMethodIdAscii` | 目录名只留方法 id 的 ASCII，空 id 回退 `measure` |

## 4. 人工验证清单（UI 不做自动化）

1. 拍照 → 选「平面度」→ 拖 ROI → 测量 → 点「保存测量帧」→ 日志出现
   `[测量-帧] 已保存`，会话目录下出现 `measure_frames/flatness_<时间>/` 三个文件。
2. 关掉相机连接（或直接重启程序不连相机）→「打开测量帧」选刚才的 `frame.json`
   → 点云与 2D 图回到视窗、工具自动切到「平面度」、ROI 框回到原位并自动复测出数值。
3. 日志里"保存时的结果"与复测的 `[测量-结果]` 数值一致（同一算法、同一帧）。
4. 「3D 孔洞」页重复 1-2：`frame.json` 的 `extra` 里应有 `material_inside`、
   `coverage`、`roundness`、`subpixel`。
5. 把 `frame.grid` 改名/删掉后打开 → 日志 `打开失败` 并指出网格文件问题，程序不崩。
6. 打开一帧后重新拍照 → 旧帧的 ROI 被清（新帧尺寸可能不同），不会静默套用。

## 5. 回退

- 删掉 `src/logic/MeasureFrame.*` 与两个按钮的 connect 即回到"只能测不能存"；
- 帧格式独立于会话与备份，不迁移、不清理旧数据；
- 已存出的 `measure_frames/` 目录可以原样保留，不影响任何既有功能。

   即可作为 M-01/M-04 的判定基准。
