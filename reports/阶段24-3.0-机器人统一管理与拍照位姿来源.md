> 2026-10-26。来源：现场（2.0 发布版 + M51000 5MP 相机 + UR5）四个问题。
> 本文记录**已定的架构方向**、**本次已完成的最小修复（P0）**，以及**只记录不修**
> 的点云颜色偏移结论。P1/P2 尚未实施，按本文 §4 的顺序做。

## 1. 现场问题与根因

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 控制台长按点动"步进式"、松手不立即停 | 每次重复触发发一条完整 `movel`（加速度 0.05–0.5 m/s²），单槽队列只保留最新目标，松手时没有停止指令；UR 侧仍要把在途 `movel` 走完 | 方案见 §5（P3，需真机验证） |

| 4 | 5MP 相机点云上色错位 | M51000 是线扫相机。**关闭**「点云与2D图对齐」时，3D 点阵与 2D 图像网格不是同一分辨率/同一映射，而 `PointCloudUtils::filterValidPoints` 用的是"第 i 个 3D 点取第 i 个像素颜色"的线性下标 | **不改代码**，结论见 §3 |

## 2. P0（已实施）：拍照位姿来源

### 2.1 规则（唯一修复点）

新增纯函数 `src/logic/RobotPoseSource.h`：

1. 通信工具已连接 → **用通信工具**（保持原有行为，操作员显式选择优先）；
2. 否则控制台满足 **已连接 + 真机后端 + 位姿新鲜（≤1000 ms）+ 无在途运动**
   → 用控制台缓存的位姿；
3. 否则 → **失败关闭**：拍照节点报错退出，绝不把空位姿 / 旧位姿 / 仿真位姿
   写进标定记录。

仿真后端被故意排除：仿真位姿数值看着合理，但一旦进入标定卡片就是错误数据。

### 2.2 实现位置

- `RobotMotionBackend::cardPose()` / `cardPoseUnit()`：**写卡约定**的唯一出口。
  默认透传 `state()`（法奥 mm/度、仿真）；`UrMotionBackend` 覆盖为
  **轴角弧度**（控制台内部为了点动用角度，卡片沿用通信工具历史上的弧度约定）。
  没有这一层，UR 标定数据会静默放大 57.3 倍。
- `MainWindow::rememberConsolePose()`：只在 `poseUpdated` 时缓存
  `cardPose()` + 时间戳；`backendChanged` / 断开连接时调用
  `invalidateConsolePose()` 作废。
- `MainWindow::beginProgramPhoto()`：先用 `RobotPoseSource::choose()` 选来源，
  **再**改节点状态（失败不会留下半启动状态）。
  - 通信工具来源：仍走 `readPose(RobotReadAutoBeforeCapture)` → 回调填卡；
  - 控制台来源：直接按卡片约定写 `robot_capture_pose` → `updatePoseGuide()`
    → 立即拍照，并在操作日志写明来源、单位、位姿年龄。

### 2.3 为什么 UR 卡片填弧度

HandEyeSDK 的标定输入同时支持弧度和角度，标定页会让用户选择单位。UR 控制器
原生 `actual_tcp_pose` 就是**轴角弧度**，通信工具一直按这个约定写卡。
控制台内部转成角度只是为了点动可读；写卡时转回弧度，两条路径的卡片格式一致，
用户不需要因为"从哪个工具读的"而改单位。

### 2.4 失败提示（可读、能指导操作）

| 情形 | 提示 |
|---|---|
| 两条连接都没连 | 拍照节点需要机器人位姿：请连接「机器人通信」，或在机器人控制台连接真机（仿真后端不能用于标定） |
| 控制台只连了仿真 | 拍照节点需要真机位姿：机器人控制台当前是仿真后端 |
| 位姿超过 1 s 未更新 | 机器人控制台位姿已超过 1 秒未更新，请检查机器人连接 |
| 有在途运动 | 机器人正在运动，停稳后再运行拍照节点 |

### 2.5 单测

`tests/test_robot_pose.cpp` 新增两例（已注册进 `TestRobotPose`）：

- `cardPoseFromState`：`fromStateCart` 只搬值、`axisAngleDegToRad` 只缩放姿态、
  `formatFields` 固定 6 字段 3 位小数；90° → 1.570796…
- `poseSourceChoice`：通信优先；仅控制台真机可取；仿真/过期/运动中/断开
  一律 `None`。

## 3. 点云颜色偏移（M51000、关闭对齐）— 结论，不改代码

- RVC 一次 `Capture()` 同时给出 3D 点云与 2D 图像；**打开**「点云与2D图对齐」时
  两者索引一一对应，线性取色正确。
- **关闭**对齐时，线扫的点云网格与 2D 图像网格不对齐（尺寸/采样都不同），
  `filterValidPoints` 的 `imgData[i*3]` 取下标的做法就取到了别的像素。
- RVCManager 在两种模式下都能正确上色，说明它走的是 SDK 的对应关系
  （`CorrespondMap` / 内外参 + 畸变反投影），而不是位置下标；相机代码里本来
  就有 `GetCorrespondMap()` 分支（`CameraManager::captureFrameX2`，仅在
  `!gridAligned` 时取），只是点云上色没有用它。
- **结论**：标定要求 3D 与 2D 对齐，现场把「点云与2D图对齐」保持打开即可，
  不做额外反投影着色。若以后有"关闭对齐也要正确上色"的需求，正确做法是用
  `CorrespondMap`（3D 点下标 → 像素坐标）逐点取样，而不是修线性下标。

## 4. P1/P2 架构（已与用户确认，待实施）

### 4.1 一个品牌一个对象 + 一个 Hub

```
RobotHub                // 全应用唯一的机器人入口（连接、状态、位姿、运动）
 ├─ RobotDevice (抽象)  // name/capabilities/connect/disconnect/pose()/motion()
 │   ├─ UrDevice        // 30003 反馈 + 30001 脚本 + 29999 Dashboard（无 RTDE）
 │   ├─ FairinoDevice   // 20004 状态 + 20003 XML-RPC
 │   ├─ ModbusDevice    // Modbus TCP 读寄存器（只读位姿）
 │   ├─ NrcJsonDevice   // 博纳斯/纳博特 JSON/TCP（只读位姿）
 │   ├─ EfortDevice     // EfortSDK（只读位姿）
 │   └─ SimulatedDevice // 只服务控制台仿真，永不参与标定写卡
```

- 品牌差异（报文、单位、运动指令）全部留在各自的 Device 里；上层只看
  **能力矩阵**：

  | 能力 | UR | 法奥 | Modbus | NRC JSON | Efort | 仿真 |
  |---|---|---|---|---|---|---|
  | 读位姿 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓（仅控制台） |
  | 笛卡尔/关节点动 | ✓ | ✓ | — | — | — | ✓ |
  | 程序节点运动 | ✓ | ✓ | — | — | — | ✓ |
  | 写标定卡片 | ✓ 轴角弧度 | ✓ mm/度 | ✓ | ✓ | ✓ | ✗ |

- 只读品牌在 UI 上隐藏运动/程序区，只保留连接与位姿显示。
- `RobotPoseSource.h` 保留为纯决策函数，P1 后输入由 Hub 提供，语义不变。

### 4.2 合并「机器人通信」与「机器人控制台」为一个「机器人控制」

- UI 以**控制台**为准（它已经包含连接）；通信工具页删除。
- 删除通信工具里的 **UR RTDE (30004)** 和 **「模拟连接成功」**：仿真只保留
  控制台「仿真」后端这一条路，避免"看起来连上了但什么都不是"。
- 删除通信工具里的「拍照时自动读取机器人位姿」勾选：设置对话框已有同名项，
  两处状态容易打架。
- 设置对话框的连接项改为按品牌展开（主机/端口/协议/单位/从站号/起始地址）。

### 4.3 迁移顺序与验收

1. P1：抽 `RobotDevice`/`RobotHub`，把现有 `RobotWorker` 的五个 reader 包成
   Device；通信工具与控制台都改为经 Hub 连接。**两条连接合并成一条**。
   验收：单测全绿；两个工具任一连接后，另一个立即显示已连接；拍照节点无需
   关心来源；UR/法奥原有现场清单回归。
2. P2：合并 UI、删 RTDE/模拟连接/重复勾选、只读品牌隐藏运动区、帮助文档同步。
   验收：人工清单（连接→读位姿→点动→程序→拍照），只读品牌不出现运动按钮。
3. 回退：P1 是新增抽象层，`RobotHub` 内部先委托旧实现，去掉接线即可回退；
   P2 只动 UI 布线。

## 5. 连续点动（P3，方案，待真机验证）

目标：接近示教器"按住就走、松手就停"。

- 接口加 `jogStart(axis, dir, speedPct)` / `jogStop()`；松手、失焦、断连、
  关窗都发 `jogStop`。
- **UR**：`jogStart` 发 `speedl`（笛卡尔）/`speedj`（关节），`t=0.2`，
  **每 100 ms 重发一次**刷新看门狗；`jogStop` 发 `stopl`/`stopj`（`a` 取较大
  减速度）。不用 `movel`，因为 `movel` 是"到点"语义，天然是步进式。
  30003 反馈超过 300 ms 没有新包时自动 `stopj` 兜底。
- **法奥**：优先 `ServoMoveStart` + `ServoCart`/`ServoJ` + `ServoMoveEnd`；
  若固件不支持伺服模式，退化为"短距离 MoveL + 松手 StopMotion"（仍比现在
  好，但会有一步的延迟），现场二选一。
- 30003/20004 的位姿流绝不能放到 UI 线程；重发定时器在后端 worker 线程。
- 验收：真机按住 2 s 连续移动、松手 100 ms 内停；慢速下无抖动；点动期间
  拍照节点拒绝启动（运动在途）。

## 6. 运行列表循环（P4，方案）

- 现状：`runAll()` 已从头跑；失败即停（正确，不要静默跳过）。
- 加"循环执行"作为**有界**选项，而不是无限循环：次数输入（默认 1，范围
  1–999）+「循环执行」按钮；每轮结束日志写"第 k/N 轮完成"；失败、停止、
  关窗都终止循环；循环期间禁止编辑节点列表。
- 不建议默认无限循环：标定采集是人工摆位流程，无人值守的无限运动有安全风险。
