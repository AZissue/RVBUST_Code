# 阶段 26（3.0）— 流程节点拍照的保存语义与拒绝原因

> 2026-11-02。来源：现场（UR 192.168.0.60 + M3GM620B039）第一次跑「流程节点列表」。
> 运行到拍照节点时横幅只报一句「程序运行失败：保存被拒绝：请检查相机目标点 /
> 机器人位姿等必填项」，看不出到底缺哪一项；且主界面标定方式选「戳点」时，
> 流程节点整条链路都会按戳点校验，拍照节点必然保存失败。
>
> 用户要求两条：① 报错必须点名缺的那一项；② 主界面选戳点不得影响流程节点，
> 它恒按标记物标定采集（2D + 3D + 机器人拍照位姿）。

---

## 1. 根因

| # | 现象 | 根因 |
|---|---|---|
| 1 | 横幅只有一句笼统提示 | `MainWindow::onProgramPhotoDetected()` 用「记录数有没有 +1」判断保存成败，失败后自己拼了一句通用文案，把 `CaptureFlow` 已经算出来的 `SaveIssue.message` 丢掉了 |
| 2 | 主界面选戳点 → 拍照节点必失败 | 保存校验读的是会话模式 `CalibrationMode`：戳点要 `robot_target_xyz`，而流程节点从来没有"戳点"这一步 → 必然 `robot_target_xyz 不能为空`；眼在手外 + 戳点更连机器人拍照位姿都不写 |
| 3 | 数据导出也跟着错 | `DataManager::writeHandEyeOutput()` 按会话模式选 `pose.txt` / `cameraCapturePointXyz.txt + tcp.txt`；会话是戳点就会把流程采集的数据导成戳点格式（tcp 列全空） |

要点：这三处是**同一个决定的三个投影** —— 流程节点的拍照到底属于哪种标定。
此前它跟着主界面走，而它实际上只有一种语义：标记物标定。

## 2. 修复

### 2.1 保存结果带回具体原因

`CaptureFlow::save()` 由 `void` 改为返回 `SaveIssue { ok, field, message }`
（与 `validateSaveInputs()` 同一个结构），并新增：

```cpp
SaveIssue saveWithMode(const CalibrationMode& mode,
                       const QString& cameraTargetXyz,
                       const QString& robotCapturePose,
                       const QString& robotTargetXyz);
```

`save()` 仍按会话模式校验（手动按钮行为不变），只是把"缺哪一项"返回给调用方。
导出失败（记录已写、`pose.txt` 没写成）同样返回 `ok=false` 与
「第 N 组已保存，但导出失败: …」——后续标定会读到旧文件，不能当成功继续跑。

### 2.2 流程节点恒按标记物保存

- `MainWindow::onProgramPhotoDetected()` 调 `saveWithMode(markerMode, 相机目标点,
  机器人拍照位姿, 空)`：`robot_target_xyz` 显式传空，戳点列不参与这条流程；
- 失败时 `finishProgramPhoto(false, "保存被拒绝：" + issue.message)`，横幅因此变成
  「保存被拒绝：相机目标点坐标不能为空」这类可执行的信息。

### 2.3 运行前把模式/会话切到标记物

`ProgramActions` 新增 `prepareRun(bool willWriteRecord, QString* error)`：

- `ProgramRunner::runAll()` 看整表有没有会写记录的拍照节点；`runOne(i)` 只看该节点
  （`RobotProgram::writesRecord()`：拍照节点且勾了保存）；
- `RobotProgramController` 把这次准备委托给主窗口注入的 `RunPreparation`；
- `MainWindow::prepareProgramCapture()`：
  - 已是标记物 → 直接跑；
  - 是戳点且会话为空 → 静默切换（`switchCalibrationTypeToMarker()`：`m_flow->setMode`、
    选择器静默同步、卡片显隐、文件预览、`resetSession()` 建标记物会话、写回配置、
    toast + 日志）；
  - 是戳点且已有数据 → 先问用户（切换会新建会话、清空当前 N 组数据）；取消则
    **拒绝本次运行**并给出原因，绝不清空得不明不白。

`prepareRun` 由执行器在**改变任何运行状态之前**调用，拒绝时只发
`finished(false, error)`，一个节点都不会执行。

### 2.4 位姿要求随之收敛

`beginProgramPhoto()` 改为先读节点自己的「保存」开关，再决定要不要位姿：
`needPose = m_programPhotoAutoSave`。只要会写记录就必须有机器人拍照位姿，
与主界面选的是标记物还是戳点无关；只采集不保存的节点（导入的程序里可能有）
仍然不强制连机器人。位姿来源判定（真机 / 新鲜 ≤1 s / 仿真不可用）不变。

## 3. 单测

| 用例 | 断言 |
|---|---|
| `TestRobotProgram::runnerPrepareRunCanRefuse` | 拒绝时 `runAll` 返回 false、零节点执行、原因随 `finished` 上报；整表准备收到 `willWriteRecord=true`；单跑等待节点为 false、拍照节点为 true |
| `TestCaptureFlowValidation::markerValidationOverridesTouchSession` | 同一组输入：戳点会话因缺 `robot_target_xyz` 拒绝；按标记物保存通过；缺拍照位姿仍拒绝（覆盖只换列，不放松格式） |
| `TestSaveExport::saveReturnsTheMissingField` | `save()` 返回 `field=camera_target_xyz` / `robot_capture_pose` 与对应中文原因 |
| `TestSaveExport::captureFlowSurfacesExportFailure`（加强） | 导出失败时返回 `ok=false` 且原因含「导出失败」 |

结果：D 工作区 `unit_tests` 全绿（robot_program 28 passed / capture_flow_validation 15 /
save_export 11），ctest 3/3。

## 4. 人工验证清单（UI 不做自动化）

1. 主界面选「戳点」、会话里已有数据 → 运行含拍照节点的列表 → 弹出「切换会清空
   数据」确认框；点「否」→ 列表不启动，横幅给出「当前是戳点会话，切换已取消」。
2. 同上点「是」→ 主界面切到「标记物」、会话目录新建、列表正常跑完；每组数据
   在会话目录里写的是 `pose.txt`（6 个数），不是 `tcp.txt`。
3. 主界面选「戳点」、会话为空 → 不弹框，直接切标记物并跑完，toast 提示已切换。
4. 运行列表时清空「相机目标点」卡（或先关掉识别自动填）→ 横幅应为
   「保存被拒绝：相机目标点坐标不能为空」，且节点停住、后续节点不执行。
5. 清空「机器人拍照位姿」卡 → 横幅为「保存被拒绝：机器人拍照位姿不能为空」。
6. 只连相机不连机器人 → 拍照节点提示"需要机器人位姿"，与以前一致。

## 5. 回退

- 保存语义：`onProgramPhotoDetected()` 改回 `saveFromCards()` + 记录数判断即可；
- 运行前准备：删除 `setRunPreparation` 注入（`prepareRun` 默认返回 true），
  执行器行为即恢复为"直接跑"；
- `CaptureFlow::save()` 的返回值是可忽略的（手动路径本就不看），退回 `void`
  只影响新增断言。
