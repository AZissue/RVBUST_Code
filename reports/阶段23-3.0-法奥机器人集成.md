# 阶段 23（3.0）：法奥（FAIRINO）机器人集成

> 日期：2026-10-26
> 范围：机器人通信工具（位姿读取）+ 机器人控制台（运动后端）
> 状态：代码完成，单测 31/31；**无真机，现场验收未做**

## 1. 目标与边界

用户拿到法奥官方 SDK `fairino-v2.1.7.1`（Python 包，`fairino/Robot.py` +
`.pyd`），要求在**没有真机**的前提下接入两个工具：

1. 机器人通信工具：新增「法奥实时 (20004)」协议，读出 TCP 位姿；
2. 机器人控制台：新增「法奥真机」运动后端，支持连接、上/下使能、点动、
   MoveL / MoveJ、程序执行。

明确不做：

- 不把 Python 运行时带进 C++ 程序，只复用 SDK 里**实测过的协议事实**；
- 不添加 Modbus/NRC/埃夫特后端（R-02 仍只做有真机的品牌）；
- 不实现 `servoj` 连续伺服（R-04 未做，仍按"步长 MoveL + 队列合并"）；
- 不猜错误码含义、不猜状态包偏移、不猜 MoveL/MoveJ 的收发时机。

## 2. 证据来源（为什么这样写）

| 事实 | 来源 |
|---|---|
| 命令走 20003 XML-RPC over HTTP，状态包推 20004 | SDK `Robot.py` 的连接初始化 + `robot_state_routine_thread` |
| 位姿/关节/使能/到位都以 20004 缓存为准 | `GetActualTCPPose` / `GetActualJointPosDegree` / `GetRobotMotionDone` / `GetRobotEnable` 在 Robot.py 中直接读 `robot_state_pkg`；对应 XML-RPC getter 已被注释 |
| 20004 帧头 `5A 5A`、u8 帧计数、u16 **小端** data_len、u16 小端累加和 | SDK 的收包/校验代码 |
| 结构体 1236 字节、各字段偏移 | 对 `RobotStatePkg`（`_pack_=1`）用 ctypes 实测，不是估算 |
| `MoveL` 实际线上是**一个 33 元素数组参数**；关节全 0 时客户端先调 `GetInverseKin` | Robot.py:1157 起的实际调用 |
| `MoveJ` 是 11 个参数（两个 6 元数组 + 一个 4 元数组） | Robot.py:1098 起的实际调用 |
| `Mode(0 自动/1 手动)`、`RobotEnable(0/1)`、`StopMotion()` 只回错误码 | Robot.py 对应函数 |
| `GetInverseKin(0, desc, -1)` / `GetForwardKin(joint)` 返回 `(error, 6 个值)` | Robot.py 对应函数 |
| MoveL/MoveJ 立即返回 errcode（已接收/入队），不等于到位 | 官方通讯协议手册；到位由 20004 `motion_done` + 队列长度判定 |
| `blendR = -1` 表示"到位停、不混合"，不是"阻塞到完成" | 协议手册参数表 |

## 3. 20004 状态包格式（已实现并用单测锁定）

```text
[0..1]  5A 5A        帧头
[2]     frame_cnt    u8，回绕
[3..4]  data_len     u16 小端
[5..]   payload      RobotStatePkg 去掉帧头与 data_len
[5+data_len .. +1] checksum u16 小端 = 前面所有字节之和
整帧 = data_len + 7；结构体 1236 字节 → data_len 常见 1229
```

使用的字段偏移（`logic/FairinoRealtime.h`）：

| 字段 | 偏移 | 类型/单位 |
|---|---|---|
| program_state | 5 | u8 |
| robot_state | 6 | u8（1 停 2 运行 3 暂停 4 拖动） |
| main_code / sub_code | 7 / 11 | int32 故障码 |
| robot_mode | 15 | u8（0 自动 1 手动） |
| jt_cur_pos | 16 | 6×double，度 |
| tl_cur_pos（TCP） | 64 | 6×double，mm + 度 |
| flange_cur_pos | 112 | 6×double，mm + 度 |
| tool / user | 432 / 436 | int32 |
| EmergencyStop | 549 | u8 |
| motion_done | 550 | int32（0/1） |
| mc_queue_len | 555 | int32 |
| safety_stop0/1 | 564 / 565 | u8 |
| rbtEnableState | 771 | int32（0/1） |

解析器行为（与 UR 30003 同类问题的防线）：

- 只接受尺寸、帧头、`data_len`、校验和全部正确的帧；
- 校验失败/垃圾字节时**重同步**到下一个 `5A 5A`，不会卡死；
- 流必须持续排空，**只保留最新一帧**，不按包排队；
- 位姿 NaN/Inf 或明显不合理（全 0、超量程）报 `ProtocolError`，
  不把坏数据当有效位姿。

## 4. 单位与姿态约定

- 位置 mm，姿态是**绕基座固定轴**的欧拉角（度），齐次矩阵旋转顺序
  `R = Rz(rz)·Ry(ry)·Rx(rx)`——与本程序卡片/坐标转换工具的 static-XYZ
  完全一致，读写都不做换算。
- 点动 RX/RY/RZ **不是**"给欧拉角分量加 delta"：控制台用
  `R_new = R_delta(基座轴) · R_current` 再分解回 RPY，并处理万向锁
  （`logic/FairinoMath.h`）。
- 到位判定：位置欧氏距离 + 最短旋转角（179° 与 -179° 差 2°，不是 358°）。

## 5. 运动命令与完成判定

### 5.1 XML-RPC 客户端（`FairinoXmlRpcClient`）

- 每次调用一条短 TCP 连接（`Connection: close`），超时 1800 ms（后端）/2500 ms
  （默认）；
- HTTP 解析支持 `Content-Length`（可跨多次读取）、`chunked`、
  连接关闭定界；非 200 直接报错；
- XML-RPC 解析支持数组（FAIRINO 把返回值包在一个数组里，按 Python SDK 的
  tuple 语义拆开）、多参数、fault（含 `faultCode`/`faultString`）；
- 业务错误只显示**数字**（"法奥错误码 N"），不编造含义。

### 5.2 MoveL

线上是**一个** 33 元素数组：

```text
j1..j6, x,y,z,rx,ry,rz, tool, user, vel, acc, ovl, blendR, blendMode,
exaxis1..4, search, offset_flag, offset_x..rz, 100.0, velAccParamMode
```

- 关节全 0 时先 `GetInverseKin(0, desc, -1)`，与 SDK 行为一致；
- `vel` = 界面速度百分比，`acc = 0`（SDK 注释"暂不开放"），`ovl = 100`，
  `blendR = -1`（到位停）、`blendMode = 0`，`offset_flag = 0`；
- tool/user 取 20004 最新帧里的值，超出 0~14 时回退 0 并告警。

### 5.3 MoveJ

11 个参数：

```text
joint[6](array), desc[6](array), tool, user, vel, acc, ovl,
exaxis[4](array), blendT(-1), offset_flag(0), offset[6](array)
```

关节目标先 `GetForwardKin` 求笛卡尔位姿一并下发（与 SDK 一致）。

### 5.4 完成判定

- MoveL/MoveJ 返回 0 只代表"已接收/入队"，**不阻塞到到位**；
- 后端轮询 20004：`motion_done == 1` 且 `mc_queue_len == 0`，并且
  位置/角度在容差内 → 到位；
- 若 `motion_done` 一直不置位但位置已稳定 400 ms → 按到位处理并写日志
  （兼容把 `motion_done` 留作"程序运行"语义的固件）；
- 超时报文带上 `robot_mode`、使能、`motion_done`、队列长度，便于现场判断；
- 点动采用"在途合并"：新目标覆盖旧目标，不做多级积压；非点动指令
  清空待发队列。

### 5.5 XML-RPC 可能阻塞的不确定性（已做防御）

协议手册与 SDK 都把 MoveL/MoveJ 当"立即返回"，但个别固件可能阻塞到到位。
后端在 `dispatch` 中区分：

- 调用失败且错误是"超时"、同时 20004 显示 `robot_state == 2`（运行）或
  `motion_done == 0` → **不判失败**，保留在途指令，继续等 20004 到位；
- 其它错误立即失败并向界面报告数字错误码。

这条防御只在"确实已经在动"时生效，不会把网络断开误判成运动开始。

## 6. 使能语义

- 界面「开启使能」= 软件许可 + `RobotEnable(1)`；
- 控制器反馈 `rbtEnableState` 也必须是 1，两者同时为真才显示"已使能"；
- 上使能被拒绝时提示"先在示教器清除故障码；部分固件需切手动模式"，
  不自动切模式（自动/手动是现场安全决定）；
- 下使能或急停（`rbtEnableState` 变 0）时，后端撤销在途运动并通知执行器；
- `StopMotion` 只在"我们自己有在途运动"时发送，避免打断示教器上别人发起的运动。

## 7. 线程模型（与 UR 后端一致）

- 控制台：`FairinoMotionWorker` 独占一条 `QThread`；连接、XML-RPC、流读取、
  到位轮询全在 worker 线程，UI 只收信号；析构用
  `BlockingQueuedConnection` 关闭 worker 后 `quit/wait`。
- 20004 用 `QTcpSocket` 异步读（`readyRead`），不做阻塞 `waitForReadyRead`；
  连接阶段允许 2.5 s 建链 + 1.8 s 等首帧，均在 worker 线程内。
- 通信工具：`FairinoPoseReader` 由 `RobotWorker` 的线程持有和调用，
  与其它 reader 相同，阻塞 `waitFor*` 不在 UI 线程。
- 位姿发布节流 50 ms；`kPoseFreshMs = 500`，超过 1.5 s 无新帧告警。

## 9. 测试（31 例，全部通过）

`tests/test_fairino.cpp`，除纯函数外，用**真实本机 TCP** 假控制器：

- XML-RPC：构造、数组拆包、多参数、fault、垃圾输入、非整数错误码；
- HTTP：Content-Length 分多次到达、chunked、关闭定界、非 200；
- 20004：按实测偏移解码、跨读取拆帧、多帧合并只留最新、
  垃圾后重同步、校验和错误拒绝、data_len 不符拒绝；
- 命令布局：MoveL 33 个元素逐位校验、MoveJ 11 个参数逐位校验；
- 数学：欧拉往返、万向锁、绕基座轴旋转、179°/-179° 最小角、到位判定；
- 位姿 Reader：持续推流取最新帧、拒绝全 0 位姿、断流超时；
- RPC 客户端：本机 HTTP 假服务器往返、错误码、fault。

集成过程中单测抓到两个真实缺陷（已修）：

1. `QXmlStreamReader::readNextStartElement()` 遇到**任意** EndElement 就返回
   false，原解析器在读完第一个子元素后停在 `</value>`/`</name>` 上，
   导致数组只读到第一个元素、faultString 丢失。改为显式 token 遍历 +
   自维护层级（Qt 5.14 没有 `depth()`）。
2. `FairinoMath::eulerDegToMatrix` 第 2 行第 3 个元素笔误
   （`ca*sb*sg - ca*sg`），破坏正交性，导致万向锁与最短旋转角全错。

验证结果：

- D 工作区：构建 exit 0，ctest 3/3；`TestFairino` 31 通过 / 0 失败；
- AICode 工作区：同步后构建 + ctest 见 STATUS 交接块。

## 10. 现场验收清单（必须人工执行；单测不代表真机）

### 10.1 机器人通信工具

前置：PC 与控制器同网段（出厂常见 192.168.58.2），示教器可显示 TCP 位姿。

| # | 操作 | 预期 |
|---|---|---|
| 1 | 打开机器人通信，协议选「法奥实时 (20004)」，填 IP，端口保持 20004，连接 | 状态连上；位姿区持续刷新；日志无校验失败 |
| 2 | 对比界面 x/y/z/rx/ry/rz 与示教器 | 数值一致（mm、度，静态 XYZ） |
| 3 | 在示教器上手动移动机器人 | 界面位姿在 1 s 内跟随，无明显滞后 |
| 4 | 拔掉网线 / 关闭控制器 | 状态变未连接或超时，界面不卡死 |
| 5 | 填一个不存在的 IP | 连接失败，提示包含 20004 与具体错误 |
| 6 | 若固件状态包版本不同 | 提示"校验失败 N 帧/丢弃 N 字节"，而不是显示错误位姿 |

### 10.2 机器人控制台

前置：机器人周围无人、急停可触及；先保持示教器可见。

| # | 操作 | 预期 |
|---|---|---|
| 1 | 后端切「法奥真机」，地址 192.168.58.2、端口 20003，连接 | 显示已连接，状态行给模式（自动/手动）与使能状态 |
| 2 | 观察「开启使能」按钮提示 | 提示"自动模式 + 已上使能 + 无故障码" |
| 3 | 点「开启使能」 | 若成功：显示已使能；若被拒：提示清除故障码/切手动，不崩溃 |
| 4 | 关节点动 1°，逐轴 | 方向与示教器一致；连续点按不丢步；松手停止 |
| 5 | 笛卡尔点动 X/Y/Z、RX/RY/RZ | 平移方向为基座轴；姿态为绕基座轴转，不是"欧拉角相加" |
| 6 | 速度滑杆 10% / 50% / 100% | 实际速度变化；程序执行速度跟随滑杆 |
| 7 | 记录当前位姿为节点，单步「运行」 | 机器人到位；状态行显示"已到达目标位姿"；无超时 |
| 8 | 关节移动节点 | 关节角到位；笛卡尔位姿同步正确 |
| 9 | 点「停止」 | 机器人立即停；本地在途指令撤销；不误发第二次 StopMotion |
| 10 | 运动途中下使能 / 按急停 | 界面提示被中断；程序停止；恢复使能后可继续连接 |
| 11 | 故意让目标不可达 | 逆解失败或控制器错误码原样显示（不猜含义），程序节点失败停下 |
| 12 | 整表运行（移动 + 等待 + 拍照节点） | 顺序正确；拍照节点走既有采集链路 |
| 13 | 连接/运动中拖动主窗口 | 界面不冻结（网络阻塞都在 worker 线程） |

### 10.3 重点观察（风险项）

1. **固件与参数个数**：`blendMode` 是较新固件（V3.9.9 起）才有的参数。
   老固件可能对 33 参数 MoveL 报错。预期表现：状态行显示数字错误码，
   机器人不动。现场请记录固件版本与完整错误码，再决定是否加兼容分支
   （**不要**凭猜自动降级）。
2. **MoveL 是否阻塞**：若现场发现指令迟迟不返回但机器人已动，后端会靠
   `robot_state/motion_done` 保留在途并等到位；请记录耗时与日志。
3. **到位时机**：记录 `motion_done` 与队列长度在到位前后的变化，确认是否需要
   调整 400 ms 稳定判据。
4. **使能条件**：确认该固件是否要求手动模式才能 `RobotEnable(1)`。
5. **工具/工件号**：确认 20004 里的 tool/user 与现场实际使用的一致
   （>14 时后端回退 0 并告警）。

## 11. 回退方案

- 全部为新增文件 + 开关式接入：
  - 通信工具：去掉协议索引 5 的下拉项和 `readerFor` 分支即可；
  - 控制台：`BackendKind` 去掉 `Fairino` 分支、面板下拉去掉该项；
- `RobotProgramController` 的 `BackendKind` 显式传参只是把原来的
  `isSimulated()` 推断显式化，UR/仿真行为不变；
- 未改动相机、采集、测量、标定链路；回退不影响 3.0 其它项。
