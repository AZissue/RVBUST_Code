## 3. 3.0 候选范围（三选一或组合）

### 方案 A（推荐）：测量收口与解禁

**一句话**：把 2.0 隐藏的 7 个测量工具做到真机可交付，再放回发布包。

- 范围：M-01～M-08（M-09/M-10 视进度）。
- 交付物：
  - 真件用例与扩展后的 `circle_truth`（离线可重放 42.66 / ~10 这类失败）；
  - P1 重做（**默认关闭的开关**，现场可回退）；
  - P4 歧义标记、P3 无图兜底；
  - Hole3D 参数化补齐（算法下拉 + 参数链路）；
  - 真机 5 特征 × N 次复测报告；
  - 发布包解禁测量工具（或按验收结果只解禁通过的方法）。
- DoD：PROJECT §6「测量精度」一条转 `[x]`；`circle_truth` 6 个已知缺陷
  打印 `*** FIXED ***`；真件用例与真机读数一致；发布包工具列表恢复 14 项。
- 风险：算法改动影响既有读数 → 用"默认关闭开关 + 真件基线"控制。
- 为什么推荐：这是唯一有明确判据、明确用户价值、且 2.0 已经欠下的一块。

### 方案 B：机器人控制台现场化

**一句话**：把控制台从"能用"做到"现场敢长期用"。

- 范围：R-03 程序保存/载入、R-04 `servoj`、R-05 逐条签收、R-06 复核；
  R-02 只在有对应品牌真机时做。
- 不包含：R-01 的四个协议猜测性修改（必须先取证）。
- DoD：控制台清单 20 条逐条通过；程序可保存/载入并跨重启恢复；
  长按点动在真机连续 30 s 无积压/失步；停止按钮在任何阶段可用。
- 风险：强依赖现场机器人时间；`servoj` 需要 UR 控制器版本与安全配置配合。

### 方案 C：工程收尾与交付线

**一句话**：把仓库、文档、打包、已知缺陷收干净，为下一次交付降风险。

- 范围：E-01 合并 main / README / 根索引、E-02 工作区同步、E-03 只读层解耦、
  E-04 临时复制优化、E-05 相机错误提示、E-07 日志上限、E-08/E-09 复核。
- DoD：两个工作区同一提交、同一构建/测试结果；main 与 `HandEyeTools` 关系明确；
  已知问题表只剩"待现场证据"项。
- 风险：用户可见价值低，容易做成"只改文档"；需要与 A/B 搭配。

**建议组合**：**A 为主线 + C 的 E-01/E-02/E-04 作为前置与小步交付 + B 的 R-03
（程序保存/载入）作为一个独立小增量**。R-01/R-02/C-01/C-02/C-03 不默认纳入，
等数据/决策到位再开。

**2026-10-22 用户已确认此组合**（A + C；D 工作区为真源）。因此 3.0 的
启动顺序固定为：M0 同步 → M1 测量验收基线 → M2 P1 → M3 其余测量 → M4 解禁；
E-01/E-02/E-04 与 R-03 作为并行小增量，不阻塞测量线。
