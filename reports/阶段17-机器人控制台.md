## 1. 分层

| 层 | 文件 | 职责 |
|---|---|---|
| 节点模型 | `src/logic/RobotProgram.{h,cpp}` | `MoveNode / PhotoNode / WaitNode`（`std::variant`）、数值收敛、JSON 读写 |
| 执行器 | `src/logic/ProgramRunner.{h,cpp}` | Idle/Running/Stopping；整表/单步、失败即停、停止幂等 |
| 运动接口 | `src/logic/RobotMotionBackend.h` | 连接/使能/移动/点动/停止 + 位姿与结果信号 |
| 仿真后端 | `src/logic/SimulatedMotionBackend.{h,cpp}` | 20 ms 线性插值；不访问网络 |
| UR 真机后端 | `src/logic/UrMotionBackend.{h,cpp}` | 工作线程内跑 30003/30001/29999 |
| UR 换算 | `src/logic/UrMotionMath.h` | 单位换算、旋转矩阵合成、姿态夹角、到位判据 |
| 粘合层 | `src/app/RobotProgramController.{h,cpp}` | 后端切换、节点编辑、运行、拍照节点注入、点动规则 |
| 页面 | `src/ui/RobotProgramPanel.{h,cpp}` | 只显示状态、收集输入；不碰网络 |

「拍照」节点由 `MainWindow` 注入的采集链路完成：读机器人位姿 → 拍照 →
识别 → 保存。识别结果不再走旧页面的二次自动保存；90 s 超时防止流程挂死。

## 2. UR 协议与约定

- **30003 实时反馈**：`[4 字节 BE 长度][body]`；`q_actual` body 248，
  `actual_TCP_pose` body 440；均为 6 × big-endian double。实测包长 1220。
  位置米 → mm，姿态旋转向量弧度 → 度。
- **30001 URScript**：`movel(p[x,y,z,rx,ry,rz], a=…, v=…)` / `movej([j…])`，
  位置米、角度弧度。界面上的旋转向量范数 >π 时按等价旋转折算到 ≤π。
- **29999 Dashboard**：`robotmode`、`stop`。只有存在进行中的运动才发 `stop`，
  避免误停示教器上其他已加载程序。实测 Dashboard stop 之后继续发送 movel
  仍可执行（冒烟用例覆盖）。
- **点动姿态**：RX/RY/RZ 是「绕基座轴转多少度」，用
  `R_new = R_delta · R_current` 合成；不是欧拉角分量相加。
- **到位判据**：位置欧氏距离 + 两姿态矩阵夹角；关节用最短角差（±180 环绕）。
- **线程**：阻塞的 `waitForConnected` 与全部 socket 都在 `UrMotionWorker`
  所在线程；UI 线程只收信号。位姿最多 50 ms 发一次。
- **使能**：软件许可（UR 无远程伺服上电命令）。非 RUNNING 时连接后查询
  `robotmode` 并提示，movel 不会执行，由节点超时兜底。

## 3. 实测证据（URSim 192.168.0.38，用户授权随意操控）

- 三端口 30003 / 30001 / 29999 均可连接；dashboard 返回
  `Robotmode: RUNNING`。
- 反馈解析：`actual_TCP_pose = -0.143969, -0.43562, 0.20203, -0.001221,
  3.116277, 0.038892`（m / rad），与示教器位姿一致。
- 本工具后端端到端（`HE_UR_HOST=192.168.0.38` 的可选冒烟用例）：
  连接 → 使能 → 读位姿 → +5 mm `movel` → 实测 +4.8 mm 到位 →
  慢速运动中 stop → 停止后继续 `movel` → 回原位 → 断开。
- 测试结束后 VM 位姿回到
  `-143.969, -435.620, 202.030 mm, -0.070°, 178.550°, 2.228°`。

```powershell
build\src\Release\unit_tests.exe -o "$env:TEMP\ur_live.txt,txt"
# 报告：$env:TEMP\ur_live.robot_program.txt
```

## 5. 点动问题的定位与修复

真机反馈「点 X+ 机器人随便移动」，按 30003 实测后分成两类：

- **笛卡尔点动本身是正确的**：X+/− 只改 X，RX 绕基座 X 轴，双击会从上一
  目标继续累加；实测断言全部通过。之前的现象主要来自界面缓存的位姿有
  50 ms 节流：前一条运动刚结束就点动时，界面拿到的基准是旧值，
  会少走一步或看起来「不跟手」。
- **关节点动确实有问题**：原来是「界面缓存位姿 + 本地加 delta」，
  连点时每次都从同一个旧值出发，后一拍会覆盖前一拍，表现为乱走/少走。
  现在 `jogJoint()` / `moveJointAxisTo()` 下沉到后端接口：
  基准取工作线程的最新位姿，若上一条运动还在执行则以它的目标为基准，
  快速连点会正确累加；仿真后端同样按目标值累加。
- 测试新增：仿真「J2 +2°，其余轴不动」「快速两次 +1° 累加到 +4°」
  「滑杆绝对角回到原值」；真机用例同样保留（`HE_UR_HOST` 才运行）。
- UR 侧约束：MANUAL 模式会静默忽略外部 URScript，AUTOMATIC 才能动；
  PROTECTIVE_STOP 需要示教器复位后节点才能继续。这些都会在日志/状态里
  提示，不是本工具能绕过的。

## 6. 人工验收清单（界面）

1. 打开「工具」→「机器人控制台」。
   **预期**：顶部圆点灰色、文案「通信未连接」；右侧后端=仿真，地址置灰。
2. 点「连接后端」。**预期**：圆点变绿、文案「通信已连接」；
   点「⚡ 开启使能」后按钮显示「✓ 已使能」。
3. 步长 1 mm，连续点 X 的「+」两次。
   **预期**：X 增加约 2 mm，Y/Z/RX/RY/RZ 不变；只点一次时也只走 1 mm。
4. 切「关节控制」，步长 1°，连点 J2「+」两次。
   **预期**：J2 增加约 2°，其余关节不动（真机看 30003 反馈）。
5. 点「＋ 添加移动」→ 列表出现「移动 笛卡尔」节点 → 点该行进入编辑模式。
   **预期**：通信配置和模式切换隐藏，出现「正在编辑」与保存按钮；
   ± 只改输入框，不会动机器人。
6. 修改 X 后点「💾 保存节点 1 的修改」→ 再启动「运行当前节点」。
   **预期**：节点参数已更新，机器人移动到新目标；日志给出完成。
7. 点「⏱ 等待时间」添加 1.5 s，「＋ 添加移动」再加一个节点，点「▶ 运行列表」。
   **预期**：按列表顺序执行；任一节点失败即停，日志给出原因。
8. 运行中观察顶部。**预期**：停止按钮可用，移动/增删按钮禁用；
   运行中点「停止 (STOP)」→ 运动停止，节点失败原因为「已停止」。
9. 运行中尝试切换后端/编辑节点。**预期**：被禁用，运行结束后恢复。
10. 选「UR 真机」，确认 192.168.0.38:30003，点「连接」。
    **预期**：日志出现三端口连接与 `robotmode`；非 RUNNING 时黄/红提示。
11. 使能后在 30003 侧观察，点 Z「+」1 mm → Z +1 mm；点 RX「+」1° →
    末端绕基座 X 轴转约 1°（不是欧拉角分量加 1°）。
12. 添加一个 +20 mm 的移动节点，「运行列表」，中途点「停止 (STOP)」。
    **预期**：停止后仍可继续点动；节点失败原因为「已停止」。
13. 连接相机后添加「拍照」节点并运行。
    **预期**：读位姿 → 拍照 → 识别 → 保存一条记录；失败时节点停下并
    给出原因；超过 90 s 自动失败。
14. 断开后端。**预期**：圆点回灰，再连接时位姿重新刷新。
15. 把工具窗口缩到默认大小（约 820×620），再拖到 640 宽。
    **预期**：不出现横向滚动条；左右卡片由分隔条分配宽度，右卡最窄 280 px；
    底部四个添加/删除按钮在窄窗自动换成两行，文字不被挤掉。
16. 拖动左右分隔条。**预期**：两侧都能拖，节点列表获得多余空间；卡片不会
    被拖到完全折叠。
17. 速度滑杆 10% 与 100% 各点一次 X「+」1 mm（UR 真机，观察 30003 与秒表）。
    **预期**：100% 明显更快；滑杆不是"装饰"。
18. 添加一个 +20 mm 的移动节点，滑杆 100% 运行列表；再改 20% 重新运行。
    **预期**：两次速度明显不同（全局滑杆对列表执行同样生效）。
19. 按住 X「+」不放约 2 s 后松开。**预期**：松开前连续小步前进，松开后立即
    停止，最多再走 1 步；不会在松手后继续走很久。
20. 长按途中点「停止 (STOP)」。**预期**：立即停，排队的那一步不再执行；界面
    节点失败原因为「已停止」。

## 8. 自适应布局（2026-10-21 补）

- 根因：`RobotProgramPanel` 之前 `setMinimumWidth(780)`，而工具对话框在
  1366×768 屏幕上默认只有约 820×620，左侧工具列表再占 140 px，内容区实际
  只有约 610 px；左右卡片是固定宽（左 ≥340、右固定 420），底部四个按钮强制
  一行，所以出现横向滚动条与按钮文字被裁。
- 现在：整页最小宽 560；左右卡片放进 `QSplitter`（`childrenCollapsible(false)`，
  左卡最小 240，右卡 280–460，默认按 700:420 分配）；底部按钮用自定义
  `FlowLayout`，宽时一行、窄时自动换行；顶部速度滑杆 60–110 px 弹性，
  停止按钮最小宽 100。
- 已在 820×760 与 640×620 两种尺寸截图核对：无水平滚动，卡片与按钮完整。

## 9. 速度滑杆为什么之前"没作用"（2026-10-21 补）

两个独立原因：

1. **URScript 只缩放了 `v`，没缩放 `a`。** 原实现 movel 固定 `a=0.8`、
   movej 固定 `a=1.2`。1 mm 的点动距离太短，梯形速度曲线到不了 `v`，
   全程由加速度决定（`t ≈ 2·√(d/a)`），所以滑杆从 10% 拖到 100% 几乎
   没有手感差异。现在 `UrMotionMath::scriptSpeedsFor()` 同时给 `v` 与 `a`
   乘百分比：movel `v=0.05+0.45p`、`a=0.08+0.72p`；movej `v=0.1+1.0p`、
   `a=0.1+1.1p`；100% 与原上限完全一致（movel 0.50/0.80，movej 1.10/1.20）。
   仿真后端本来就是按 `speedPct` 缩放时长，不受影响。
2. **运行列表用的是节点里的 `speedPct` 快照。** 节点创建时把当时的滑杆值
   存进节点，`startNode()` 又拿节点值覆盖全局值，所以运行列表时拖滑杆
   完全无效。现在改为全局 `m_jogSpeedPct`（节点字段保留，留给将来的
   逐节点调速，不再覆盖用户当前选择）。
- 不再有「逐节点调速」入口：如果以后要加，应在节点编辑模式里显式提供，
  而不是复用顶部滑杆的隐式快照。

## 10. 长按连续点动（2026-10-21 补）

- 界面：`RepeatButton` 继承 `QPushButton`，按下立即走一步（原有单击语义不变），
  按住 400 ms 后每 160 ms 再触发一次 `clicked()`；松开、移出按钮、禁用即停。
  笛卡尔 6 轴与关节 6 轴共 12 个 ± 全部替换。
- 后端：长按会以 6 次/秒的频率发指令，直接写 30001 会让 UR 队列积压，
  松手后机器人继续走。`UrMotionWorker` 增加**单步合并队列**：同类型点动
  在飞时，新目标只写入 `m_queued`（覆盖上一条），当前运动到位后再发；
  失败/超时/停止（含 Dashboard stop）清空队列。`latestJogBase()` 优先取
  排队目标，长按累加不会丢步。
- 风险与边界：
  - 仍是「按步长发一条 movel」，不是 `servoj` 平滑伺服；速度低时每一步
    都有加减速，观感是一顿一顿的，真机节拍需现场评估。
  - 松手时最多多走**已排队的那 1 步**（队列只有一项）；不会无限追走。
  - 160 ms 的重复周期与步长共同决定等效速度；大步长 + 长按在靠近工件时
    应降低速度或改用单击。
  - 网络断开时 `finishPending(false)` 会同时丢弃排队步，不会留残余运动。

## 11. 已知限制 / 后续

- 点动是「按步长发一条 movel」，不是 125 Hz `servoj` 连续伺服；长按已做
  合并队列，但真机手感仍需现场评估，必要时改 servoj/RTDE。
- 30001 是 secondary client 单连接：被其他客户端占用时连接会明确失败。
- 切换后端/断开时若正在连接，工作线程最长会阻塞约 6.5 s（UI 等待析构）。
- 其他品牌（Modbus/NRC/埃夫特）尚未接入运动后端；按
  `RobotMotionBackend` 增加实现与一个枚举分支即可。
- 程序节点的保存/载入已具备 JSON 能力，但页面尚未放「保存/载入」按钮。
- 逐节点调速未提供；顶部滑杆是全局速度。
