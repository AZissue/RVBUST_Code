# 阶段 6 — 机器人位姿读数误差大时，怎么还能得到相对好的标定结果

> 2026-10-08 · 状态：**讨论稿，未实现任何代码** · 待用户拍板（见第 5 节）
> 依据：`src/logic/CalibrationService.{h,cpp}`、`sdk/HandEyeSDKBridge.cpp`、
> 阶段 7 刚验证过的「助手 = 官方 HandEyeSDK」对拍结论。

---

## 0. 先把问题问对：**现在真的是"机器人位姿读数误差大"在拖后腿吗？**

阶段 6 的原文目标是「机器人位姿读数误差大时仍能获得相对好的标定结果」。这句话
预设了瓶颈是**机器人读数**。但按本项目的规矩（T-010 就是"先量再改，量完结论不用改"），
**第一步不该是写算法，而是证明瓶颈确实在这儿**。

手眼标定 `AX = XB` 的误差有四个来源，机器人读数只是其中之一：

| 来源 | 典型表现 | 本项目能不能治 |
|---|---|---|
| ① 机器人位姿读数噪声（随机的，每次读不同） | 同一物理位姿反复读，值在抖 | **能**（多次读、剔除、加权） |
| ② 机器人位姿**固定偏差**（工具坐标错、单位错、欧拉序错） | 每次读都差同一个量 | **不能**（这是机器人配置问题，只能发现并告知） |
| ③ 标定板/识别侧噪声（2D+3D 检测的板位姿） | 同一位置重拍，板位姿在抖 | **能**（现在没做任何平均） |
| ④ 采集几何（位姿分布/组数）**差** | 位姿都绕同一根轴转 → 问题病态 | **能，而且这是最有效的** |

**③ 和 ④ 往往比 ① 更致命，而它们完全在我们手里。** 特别是 ④：如果 15 组位姿的旋转
轴几乎共线，`AX=XB` 会病态到"读数再准也解不出来"。

---

## 1. 衡量标准先说清：用**验证集**，不要用标定集残差

「标定结果好不好」必须用**独立走点**（标定之外的若干位姿，拿矩阵算一遍实际误差）来量。
用标定集自己的残差去评判"剔除离群帧有没有用"，等于在自己的离群点上自证 —— 越剔越小，
但真实精度可能更差。项目里已有"标定集/验证集"的分法（阶段 3 的真实数据复算走的就是
这条路），**阶段 6 的全部对比都走它**。

---

## 2. 先量（M0）——这一步不写任何算法，但它就是 DoD 的一半

阶段 6 原本的 DoD 是「方案评审通过 + 仿真/真实数据误差对比报告」。**M0 的产出正好就是
那份对比报告**，所以先做 M0 不是拖时间，是完成 DoD。

### M0-a 现状诊断（用已有真实数据）

手头已有 `D:\日常支持数据\handeye\HandEyeData` 的真实数据。做三张图：

1. **逐帧误差 vs 位姿**：把 SDK 返回的 `Result::errors[]`（助手已经拿到）按组号画出来，
   再看它与该组的平移/旋转分量的相关性。某根轴上一根针 → 指向机器人读数或该姿态特殊。
2. **子集重算的稳定性**：从 N 组里随机抽 N−1 组重算，重复几十次，看得到的矩阵和
   **验证集误差**散布多大。散布小 ⇒ 数据够稳，机器人噪声不是瓶颈；散布大 ⇒ 才是真问题。
3. **留一法**：每次剔掉一组，看验证集误差怎么变。如果剔掉某一组误差骤降，
   那一组就是坏数据（可能正是机器人读数错的那一帧）。

### M0-b 仿真：把"机器人读数噪声"做成一个**可以拧的旋钮**

这是最值钱的一步，而且意外地好做 —— **用戳点标定（TcpTouch）做仿真**：

`HandEyeCalibrationTcpTouch(cameraFile, poseFile, tcpFile)` 的输入就是三列文本
（相机目标点 / 机器人拍照位姿 / 机器人目标点），**可以程序化生成**。于是：

```
给定一个真值 (R, t)
  → 造 N 组几何分布良好的位姿
  → 在"机器人位姿"这一列上叠加指定大小的噪声 σ
  → 走真实的 SDK 路径（助手实际用的那一条）
  → 用独立验证集量误差
重复，扫 σ 从 0 到远超现场水平
```

得到一条**「机器人读数噪声 σ → 标定误差」的灵敏度曲线**。它会直接回答：

- 现场那种抖动水平，到底把标定误差推高了多少？
- 为了达到可接受的误差，读数噪声必须压到多少？（反过来告诉现场"读数要准到什么程度"）
- 剩下的误差有多少来自 ③ 和 ④ 而不是 ① —— 把 ③④ 也做成旋钮，就能**归因**。

**这条路不需要自研求解器，不需要 Eigen/OpenCV，用的是产品自己的代码路径**，
所以结论直接适用于现场。

### M0 的判据

- 若灵敏度曲线显示：现场抖动水平对验证集误差的贡献**远小于**③④ ⇒ **阶段 6 应关闭**
  （像 T-010 一样，结论是"不用改"，把资源给别处）。
- 若①的贡献显著，或子集重算极不稳定 ⇒ 进 M1–M3。

## 3. 可行的办法（按"性价比从高到低"，全部排除了自研求解器）

### M1 采集策略：把"位姿分布"变成可提示、可打分的东西 ★最高性价比

**为什么最有效**：标定误差对**位姿几何**的敏感度，通常远高于对单帧噪声的敏感度；
而且它是唯一**完全不依赖 SDK、不冒任何算法风险**的手段。

- **现状**：已有 `PoseGuide`（平移 ≥50 mm 且 角度 ≥15° 双阈值）。它只保证"有变化"，
  **不保证转轴不共线** —— 15 组都绕同一根轴转 20°，仍然全部满足现有阈值，但问题**病态**。
- **改法**：
  1. 增加"绕**两个不同轴**都转过"的要求（可用已采位姿的旋转轴方向做聚类/最小夹角）；
  2. 给一个**分散度评分**（旋转轴方向分布 + 平移质心偏移量的组合指标），
     采集时实时显示"当前数据够不够解"，而不是等到算完才发现；
  3. 结合已有质检卡（`DataQualityCheck`）的"分散度不足"检查，把它从"提示"升级为
     "采集前就说"。
- **判据**：同一批数据，按分布好坏分组，看**验证集**误差是否与评分单调相关。
- **成本**：纯 `logic/` + 侧栏显示，可单测（给定一组位姿 → 打分）。小。

### M2 读数层面：同一位姿多次读 / 读数稳定性检测

只有 ① 是**随机**噪声时才有用（是固定偏差就没用）。

- **改法**：(a) 每次采集连读 M 次（比如 3 次）取**中位数**入库；
  (b) 3 次读数相互差超过阈值就提示「机器人读数不稳，请重取」，不入库；
  (c) 把这 M 次的**极差**记进日志 —— 这本身就是现场"读数噪声有多大"的直接证据，
  也正是 M0-a 第 1 项要的数据。
- **判据**：同一物理位姿连读 10 次的标准差（先量，再决定 M 取几）。
- **成本**：小。`RobotWorker` 已经是异步线程，连读不冻 UI。

### M3 离群帧剔除：用 **SDK 自己的逐组误差**，不重写求解器 ★低风险

- **现状**：`Result::errors[]` 里已经有 SDK 算的逐帧误差，而且
  `Params::autoRemoveLargeError` 现在是 `true` —— **SDK 内部已经在做一轮**。
  所以要做的第一件事是**先搞清楚 SDK 那一轮到底剔了什么**（把剔除前后的
  组数/矩阵都记下来对拍），不然会做第二遍重复劳动。
- **改法**：在 SDK 之外再加一层**我们自己的**选择逻辑：
  1. 纯函数 `selectFrames(errors, k)` —— 按 `k·1.4826·MAD` 选保留帧（可单测，
     与测量模块用的是同一个稳健口径）；
  2. 用保留帧**重算**一次；
  3. 用**验证集**比较"剔之前 / 剔之后"。
- **判据**：验证集误差下降才保留这个功能；不降就不做（并且记录结论）。
- **成本**：小–中。不需要自研 `AX=XB`。

### M4 自研鲁棒求解（RANSAC / 加权 AX=XB）—— **最后手段，默认不做**

写在最后是有理由的：

1. 项目**不引 Eigen/OpenCV**，自研 `AX=XB` 需要自己实现 6×6 或 12×12 的 SVD，
   而 `logic/` 里现成的只有 3×3 对称特征分解（`symEigen3`）；
2. **会放弃一条已经验证过的一致性**：用户刚在阶段 7 用同一组数据对拍过
   「助手 = 官方 HandEyeSDK」。引入第二个求解器，这条对拍就作废了；
3. 现在**没有任何判据**能证明自研求解器比 SDK 好。

**触发条件**（只有全部满足才做）：M0 证明①是显著瓶颈、且 M1–M3 都做完仍不达标、
且用户接受"放弃与 SDK 一致"。

## 4. 建议的路线

```
M0（不写算法）
 ├─ M0-a 真实数据诊断（逐帧误差/子集重算/留一法）
 └─ M0-b 戳点仿真：噪声 σ → 标定误差 灵敏度曲线 + ③④ 归因
      │
      ├─ 结论 A：①不是瓶颈  →  阶段 6 关闭（照 T-010 的先例，写清"不用改"）
      └─ 结论 B：①是瓶颈    →  M1（采集策略）→ M2（多次读）→ M3（剔除）→ 必要时 M4
```

- M0 是**纯分析 + 一次仿真脚本**，不动产品代码，风险为零。
- M1 是**收益最高**的一项，即使①不是瓶颈，它也能改善标定结果（治的是 ④）。
- M4 大概率永远用不上；把"要不要走到 M4"留给证据决定。
