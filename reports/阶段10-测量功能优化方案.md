## 2. 「孔径」与「圆环拟合」——唯一的两个硬判据项

判据：五特征 `max|实测−标称| ≤ 0.5%×标称`，且重复性极差 ≤ 同一容差
（Ø6 ±0.030 / Ø5 ±0.025 / Ø9 ±0.045 / Ø26 ±0.130 / Ø63.5 ±0.3175 mm）。

### L0（**必须最先做**）：先把新 kernel 现在的真机数字测出来

**当前真机读数未知。** 仓库里最后一次记录是 `reports/T-012/results.json`
（**09-30 20:31**），而且：

- 容差还是**旧口径** `0.052 / 0.127`（＝0.2%，不是改判后的 0.3175）；
- 只跑了 2 个特征（`hub_d26 = 25.4482`、`disc_d63_5` **没有读数**），
  其余三个没跑；
- 它是**新 kernel 接进界面之前还是之后**，仓库里没有记录能说清。
  另据 `BACKLOG-2.0.md`，WIP 检查点阶段 Ø6 曾从 6.2648 **退到 2.0647**。

**在不知道新 kernel 现在读到几毫米之前，下面 L1–L6 全是猜。**
成本：一条 `python reports/T-012/accuracy_probe.py --reps 3`（约 12 分钟）。
产出：五个特征各 3 次读数 + new `results.json`（口径已是 0.5%）。

### L1 像素→平面的映射用了**仿射**，这是个系统性嫌疑（预期收益最大）

`measureBoundaryCircle` 把网格/像素映射到拟合平面用的是 `solveAffine`
（最小二乘仿射，6 参数）。透视投影在**平面上**是**单应**（8 参数 homography），
仿射丢掉了分母项 —— 只在视场中心附近才是好近似。

- **现象**：特征越大、越靠视场边缘，偏得越多。Ø63.5 的外缘跨约 370 px，
  正是最吃亏的尺度（历史上 Ø63.5 只读到真值的 76%，虽那是旧 kernel，方向一致）。
- **改法（二选一，可先试 a）**：
  (a) 用 8 参数单应替换 `solveAffine`（`solve3` 已在，扩成 8×8 正规方程即可，
      纯 `logic/` 改动，可单测）；
  (b) 每条射线用**邻域**点重拟合一个局部仿射（更贴合"局部近似"的初衷，成本更高）。
- **判据**：Ø63.5 与 Ø26 的误差是否随 (a) 明显收敛；用第 3 节的合成图先验证
  偏置模型，再上真机。

### L2 边缘判据是**为某一件工件调出来的启发式**

`scanEdgeRays` 里选边有两条互斥规则：

- `dip`（内部强度**极小值**）—— 注释自己写明是为 Ø26 那道凹槽调的
  （「23.54 mm where the step is really at 172 px」）；
- 否则退回「最强梯度」。

**风险**：换一件没有凹槽的工件（比如光板上的 Ø63.5），dip 规则可能选到别的跃变；
带倒角的孔口又会让"最强梯度"落在倒角而不是孔壁上。

- **改法**：不再"猜哪一个跃变"，而是把窗口内的**全部候选跃变**列出来
  （亚像素位置 + 对比度 + 方向），按"材料→非材料"的语义挑**最外/最内**的那一个；
  选不出来就标"参考"而不是给一个自信的错数。
- **判据**：人工标注对拍（现场拍一张，人工点几个边缘点，比位置）。

### L3 梯度没平滑，噪声直接进亚像素位置

剖面以 0.5 px 步长采样后直接做中心差分。标准做法是先做 σ≈1 px 的高斯平滑再求导
（等价于 Canny 的第一步）。**改法小、风险低**，建议与 L2 一起做。

### L4 亚像素精度被采样步长与 3 点抛物线限制

步长 0.5 px；抛物线只用相邻 3 点。**改法**：步长降到 0.25 px，或在 ±1.5 px
窗口上做二次拟合（对模糊边缘更稳）。成本低，收益取决于相机实际模糊半径。

### L5 语义题：图纸的 Ø 是**孔口**（含倒角）还是**孔壁**？

图像给的是孔口/倒角边缘，3D 给的是孔壁 —— 两者**差一个倒角量**。代码里那段
`inner3d_med` 调试本身就是作者在旁证这件事。**这不是算法问题，是定义问题**，
而且直接决定：现场量出来的数该跟图纸哪个尺寸比、超差多少算超差。
**需要用户拍板**（第 5 节第 1 条）。

### L6 种子半径偏出窗口 → 整条射线被丢

窗口固定（圆环 10 px / 孔 6 px），种子半径来自 3D 外缘/泛洪。若种子偏出窗口，
该射线直接丢弃，覆盖下降 → 标"参考"。**改法**：窗口按种子不确定度自适应
（比如 `max(固定值, 1.5×种子误差估计)`）。低优先。

## 3. 其余六个方法：**不投工程，投验证**

这六个（平面度 / 高度段差 / 面面距离夹角 / 包围盒 / 截面轮廓 / 重复性）目前**没有真机
判据，也没暴露问题**。按本项目自己的规矩（T-010 的「先量再改，量完结论是不用改」），
**不建议现在改它们的算法** —— 改了没有任何判据能证明是变好还是变坏。

要做的是**把新 kernel 重新纳入真值回归**，顺便给这六个补上缺的场景：

| 方法 | 现有点云单测 | 建议补的场景 |
|---|---|---|
| 平面度 | PV/RMS/最小区域/剔除飞点 | 倾斜面 + 已知 PV（验证最小区域搜索不劣于 LSQ） |
| 高度段差 | 已知 3 mm 台阶、符号 | 两平行面 + 已知间距 |
| 面面距离夹角 | 构造倾角、平行/非平行 | 已知夹角（含 3° 阈值两侧） |
| 包围盒 | 尺寸、斜放不受影响 | 已知尺寸的斜放盒（更极端姿态） |
| 截面轮廓 | 台阶跟随 | 已知台阶高度（验证分箱不糊掉台阶） |
| 重复性 | 手算对拍 | 已够，不动 |

### 3.1 唯一能回归亚像素路径的办法：**合成图像真值**

`codex_testData/` 是**点云**真值，走不了图像路径。要单测 `measureBoundaryCircle`
的图像分支，只能**程序化画图**：

- 生成一张合成灰度图：已知半径 R、已知边缘模糊 σ、已知背景/材料灰度、
  加已知高斯噪声；同时生成一张"已知的网格点云"（半径 R、点距 p）；
- 把两者喂给 `measureBoundaryCircle`，断言 `|直径 − 2R| < 某个等效像素容差`；
- 再扫参数（R / σ / 噪声 / 点距），画出误差曲线 —— **这张曲线就是 L1–L4 的判据**，
  在没有相机的情况下一分钱不花就能验证每一项改动。

同一招还能反过来验证 L1：合成一张**带透视**的图（用真单应投影一个圆盘），
对拍"仿射映射 vs 单应映射"哪个更接近真值 —— 这能把 L1 从"嫌疑"变成"证据"，
**在占用真机之前**。
