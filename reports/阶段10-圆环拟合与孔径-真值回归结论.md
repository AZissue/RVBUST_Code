**"误差较大"复现了，而且定位到了唯一一个原因：边缘选择。**
当工件在材料边界之内还有第二道跃变（台阶 / 槽 / 沉孔）时，
两个工具都会**停在靠里的那一道**，并且**报 `reliable = yes`**：

| 场景（图纸 Ø） | 实测 | 误差 |
|---|---|---|
| 圆盘 Ø26，内圈 R12 处有一道台阶 | **23.9998** | **−7.69%** |
| 圆盘 Ø26，内圈 R10 处有一道台阶 | **20.0008** | **−23.07%** |
| 孔 Ø9，孔口沉孔到 R6 | **8.9995**（孔壁） | **−25.00%** |
| 孔 Ø9，孔口沉孔到 R5.5 | **8.9995**（孔壁） | **−18.19%** |

除此之外的所有情形（平面 + 圆形边界、倒角、模糊、噪声、大倾角、离轴、镜头畸变）
**全部在 0.5% 判据之内**，多数在 0.05% 以内。
所以 **子像素算法、像素→平面映射、亚像素步长都不是问题** —— 方案里排在前面的
L1（仿射 vs 单应）、L4（步长/抛物线）**实测收益极小，应当降级**。

另有一个独立缺陷：**没有可用图像时，圆环拟合返回 "找不到材料边界"，一个数都给不出**
（孔有兜底，圆盘没有）。

## 1. 这套回归测的是什么（`tests/circle_truth.cpp`）

不需要相机、不需要 SDK，纯计算，已注册进 ctest（`circle_truth`，约 28 s）：

- 场景 = 一块**倾斜平面**被**针孔相机**成像。倾斜是刻意的：这样投影到图像上是
  **真正的单应**而不是相似变换，才能检验 kernel 用 6 参数仿射拟合"像素→平面"的代价。
- **点云**按对齐 RGB-D 传感器的作法生成：网格格点 (a,b) 就是"过图像像素
  ((a+0.5)·s, (b+0.5)·s) 的射线"与表面的交点 —— 与真实相机同构。
- **图像**同一场景渲染：4× 超采样 → 高斯 PSF（`blurPx`）→ 盒式降采样 → 灰度噪声。
  表面是**多能级**的（背景 30 / 顶面 200 / 下沉面 140），所以台阶既体现在几何上，
  也体现在亮度上 —— 这正是"选哪一道跃变"这件事的成因。
- 每个场景直接读回 `measureBoundaryCircle` 的直径、圆心、圆度、扇区覆盖率、
  `subpixel` / `reliable`，与已知真值对比。

**诚实性设计**：出画（特征 + 边距超出图像范围）的场景会被标 `OUT OF FRAME` 并跳过 ——
第一轮就是这么发现我自己造的两个"离轴"场景其实特征中心落在图像外，
那一轮的 −1.48% 是我场景的错，不是 kernel 的错。

## 2. 实测结果（31 个场景）

### 2.1 通过的部分 —— 这些**不用改**

| 情形 | 实测误差 |
|---|---|
| 孔 Ø5 / Ø6 / Ø9 / Ø26，理想 | 0.011% – 0.029% |
| 孔 Ø6，blur 1 px + 噪声 2 级 | −0.020% |
| 孔 Ø26，blur 1 px + 噪声 2 级 | 0.012% |
| 孔 Ø9，**离轴 25 mm** + k1=0.15 | **0.110%**（最坏） |
| 孔 Ø6，倾角 45° | −0.045%（但覆盖率掉到 0.35） |
| 圆盘 Ø26，理想 / blur 1 px | −0.003% / −0.004% |
| 圆盘 Ø26，**离轴 20 mm** + k1=0.15 | 0.084% |
| 孔 Ø6/Ø9，孔口倒角 0.5 / 1.0 mm | 报**孔口**，误差 ≤0.02% |
| 圆盘 Ø26，边缘倒角 0.5 mm | 报**轮廓**，误差 −0.003% |
| **无图像**（走 3D 兜底）：孔 | 0.070% – 0.193% |

两条重要的**好消息**：

1. **"图纸 Ø = 孔口"这个约定，代码本来就是对的**：带倒角的孔报孔口、实心盘报轮廓，
   都对得上图纸。所以 L5 不是"改算法"，而是"要确认图纸指的是哪一道"。
2. **仿射映射够用**：离轴 25 mm + 畸变 15% 也只偏 0.11%。L1 不值得优先做。

### 2.2 失败的部分 —— 两个真实缺陷

> **2026-10-08 更新：两个缺陷都已修好**（缺陷 A → P1，缺陷 B → P3），
> 下表是**修复前**的实测记录，保留作为验收依据。修复后 6 个场景全部 ≤0.5%，
> 见 §7。这两个场景组现在是 `circle_truth` 的常驻回归项。

**缺陷 A：多跃变工件选错边缘（6 个场景，误差 7.7% – 25%）** —— 已修（P1）

扫描从种子出发，**遇到第一道跃变就停**，没有继续找到"最外的材料边界"：

- 圆盘：种子在材料内，向外扫，先撞到内部台阶（R12 / R10）就停了 → 报台阶直径。
  （同一场景**没有台阶**时报 25.999，说明外缘本身够得着，不是搜索范围不够。）
- 孔：种子在孔内，向外扫，先撞到孔壁（R4.5）就停了 → 报孔壁，
  而图纸要的是孔口沉孔（R6）。

**最危险的不是偏得多，是它不吭声**：四个场景全部 `subpixel=yes, reliable=yes`。
现场拿到 `23.9998` 和拿到 `25.999` 是一样的提示强度，唯一能看出不对劲的线索是
圆心偏了 0.5–2.0 mm（可圆心本来就不是重点）。

**缺陷 B：无图像时圆环拟合给不出结果（2 个场景）** —— 已修（P3）

`contour3d`（外缘的 3D 轮廓兜底）只在 `if (map.ok)` 里构造，而 `map.ok` 需要有效图像。
于是**没有图像 = 直接返回"找不到材料边界"**，文档里写的 3D 兜底不可达。
孔的分支在 `measureBoundaryCircle` 末尾有 `holeBoundary(pts)` 兜底，所以孔有数、圆盘没有。
（`results.json` 里 `disc_d63_5` 那条 "没有读到任何读数" 很可能就是这个。）

| 项 | 原判断 | 实测后的判断 |
|---|---|---|

## 4. 这套回归**测不到**什么 —— 还需要什么

它测的是算法对**理想化**场景的响应。下列差异仍在，任何一条都可能是现场误差的来源，
而它们**只有真实数据能回答**：

1. **真实图像质量**：反光、阴影、纹理、真正的相机模糊半径。
2. **真实点云质量**：X2 的点云在孔口/边缘处本来就有"飞点"（孔壁与底面混叠），
   我的合成点云太干净。
3. **图像与点云的真实配准误差**：这里假设两者由同一射线模型生成，完全对齐。
4. **现场实际工件的几何**：我按"台阶 1–2 mm、沉孔 0.5–2 mm"造，
   真实工件是不是这样，只有对一次真件才知道。

**所以：本结论的定位是"把嫌疑范围从 6 条缩小到 1 条"，
不是"证明现场误差就是它"。** 要坐实，需要**一个真件 + 一个已知真值**：

> **请给我一组这样的数据**：一个带台阶（或沉孔/倒角）的真实工件，
> 用卡尺或三坐标量出它的实际尺寸（尤其是图纸 Ø 对应的那个尺寸），
> 再在助手上对同一次采集跑一遍圆环拟合 / 孔径，把读数截给我。
> 有这一组，就能判定现场误差 = 缺陷 A，还是另有原因。

**2026-10-08 更新**：用户给了 `tests/data/circle/2.ply`（`1.ply` 的裁剪，35 383 点，
1 px = 0.0675 mm）。它**不是**缺陷 A 那类工件（图像里只有一道跃变），
但把另一件事说清楚了：助手报的 5.4321 mm 是**对图像里那个黑圆的准确读数**
（独立重建 ⌀5.4381，差 0.006 mm），所以那 0.43 mm 的来源**不在算法里**，
而在"图像里那个黑圆本身就有 ⌀5.44"。**仍差一次实物测量（卡尺/塞规）才能定性** ——
见 `阶段10-真件点云分析/2ply-结论.md` §4。那组"带台阶 + 已知真值"的数据**仍然需要**。

## 7. P1 / P3 实现记录与验收（2026-10-08）

### 7.1 P1 做了什么（`MeasureTools::scanEdgeRays` 重写）

原来"沿射线从种子往外扫，遇到第一道跃变就返回"。现在分三步：

1. **枚举全部候选跃变，而不是取第一个。** 沿射线以 0.5 px 步长取样，对灰度的
   一阶差分做 1 px 非极大值抑制，找**所有**局部极值，每个都用梯度抛物线求亚像素位置。
   候选要同时过两道门槛（这是本次的关键）：一条**噪声门**只管斜率，一条**幅度门**只管跃变大小。
   ```
   gFloor = max(2.5, 0.05 * (hi - lo))     // 斜率门：压噪声
   aFloor = max(5.0, 0.10 * (hi - lo))     // 幅度门：压小起伏
   ```
   两道分开是必须的：沉孔那道 140→200 的台阶，斜率峰值过不了原来的单一门
   （`max(3.0, 0.15*(hi−lo))`），所以旧代码根本看不见它 —— 这就是缺陷 A 的直接原因。
   每个候选还记下跃变**前后各自的灰度中位**（`before` / `after`，取自 ±2…±5 采样）。
2. **按方向筛，再串成"一段"。** `materialInside` 决定要哪个方向（圆盘要亮→暗，
   孔要暗→亮），方向不对的直接丢。然后在剩下的候选里**从内往外**连成一条链，
   终止条件不是"第几道"而是**空隙里的灰度掉回了背景/空腔水平**：
   ```
   if (havePrev && c.before <= lo + 0.25 * (hi - lo)) break;
   ```
   即"两道跃变之间如果是材料内部（还是亮的），就继续走；如果掉回空腔，说明这段材料到这儿就结束了"。
   （旧代码用的是"第 n 个候选就停"这类位置启发式，换一个工件就失效。）
3. **取链上最外那一道 = 链尾。** 这正是"最外材料边界"的定义：
   ```
   const double r = chain.back();
   ```
   链上超过一道时，把**最里面那道**的半径记进 `alts`，向上汇总。

**对外接口**：`BoundaryCircle` 新增

```cpp
std::vector<double> candidates;   // 从小到大排的候选直径（只有真正歧义时非空）
bool ambiguous = false;           // 是否要求用户确认量了哪条边
```

当"半数以上的射线都看到了内侧那道跃变"（`multiRays * 2 >= 360`）且比例尺已知时，
填 `candidates = {内侧直径, 外侧直径}`、置 `ambiguous = true`，并在 `message` 里写清
「边缘内侧还有一道跃变 ⌀X mm，已取外侧 ⌀Y mm（最外材料边界）」。

**另一个配套改动**：向外搜索的窗口原来是固定的 ±10 px（圆盘）/ ±6 px（孔），
现在按**物理尺度**给（`min(5.0, max(0.8, 0.6·r0mm))` mm 折算回 px，且不小于窗口内沿）。
固定 px 数在小孔上够不着外侧边界，放大孔上白跑。原来只记**第一次迭代**看到的内侧候选
（拟合把锚点走到真边界之后，窗口就够不回内侧了），所以 `altInnerPx` 只在首次非空时赋值。

### 7.2 P3 做了什么

`contour3d` 原来嵌在 `if (map.ok)` 里，而 `map.ok` 需要有效图像 —— 于是"没有图像"时
圆盘分支**一个数都给不出**（孔有 `holeBoundary` 兜底，圆盘没有）。现在把 3D 轮廓的构造
提到 `map.ok` 之外：圆盘在无图像时也走"平面带分连通域 → 取轮廓 → 拟圆"，只是**不做**
需要映射的像素级精化。有图像时行为不变（映射仍然门控在 `map.ok` 里）。

### 7.4 **P1 修不了什么**（必须写死，防止误判）

**真件 `tests/data/circle/2.ply` 的 5.4321 mm（+8.6%）不是缺陷 A，P1 修不好它。**
那条边在图像里**只有一道跃变**，没有"第二道边"可供挑选；
5.4321 是对图像里那个黑圆的**准确**读数（独立重建 ⌀5.4381，差 0.006 mm）。
详见 `reports/阶段10-真件点云分析/2ply-结论.md` §3 与 §5。
**以后再看到"P1 做完了 2.ply 还是 8.6%"，那是预期行为，不是 P1 没做好。**
