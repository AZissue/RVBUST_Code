## 2. 24 种欧拉约定与目录

### 2.1 记号

- 名字里的轴顺序 = 三个值依次对应的轴；
- `s` = **static（外旋）**，绕固定基轴转：`R = Rk(c)·Rj(b)·Ri(a)`；
- `r` = **rotating（内旋）**，绕随动轴转：`R = Ri(a)·Rj(b)·Rk(c)`；
- 恒等式：`外旋(i,j,k)(a,b,c) == 内旋(k,j,i)(c,b,a)`。

### 2.3 高级档（12 项，勾选后才显示）

全部首尾同轴的 proper Euler，rZYZ 最常见排最前：
`rZYZ`(7)、`rZXZ`(22)、`sZYZ`(28)、`sZXZ`(27)、
`rXYX`(18)、`rXZX`(19)、`rYXY`(20)、`rYZY`(21)、
`sXYX`(23)、`sXZX`(24)、`sYXY`(25)、`sYZY`(26)。

> 18 + 12 = 30，正好是整个目录，没有漏项也没有重复。

### 2.4 Id 的持久化规则

`AppConfig::calib_pose_format` 存的是 `Id` 的整数。**0..6 与旧
`TransformTools::RotationFormat` 逐个一致**（`EulerSxyz=0`、`EulerRzyx=1`、
`EulerRxyz=2`、`QuatWxyz=3`、`QuatXyzw=4`、`Matrix3x3Row=5`、`RotationVector=6`）。
新约定只能用新整数（7..29）；`Matrix4x4Row = 29` 是本轮追加的 4×4 姿态变换矩阵，
不占用已持久化的 3×3（Id 5）。单测 `idIntegersKeepThePersistedLegacyValues` 钉死这一点。

### 2.5 标定卡片只能用 3 个旋转数的格式

卡片固定 6 个数是红线。`Entry::cardUsable = (valueCount == 3)`，所以手眼标定页的
格式下拉框只列三数格式（含首尾同轴，勾高级后可见）；坐标转换页没有这个限制，
四元数与矩阵也能选。

## 3. 通用欧拉逆解（`eulerAngles`）

正向 `buildRotation(id, unit, values)` 覆盖全部 24 种；反向要能把任意旋转矩阵解回
该约定的三个角。做法是**轴置换 + 复用两条标准公式 + 前向验证**：

1. 三轴互异：新 X←i、Y←j、Z←k，套用 `sXYZ` 的公式
   （`b=asin(M02)`、`a=atan2(-M12,M22)`、`c=atan2(-M01,M00)`）。
2. 首尾同轴：新 XYZ ←（剩下的那根轴, j, i），套用 `ZYZ` 的公式
   （`b=acos(M22)`、`a=atan2(M12,M02)`、`c=atan2(M21,-M20)`）。
   **不能**直接写 `{i,j,k}` —— i == k 时它不是置换。
3. 统计置换的逆序数：奇置换（det = −1）的共轭会把旋转角整体取反，
   解出的三个角要**乘以 −1**。
4. 把解代回 `buildRotation` 验证；失败时取第二分支 `(a+π, proper ? −b : π−b, c+π)`
   再验证。

单测 `everyEulerConventionRoundTrips` 对 24 种 × 4 组角（含 `(0,0,0)`）逐一往返；
`extrinsicEqualsReversedIntrinsic` 钉住外旋/倒序内旋的等价关系。

## 4. 推算工具的设计

### 4.1 判据

设点动前后示教器上的两组旋转数按候选约定解成 `R1`、`R2`：

- **绕基坐标轴点动**：`R2 = R_axis(θ)·R1` ⇒ `D = R2·R1ᵀ = R_axis(θ)`；
- **绕工具坐标轴点动**：`R2 = R1·R_axis(θ)` ⇒ `D = R1ᵀ·R2 = R_axis(θ)`。

正确约定下，`D` 必须**正好绕用户点动的那根轴**：该轴分量 `|dot|` 对应
`acos(|dot|) ≤ 2°`（`kAxisToleranceDeg`）；同时相对转角必须在 **5°~175°**
（`kMinJogDeg` / `kMaxJogDeg`）—— 角度太小会被噪声淹没，接近 180° 时转轴病态。
判据与机器人当前绝对姿态无关，不需要零位、不需要标定数据。

### 4.2 为什么必须给「点动轴」

开发中实测：**只看"相对旋转是否落在某根基轴上"时，一次 Z 点动会同时命中
sXYZ / sYZX / sZXY 三种外旋约定** —— 它们只是轴顺序循环换名。把「你点的是哪根轴」
加入条件后，这三者被分开（sYZX、sZXY 的第三个值并不绕 Z）。

但**同一根轴的一组实验仍有本质歧义**：sXYZ 与 sYXZ 的前两个值互换、第三个值都绕 Z，
"前两个值不动、第三个值加同一个角"在两套约定下的相对旋转都是 `Rz(θ)`。
这不是判据写错，而是数据本身分不开。单测
`inferenceKeepsTheSwapAmbiguityForASingleJog` 把这个局限钉住，界面据此提示
"再补一组绕另一根轴的点动"。**两组绕不同轴的点动可唯一判定全部 24 种**
（`inferenceIdentifiesEveryConventionBaseJog` / `...ToolJog`）。

### 4.3 三种确认方式

| 方式 | 用户提供什么 | 覆盖范围 | 说明 |
|---|---|---|---|
| **① 绕基坐标轴点动（推荐）** | 点动轴 + 转动前后两组 3 个数 | 全部 24 种 | 普通姿态起，只绕一根基轴转 15°~60°；最好再做一组另一根轴 |
| **② 绕工具坐标轴点动** | 同上，轴按工具系选 | 全部 24 种 | 现场只能在工具系点动时用 |
| **③ 用已有标定数据按残差排序** | 已采好的手眼标定数据（「用当前会话」或「选择数据文件夹」） | 5 种常见约定 | 本页直接点「试算各格式」；判据按 SDK 总平均误差排序。标定方式 / 安装方式 / 文件名仍与标定页共用 |

界面行为：

- 判定唯一 → 绿色提示 + 「应用为全局预设」可用（写 `AppConfig`，标定页与主界面
  「计算」立即按它读卡片）；
- 无匹配 → 红色提示 + 排查清单（角度单位、是否真的只绕一根轴、转角是否在范围内、
  是否点动了多根轴）；
- 多候选 → 列出候选并提示再补一组不同轴的点动；
- 输入只填一半 / 不是 3 或 6 个数 → 指出是哪一组实验的问题，不猜。

## 8. 遗留 / 边界

- **只判欧拉约定**：角度单位与四元数顺序不在推算范围内（用户 2026-10 决定）。
  若现场连单位也不确定，先用「试算各格式」的度/弧度两列对照。
- **单轴实验有本质歧义**：sXYZ / sYXZ 这类"前两轴互换、第三轴相同"的约定，
  只点一根轴分不开。界面已提示，测试已钉住；不要试图用打分把它伪装成唯一。
- **推算依赖输入准确**：示教器上两个数只要有一个抄错，结果就会无匹配。
  无匹配时的第一排查项是"数抄对了吗"，然后是单位与点动轴。
- **真机尚未走一遍**：判据由合成位姿证明（24 种 × 基轴/工具轴）。建议用户用
  一台已知格式的机器人按 §7-B 走一次，确认现场数值与界面一致后再交给客户。

## 9. 2026-10-19 第二轮现场反馈修正

用户手动复测后提出 4 条，本轮处理前 3 条，第 4 条给出分析结论。

### 9.1 未勾「高级」仍看到首尾同轴（已修）

**现象**：下拉框显示「显示高级格式（首尾同轴）」未勾选，但 rZYZ 仍在列表里。

**根因**：rZYZ 属于 proper Euler（首尾同轴），上一轮却放在常用档。勾选框的
语义与实际列表不一致 —— 用户会以为勾选没生效。

**修法**：把 `EulerRzyz` 从常用档移到高级档，并同步改 `Entry::tier`
（`tier()` 读的是 `Entry::tier`，只改列表不改条目会继续报 Common —— 本轮单测
先抓到了这一点）。现在：

- 常用档 **18** 项：12 种三轴互异 + 旋转矢量 + 2 四元数 + 4×4 + 2 种 3×3；
- 高级档 **12** 项：全部首尾同轴（rZYZ 排最前）；
- 两档不重叠，18 + 12 = 30 = 全目录。

**覆盖范围**：坐标转换页与手眼标定页共用 `RobotDataFormats::ids()`，所以两处
同时修正；`cardOnly` 过滤后标定页高级档仍是 12 项。单测新增/改写断言：
`tier(EulerRzyz) == Advanced`、常用档里 proper Euler 数量为 0、两档合计 30。

### 9.2 推算页无法选位姿 txt；标定页只能手写文件名（已修）

- 标定页三个文件行（位姿 / 相机点位 / 戳点）都改成「输入框 + 浏览」；
  `chooseCalibrationFile()` 统一处理：
  - 起始目录 = 当前数据文件夹（为空时退回文件所在目录，再退回主目录）；
  - 过滤器 `文本文件 (*.txt);;所有文件 (*.*)`；
  - 文件就在当前文件夹 → 只写文件名；
  - 选了别的文件夹 → 连同「数据文件夹」一起改，避免"选了文件还在读老目录"。
- 推算页方式 ③ 增加一组「标定数据」输入：数据文件夹、位姿文件、相机点位文件、
  戳点文件、标定方式、安装方式、标定板类型、位姿位置单位、自动剔除 —— 与标定页
  **双向同步**（相等即跳过，防 `setText → textChanged → setText` 死循环）。
  推算仍走 `gatherCalibrationInput()`，没有第二份计算逻辑。
- 删掉「选择数据文件夹」「去手眼标定页」两个按钮（前者与文件夹行重复，
  后者不再需要）；数据来源说明改为指向本页的文件夹行。

### 9.3 不同方法的按钮没有正确隐藏（已修）

### 9.4 文件路径选择 / 识别 / 增删改查是否该解耦（分析结论）

**结论：值得做，但先做「读」的一层，别急着做统一对话框，更别碰写入路径。**
建议分三步，风险从低到高：

**P1（建议现在做，1~2 天）—— 纯逻辑层：**

1. `logic/TextTableReader`：把现在散落的"按行读 txt、按空白/逗号切数字、列数校验、
   忽略空行/注释、带行号的错误文案"收成一处。目前 `CalibrationService` 用
   `ToolInputParser`，`ToolsPanel::gatherCalibrationInput` 里又有一个 `readLines`
   lambda，报错措辞各写一套。抽出来后两处都调用它，新增单测覆盖 BOM、CRLF、
   注释行、列数不符、文件不存在。
2. `logic/SessionLayout`：会话目录里已知文件名的唯一出处
   （`pose.txt`、`cameraCapturePointXyz.txt`、`tcp.txt`、`cameraCaptureRobotPose.txt`、
   `intrinsics.txt` / `extrinsics.txt`、`<n>.png` / `<n>.ply`），提供
   `defaultName(role, calibType, eyeMode)` 与 `resolve(folder, role, explicitName)`。
   解决两个现有隐患：默认文件名逻辑分散在 `ToolsPanel`，以及"选了绝对路径但
   文件夹没改"的静默读错目录。
3. `ui/FilePick`：只封装"弹框 + 起始目录 + 过滤器 + 写回 folder/filename 两个控件"，
   不封装业务。三个页面共用，行为一致。

**P2（出现第三个文件消费页面时做）—— 发现与清单：**

`logic/FileCatalog::list(folder, role)` 枚举候选文件（名字、修改时间、行数/列数是否
有效），喂给下拉框。现在像素→3D 页自己扫目录、标定页让用户手输文件名，
同一件事两种体验。注意 `tests/data/` 不提交的规矩不变。

**P3（只有确实需要批量管理时做）—— 增删改查：**

写入必须继续只走 `DataManager`/`CaptureFlow`（保护「保存路径回退」「会话目录精简」
「卡片格式校验」三条红线）。若要统一，做法是给 `DataManager` 增加一个只读
`SessionManifest` 查询接口，**不新增磁盘文件**；任何"往会话目录里加 JSON"的方案
都要先过用户，因为它触碰精简红线。

**为什么不做大一统的「文件管理器」框架：**

- 工具页对文件的用法是**只读 + 少量角色固定的文件**，不是通用 CRUD；
- 统一对话框会把"选文件"和"改文件夹"的语义绑死，而这两件事在标定页恰恰需要
  一起变（见 9.2）；
- 真正的问题是**重复的解析与命名逻辑**，不是缺少一个 UI 组件。先抽 P1，
  观察新增页面是否还需要更多，再决定 P2/P3。

**排查收益**：P1 落地后，每个读文件入口都能在日志里留一行
`[数据] role=pose file=... rows=12 status=Ok`，现场"读不到/读错了"不用再猜是哪一层。
