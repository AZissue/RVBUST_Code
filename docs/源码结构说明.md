# RvcVisionStudio 源码结构说明

> 面向刚接手项目的 C++ 开发者。目标是：看完能回答「我要改 X 功能应该动哪个文件」。
> 本文以代码实际内容为准（对应 M3 里程碑）。构建/运行操作请看 [构建与测试指南](构建与测试指南.md)，模块清单与参数表请看 [../README.md](../README.md)。

## 1. 分层架构与一次「运行」的完整调用链

### 1.1 分层架构图

```
┌────────────────────────────────────────────────────────────────────┐
│ src/app/main.cpp          入口：--selftest / --smoke / --demo GUI   │
├────────────────────────────────────────────────────────────────────┤
│ src/ui/                   依赖 Qt6 Widgets + 自编译 VTK(GUISupportQt)│
│  MainWindow    无边框主窗 + 自定义暗色标题栏；内部 QMainWindow 承载   │
│                Dock/菜单/工具栏；scene 用 unique_ptr 控生命周期      │
│  FlowModel     QtNodes AbstractGraphModel ↔ core::Process 双向同步  │
│  FlowView      画布视图（拖放实例化模块）                            │
│  Toolbox       可折叠分类树 + 搜索过滤；拖拽/双击实例化模块          │
│  PropertyPanel 按 ParamDesc 自动生成参数控件                         │
│  Viewport3D    QVTKOpenGLNativeWidget 交互视口 + 框选ROI             │
│  ViewportManager 多视窗 Dock 管理 + 按名路由显示回调                 │
│  EngineRunner  Engine 异步封装（QThread worker + 信号）              │
│  Theme         Foundation 设计系统 token + 全局 QSS + QtNodes 风格    │
├────────────────────────────────────────────────────────────────────┤
│ src/modules/              13 个内置模块（依赖 core + PCL，无 Qt）    │
│  acquisition / preprocess / fit / measure / io / display            │
│  CloudUtils.h（NaN/ROI 工具）  FitUtils.h（RANSAC 封装）             │
├────────────────────────────────────────────────────────────────────┤
│ src/camera/               RVC SDK 封装（M1 真机地基，依赖 RVC::RVC） │
├────────────────────────────────────────────────────────────────────┤
│ src/core/                 ★ 核心层：仅依赖 Qt6::Core + PCL common    │
│  DataTypes     端口数据类型（variant 端口值，含 RoiBox/Plane3D 等）  │
│  ModuleBase    模块基类 + ModuleContext + ParamDesc 参数机制         │
│  ModuleRegistry 类型注册表（工厂 + 分类枚举）                        │
│  Process       模块有向图：连线校验、拓扑排序、输出缓存              │
│  Solution      方案：持有 Process，QJsonObject 保存/加载             │
│  Engine        runOnce：同步拓扑执行（Qt-free，可无头）              │
├────────────────────────────────────────────────────────────────────┤
│ third_party/   QtNodes v3.0.9 · Catch2 v3.9.1 · VTK 9.2.2(自编译)   │
└────────────────────────────────────────────────────────────────────┘
```

依赖方向只允许自上而下：ui → modules → core；ui → camera；app → 全部。
core 不知道 ui 的存在；显示回调、进度回调都以 `std::function` 注入，保证 core 可无头运行。

### 1.2 一次「运行」的调用链（GUI 路径）

```
用户点击「▶ 运行」
  MainWindow::runOnce()                     src/ui/MainWindow.cpp
    ├─ engineRunner_->start(process)  失败(已在运行)→状态栏提示并返回
    └─ runAction_->setEnabled(false)  防并发

EngineRunner::start(Process&)               src/ui/EngineRunner.cpp
  └─ QThread::create(lambda).start()  ──────── worker 线程开始 ────────
       Engine::runOnce(process, onModule)    src/core/Engine.cpp
         ├─ process.topologicalOrder()       src/core/Process.cpp（Kahn）
         ├─ process.clearOutputCache()
         └─ 对每个节点 nodeId（拓扑序）：
              收集输入：遍历 process.links()，从 process.cachedOutput(上游) 取 PortValue
              ModuleContext ctx(inputs, logs)          src/core/ModuleBase.h
              module->execute(ctx)                     各模块（worker 线程内执行 PCL）
              ctx.outputs() → process.setCachedOutput()（供下游读取）
              onModule(record) → Q_EMIT moduleFinished(rec)
       Q_EMIT runFinished(result, totalMs)
  ──────── 以下经 Qt::QueuedConnection 回到 GUI 线程 ────────
  MainWindow::onModuleFinished(rec)          逐模块日志（含耗时 ms）→ 日志 tab
  MainWindow::onRunFinished(result, ms)      复位 running、恢复按钮、总耗时、
                                             fillResultsTable()（Scalar → 结果 tab）

显示链路（Display3D 模块 execute 在 worker 线程触发）：
  Display3DModule::execute                   src/modules/display/Display3DModule.cpp
    └─ 静态回调 cb(viewport名, cloud, overlays)（由 MainWindow 构造时注入）
         MainWindow 注入的 lambda：
           QMetaObject::invokeMethod(this, ..., Qt::QueuedConnection)  → GUI 线程
             ViewportManager::routeDisplay()    src/ui/ViewportManager.cpp
               ensureViewport(名字)（不存在则新建 Dock 并 tabify）
               Viewport3D::setPointCloud(cloud, overlays)  src/ui/Viewport3D.cpp
                 updatePointCloud/addPointCloud + clearOverlays/drawOverlays
                 resetCamera + renderWindow->Render()
```

线程规则总结：core/Engine/模块 execute 全部跑在 worker 线程；一切触碰 Qt 控件
（日志、视口、结果表）的代码都经 QueuedConnection 回 GUI 线程。Process 的图结构
（节点/连线/参数）运行期间只允许 GUI 线程只读使用结果缓存，禁止编辑。

## 2. core 层（src/core/）— 无 QWidget 依赖，可无头运行

### 2.1 `src/core/DataTypes.h` — 端口数据类型（纯头文件）

- **职责**：定义模块端口上传输的所有类型化数据。
- **关键内容**：
  - 数据结构：`PointCloud`（`pcl::PointCloud<pcl::PointXYZ>::Ptr` 别名）、`Image`（占位）、
    `Plane3D`（单位法线 a,b,c + d，带 `signedDistance()` 和 `alignWith()` 朝向对齐）、
    `Line3D`（point + 单位 direction）、`Circle3D`（center + 单位 normal + radius）、
    `RoiBox`（min/max/valid/is2D，`fromMinMax()`、`contains()`/`contains2D()`；`is2D=true` 时仅约束 x/y）。
  - **`DataType` 枚举**：PointCloud/Image/Pose/Scalar/String/Plane/Line/Circle/Roi —— 端口类型校验的唯一依据。
  - **variant 端口值机制**：`DataVariant = std::variant<std::monostate, PointCloud, Image,
    Eigen::Matrix4d, double, std::string, Plane3D, Line3D, Circle3D, RoiBox>`；
    `PortValue{ DataType type; DataVariant data; }` —— 类型标签 + 数据。
    `isValid()`（非 monostate）、`get<T>()`（类型不符返回 nullptr）。
  - `dataTypeName(DataType)`：同时被 ui/FlowModel 用作 QtNodes 端口类型 id（字符串相等才能连线）。
  - `makePortValue<T>(DataType, T)`：模块写输出时的便捷构造。
- **被谁用**：全工程。新增数据类型必须改这里（见 §8 指引）。

### 2.2 `src/core/ModuleBase.h` — 模块基类 + 执行上下文 + 参数机制（纯头文件）

- **`PortDecl{ name, type, optional }`**：端口声明；`optional=true` 的输入允许未连接（Display3D 的叠加输入、拟合/测量的 roi 输入）。
- **`ModuleContext`**：execute 的入参，由 Engine 构造。三个能力：
  `input(port)/hasInput(port)`（读上游缓存值）、`setOutput(port, PortValue)`（写输出，引擎缓存给下游）、`log(msg)`（追加到本模块日志表）。
- **ParamDesc 参数机制**（M2 引入，替代各模块特判）：
  - `ParamType{Double, Int, Bool, String, FilePath}`，`ParamValue = std::variant<double,int,bool,std::string>`（FilePath 底层存 string）。
  - 模块构造时 `declareParam({name, type, default, min, max})`（public，CloudUtils 的 `declareRoiParams` 靠它批量声明）。
  - `getParam/getDouble/getInt/getBool/getString`（局部拷贝后 get_if，避免对右值取址）、`setParam`（校名+校类型；int 参数允许 double 写入自动取整；FilePath 按 String 校验）。
  - 通用 `saveParams()/loadParams(QJsonObject)`：遍历声明表序列化/回填，子类一般不用重写。
- **`ModuleBase`** 虚接口：`typeId()`（注册表键，如 `"Fit.Plane"`）、`name()/setName()`（实例显示名）、
  `inputPorts()/outputPorts()`、`execute(ModuleContext&)`。
- **被谁用**：所有模块、Process、Engine、PropertyPanel、tests。

### 2.3 `src/core/ModuleRegistry.h` — 类型注册表（纯头文件，单例）

- `ModuleInfo{typeId, category, displayName, factory}`；`ModuleRegistry::instance()`。
- `reg<T>(typeId, category, displayName)`：模板注册（factory = `make_unique<T>`）。
- `create(typeId)` → ModulePtr；`all()`；`byCategory()`（工具箱分组数据源）。
- 注册入口在 `src/modules/Modules.cpp::registerBuiltinModules()`（幂等，main/测试启动时调用）。

### 2.4 `src/core/Process.h/.cpp` — 模块有向图（真实执行图）

- **数据结构**：`ProcessNode{id, typeId, ModulePtr, x, y}`（x/y 仅用于 Solution 恢复布局）；
  `ProcessLink{fromNode, fromPort, toNode, toPort}`（连线 = 订阅）。
- **图构建**：
  - `addNode(typeId)`（注册表创建实例，id 自增）/ `addNodeWithId(typeId, id)`（Solution 加载保 id）。
  - `removeNode`：连带删除所有相关连线。
  - **`canConnect` 五项校验**（UI 的 connectionPossible 也走这里）：非自连 → 节点存在 →
    fromPort 是上游输出端口、toPort 是下游输入端口 → **数据类型一致** → **输入端口单订阅**
    → **不成环**（`reachable()` BFS：若 toNode 已可达 fromNode 则新边成环）。错误原因经 `err` 输出。
  - `addLink`（内部先 canConnect）、`removeLink`、`clear`。
- **`topologicalOrder`**：Kahn 算法；出度表 + 队列；结果数 ≠ 节点数则判定有环，返回空表 + err。
- **输出缓存**：`outputCache_`（key = {nodeId, port}），`clearOutputCache/setCachedOutput/
  hasCachedOutput/cachedOutput`。一次 runOnce 开始时清空；Engine 写、下游读、UI 结果表也读。
- **被谁用**：Engine、Solution、FlowModel、MainWindow、tests。

### 2.5 `src/core/Solution.h/.cpp` — 方案 JSON 保存/加载

- 持有 `std::unique_ptr<Process>`（`process()` 访问）；`save(path, err)` / `load(path, err)`。
- **JSON schema**（QJsonObject，无第三方库）：
  ```json
  {
    "version": 1,
    "modules": [
      { "id": 1, "type": "Acquisition.LoadPly", "name": "加载PLY点云",
        "x": 0.0, "y": 0.0, "params": { "filePath": "D:/a.ply" } }
    ],
    "links": [
      { "fromNode": 1, "fromPort": "cloud", "toNode": 2, "toPort": "cloud" }
    ]
  }
  ```
  `params` 内容由 ModuleBase 通用 saveParams 生成（遍历 ParamDesc）。
- load 的关键细节：先在临时 Process 上重建（`addNodeWithId` 保持文件 id → 连线表无需重映射），
  全部成功才 `*process_ = std::move(rebuilt)`；任何一步失败（未知类型/id 冲突/连线非法）整体失败。
- UI 侧加载后由 `FlowModel::resetFromProcess()`（emit modelReset）让场景重建。

### 2.6 `src/core/Engine.h/.cpp` — 执行引擎（同步、Qt-free）

- `ModuleRunRecord{nodeId, name, success, elapsedMs, logs}`；`RunResult{ok, error, records}`。
- `Engine::runOnce(Process&, ProgressCallback = nullptr)`：
  1. `topologicalOrder`（有环 → `result.error` 直接返回）；
  2. `clearOutputCache`；
  3. 按序每节点：从 links + cachedOutput 组 inputs → 构造 ModuleContext → try/catch 调
     `execute`（std::exception/unknown 都兜底记日志）→ chrono 记 `elapsedMs` →
     outputs 写入缓存 → `records.push_back(record)` + `onModule(record)`（进度回调，M3 加，
     供 EngineRunner 逐模块推信号）。
- 设计约束：单模块失败不中断，下游因输入缺失自行失败；全程不碰 Qt，worker 线程/无头皆可跑。

## 3. camera 层（src/camera/）— RVC SDK 封装（M1 地基）

### `src/camera/RvcCamera.h/.cpp`

- `RvcSystemGuard`：`RVC::SystemInit/SystemShutdown` 的 RAII 引用计数（进程级配对调用）。
- `RvcCamera`：`listDevices()`（SystemListDevices 两段式探测）、`openBySn/close/isOpen`
  （M0 骨架：SN 登记表 `g_snRegistry` 防 SDK 允许同一相机重复 Open 的陷阱）、
  `pointMapToPointCloud()`（PointMap → PCL，保留 W×H 组织结构、is_dense=false、数据单位米）。
- 头注释记录了 RVC 四条已知陷阱（CaptureOptions 先 Load 再改、SN 查重、内存米/存盘毫米、Save 不支持中文路径）。
- 当前不被任何运行链路调用（M1 才接采集模块）；链接 `RVC::RVC`（cmake/FindRVC.cmake）。

### 4.2 共享工具

- **`src/modules/CloudUtils.h`**（header-only，include `core/ModuleBase.h` + pcl filter）：
  - `removeNaNIfNeeded(cloud)`：is_dense=false 时 removeNaNFromPointCloud（RVC 点云有无效点）。
  - `cropByRoi(cloud, RoiBox)`：逐点 contains 过滤；roi.valid=false 原样返回。
  - `declareRoiParams(module)`：声明 `roiEnabled` + `roiIs2D` + `roiXmin..roiZmax` 九个参数（拟合/测量模块构造时调用）。
  - `resolveRoi(ctx, module)`：ROI 生效优先级——**连线 roi 端口 > 自有 roiXxx 参数（roiEnabled=true）> 不裁（valid=false）**。
  - `readRoiFromParams(module)`：从参数组读取完整 RoiBox（含 is2D），供 ROI 编辑弹窗初始化。
  - `writeRoiToParams(module, RoiBox)`：3D 框选结果 / ROI 弹窗确认回写 roiXxx 参数组并启用（含 `roiIs2D`）。
- **`src/modules/fit/FitUtils.h`**：`RansacResult` + `ransacFit(cloud, modelType, distThresh, maxIter, rMin, rMax)`——
  去 NaN → 有效点 <10 判失败 → pcl::SACSegmentation（SAC_RANSAC、optimizeCoefficients、可选 radiusLimits）
  → **内点 < max(50, 输入 3%) 判失败** → ExtractIndices 取内点云。三个拟合模块共用。
- **`src/modules/Modules.h/.cpp`**：`registerBuiltinModules()` 把 13 个模块按分类
  （采集/预处理/拟合/测量/显示/IO）注册进 ModuleRegistry；幂等。

### 4.3 拟合/测量模块强制 ROI

- FitCircle / FitLine / FitPlane / PointToPlaneDistance / BoundingBoxMeasure 的 `execute` 要求 ROI 已设置：
  - 优先使用连线 `roi` 端口输入；
  - 未连线时必须启用自有 `roiEnabled=true` 且范围有效；
  - 否则直接失败并提示「ROI not set」。
- `RoiBox.is2D=true` 时仅按 x/y 裁剪，z 方向视为无限，适合圆拟合等平面内特征提取。

### 4.4 值得注意的实现点

- `LoadPlyModule.cpp::loadPlyAsPointXYZ`：**不用** `pcl::io::loadPLYFile<PointXYZ>`（PCL 1.13 对二进制
  double 型 x/y/z 字段不转换、输出全零），改读 `PCLPointCloud2` 后按字段原生类型（float/double）手动转；
  全零点云判失败。
- `SavePlyModule.cpp`：路径含非 ASCII 时先存 `temp_directory_path()/rvc_saveply_tmp.ply` 再
  `std::filesystem::copy_file`（u8path）移动——RVC 中文路径陷阱的同款规避。
- `Display3DModule`：静态 `DisplayCallback(viewport名, cloud, overlays)` 由 UI 注入（进程级单回调，
  路由按名分发在 ViewportManager）；无回调时仅记日志不失败（无头友好）。
- `FitPlaneModule`：拟合后法线单位化并 `alignWith(+Z)` 统一朝向，保证下游测量语义稳定。
- `PlaneToPlaneModule`：夹角用法线点积绝对值（无向角）；近平行时先 alignWith 再 `|d1-d2|` 得间距。

## 5. ui 层（src/ui/）— Qt6 Widgets + 自编译 VTK

### 5.1 `src/ui/FlowModel.h/.cpp` — 画布 ↔ core::Process 双向同步

- 继承 `QtNodes::AbstractGraphModel`（QtNodes v3 Model-View 架构），持 `Process&`（不拥有）。
- **id 与端口映射**：QtNodes `NodeId` 直接等于 Process 节点 id；`PortIndex` = 模块端口声明
  向量下标（`portName/portIndex` 互转）；`ConnectionId` ↔ `ProcessLink` 由 `toConnectionId` 转换。
- **同步方向**：`addNode(typeId)` → `process_.addNode` + emit nodeCreated（场景自动建图元）；
  `addConnection` → `process_.addLink`；`connectionPossible` → `process_.canConnect`
  （类型/单订阅/成环校验全部复用 core）；`deleteNode/deleteConnection` 同理。
  `nodeData(Position)` 读写 Process 节点 x/y；`resetFromProcess()` emit modelReset（Solution 加载后整体重建）。
- **两个关键坑（注释里也写了）**：`NodeRole::Size` 必须可读写存储（`nodeSizes_` map），否则节点
  boundingRect 为 0 不渲染；`NodeRole::Style` 必须返回 `StyleCollection::nodeStyle().toJson()
  .toVariantMap()`（QJsonObject 变体无法被 QJsonDocument::fromVariant 转换，会导致节点全黑无文字）。

### 5.2 `src/ui/FlowView.h/.cpp` — 画布视图（拖放）

- 继承 `QtNodes::GraphicsView`；`dragEnter/dragMove/drop` 识别 mime `application/x-rvc-module`
  → `model_.addNode(typeId)` 在落点实例化 + setNodeData(Position)。

### 5.3 `src/ui/Toolbox.h/.cpp` — 可折叠分类工具箱 + 模块搜索

- **结构**：`QLineEdit` 搜索框 + `QTreeWidget` 分类树；分类为顶层节点（粗体、ink-secondary），
  模块为叶子节点（UserRole 存 typeId）。叶子可拖拽，分类节点不可拖拽。
- **`reload()`**：从 `ModuleRegistry::byCategory()` 重建树并 `expandAll()`。
- **搜索过滤** `applyFilter(key)`：隐藏不匹配叶子；无匹配子项时隐藏整棵分类；有匹配时自动展开分类。
  快捷键 `Ctrl+F` 聚焦搜索框（MainWindow 绑定）。
- **实例化**：重写 `startDrag/mimeData()` 产出 `application/x-rvc-module` mime；双击（或未来回车）
  发 `moduleActivated(typeId)`，MainWindow 在画布中心实例化模块。
- **可折叠**：QTreeWidget 原生 expand/collapse 箭头；分类节点双击仅实例化叶子，不折叠。

### 5.4 `src/ui/PropertyPanel.h/.cpp` — 通用参数面板 + ROI 设置入口

- `setModule(ModuleBase*)` → `rebuild()`：按 `paramDescs()` 逐条 `buildEditor`：
  Double→QDoubleSpinBox（6 位小数）、Int→QSpinBox、Bool→QCheckBox、String→QLineEdit、
  FilePath→QLineEdit + 「…」浏览按钮；编辑信号直接 `module->setParam`（GUI 线程，无需加锁）。
- **ROI 设置按钮**：模块声明了 `roiEnabled` 参数组时，在参数表末尾追加「ROI」行 +
  「设置 ROI…」按钮；点击后通过 `currentCloudProvider`（MainWindow 注入，取主视窗当前点云）
  获取预览点云，弹出 `RoiEditDialog`。
- 文件对话框父窗口固定为主窗口（构造传入），避免 alien widget 无 HWND 导致原生对话框异常。

### 5.5 `src/ui/Roi2DView.h/.cpp` — 2D ROI 编辑视图（状态机交互）

- 点云 XY 投影散点绘制（自动按包围盒缩放/居中，Y 轴翻转使屏幕上方对应较大的 world Y）。
- **交互状态机**：
  - 空白处左键拖拽 → `Draw`：画新矩形；
  - 矩形内部左键拖拽 → `Move`：整体移动矩形；
  - 矩形边缘/角左键拖拽（±6px 容差）→ `ResizeXxx`：调整对应边或角。
- **视图导航**：滚轮以鼠标为中心缩放；右键拖拽平移视图。
- 矩形 8 个 handle（4 边中点 + 4 角）常显，悬停自动切换光标形状。
- 交互结束发 `roiChanged(RoiBox)`；`setRoi()` 可外部设置并显示当前矩形。

### 5.6 `src/ui/RoiEditDialog.h/.cpp` — ROI 设置弹窗

- 从 PropertyPanel「设置 ROI…」打开；支持 **3D 盒体** / **2D 矩形（XY）** 两种模式。
- 3D 模式：内嵌 `Viewport3D`，复用其框选 ROI 交互；2D 模式：内嵌 `Roi2DView`。
- 底部 6 个 `QDoubleSpinBox`（x/y/z min/max）与拖拽实时同步；2D 模式下 z 参数禁用并固定 ±1e9。
- 确定：`writeRoiToParams(*module, roi)` 写回模块并启用 `roiEnabled`；取消不修改。

### 5.7 `src/ui/Viewport3D.h/.cpp` — 交互式 3D 视口 + vtkBoxWidget2 ROI 编辑

- **渲染**：`QVTKOpenGLNativeWidget + vtkGenericOpenGLRenderWindow +
  pcl::visualization::PCLVisualizer(renderer, renderWindow, "viewport3d", false)`；
  `vtkInteractorStyleTrackballCamera`（旋转/缩放/平移）；`addCoordinateSystem(0.1)`（米）。
  main.cpp 在 QApplication 前设置 `QSurfaceFormat::setDefaultFormat(QVTKOpenGLNativeWidget::defaultFormat())`。
- **工具条**：重置视角（viewer_->resetCamera）、编辑ROI（checkable，开关 vtkBoxWidget2）、点大小
  （PCL_VISUALIZER_POINT_SIZE）。
- **几何叠加**（drawOverlays，与数据同帧刷新，旧 actor 按 `overlayShapeIds_` 清除）：
  平面=按点云包围盒尺度的黄色网格线、直线=青色延长线、圆=64 段品红折线+圆心球。
- **ROI 编辑链路**：按钮 toggled → `setRoiEditing(on)` → 若当前无 ROI 则以点云包围盒
  `boxRep_->PlaceWidget(bounds)` 初始化 → `boxWidget_->On()`；用户拖 7 个 handle（6 面 + 中心）
  或中键/右键整体调整 → `InteractionEvent` → `onBoxWidgetInteraction()` 从 transform 反推
  min/max → `currentRoi_` → `roiPickedCallback(roi)`。
- **双向同步**：外部 `setRoi(roi)` 时计算初始 bounds 到目标 ROI 的平移+缩放 transform 并
  `boxRep_->SetTransform(t)`；`updatingBoxWidget_` 标志防止 setRoi → box widget → callback 循环。
- 旋转已禁用（`RotationEnabledOff`），保证 ROI 始终轴对齐。

### 5.8 `src/ui/ViewportManager.h/.cpp` — 多视窗管理 + 显示路由

- `ensureViewport(name)`：不存在则建 QDockWidget（Closable/Movable/Floatable）+ Viewport3D，
  `addDockWidget(Right)` 并与既有视窗 `tabifyDockWidget` 后 `raise()`；发 `viewportDockAdded`
  （MainWindow 把 toggleViewAction 挂进「窗口」菜单）。
- `addViewport()`：「窗口」菜单入口，按 视窗2/视窗3… 命名。
- `routeDisplay(viewport名, cloud, overlays)`：Display3D 回调的终点（空名字按"主视窗"）。
- `setRoiPickedHandler`：给每个视窗统一注入框选回调。

### 5.9 `src/ui/EngineRunner.h/.cpp` — 异步执行封装

- `start(Process&)`：`std::atomic<bool> running_` 防并发（已运行返回 false）；
  `QThread::create` 一次性 worker（finished → deleteLater）；worker 内跑
  `Engine::runOnce(process, onModule)`，onModule → `Q_EMIT moduleFinished`，结束
  `Q_EMIT runFinished(result, totalMs)`；`reset()` 由 GUI 在 runFinished 后调用。
- 构造时 `qRegisterMetaType<ModuleRunRecord/RunResult>`（跨线程排队投递必需）。
- 生命周期约定：Process 引用由 MainWindow 保证（运行中禁编辑图、禁并发）；「停止」按钮未实现。

### 5.10 `src/ui/MainWindow.h/.cpp` — 主窗口（无边框 + 内部 QMainWindow + 异步调度）

- **窗口架构**：`MainWindow` 自身继承 `QWidget` 并设 `Qt::FramelessWindowHint`；顶部是自定义暗色
  标题栏（`#titleBar`），含标题文字、最小化/最大化/关闭按钮；标题栏拖动、`WM_NCHITTEST` 原生事件、
  边框 8px 缩放区均保留原生窗口行为。内部放一个 `QMainWindow inner_` 真正承载菜单/工具栏/Dock/中央画布，
  避免无边框窗口与 QMainWindow 自带标题栏冲突。
- **布局**：`inner_` 中央 = FlowView；Dock：工具箱（左）、属性（右）、日志/结果 tab（下）、3D 视窗
  （右，ViewportManager 管理，可 tab 折叠）。「窗口」菜单 = 各 Dock toggleViewAction +
  「添加3D视窗」+ 动态视窗的 toggle（viewportDockAdded 信号挂入）。
- **场景生命周期**：`BasicGraphicsScene` 由 `std::unique_ptr<QtNodes::BasicGraphicsScene> scene_` 持有，
  且 `scene_` 在 `MainWindow.h` 中声明于 `inner_` 之前；析构时 `inner_`（含 FlowView）先被销毁，
  `scene_` 在 `MainWindow` 最后销毁，避免 QtNodes view 析构访问已释放 scene 导致段错误。
- **显示回调注入**（构造函数）：Display3D 静态回调可能在 worker 线程触发 →
  `QMetaObject::invokeMethod(this, lambda, Qt::QueuedConnection)` → `viewportManager_->routeDisplay`。
- **异步运行**：`runOnce`（start 失败→状态栏提示；成功→禁用按钮）→ `onModuleFinished`
  （逐模块日志+耗时）→ `onRunFinished`（reset、恢复按钮、总耗时、`fillResultsTable`
  遍历 Process 节点把 Scalar 输出填结果表）。
- **画布选中**：scene selectionChanged → `selectedModule_` + PropertyPanel 刷新。
- **框选回写** `onRoiPicked(RoiBox)`：未选中模块→状态栏提示；选中 BoxRoiModule→写 xmin..zmax；
  其他→`writeRoiToParams`（无 roiXxx 参数组返回 false→状态栏提示）；成功则刷新属性面板。
- `loadDemoFlow(ply)`（--demo 用）：程序化建 6 节点流水线（含 ROI 订阅连线 roi→fit），
  选中拟合节点并 fitInView，然后 runOnce。
- 方案打开/保存：QFileDialog + Solution::load/save + `flowModel_->resetFromProcess()`。
- 日志分级着色：`appendLog(line, LogLevel)`（QPlainTextEdit::appendHtml + token 颜色），
  Normal=ink-secondary、Success=success、Warning=warning、Error=danger；「运行」按钮经
  `widgetForAction` 设 `class="primary"` 动态属性（QSS 按属性选择器上琥珀填充）。

### 5.11 `src/ui/Theme.h/.cpp` — 主题系统（Foundation 设计系统，换肤扩展点）

- **token 集中定义**：`Theme::Color::*`（表面四级 / ink 三级 / border / 琥珀 accent 四态 /
  语义色四组）、`Theme::Space`、`Theme::Radius`。全工程 QSS 只允许引用这些常量，禁裸 hex。

  fallback 链探测可用族（Geist→Inter→Segoe UI→system-ui；JetBrains Mono→Fira Code→Consolas）。
- **`appStyleSheet()`**：token 拼接的全局 QSS（`.arg` 注入），覆盖 QMainWindow/QDockWidget/
  QMenu(Bar)/QToolBar/QPushButton 三层级（`[class="primary"]` 动态属性选 Primary）/
  QToolButton(Ghost + primary 变体)/输入控件（focus=accent 边框）/QCheckBox/QListWidget/
  QTabWidget(accent 下划线)/QTableWidget/QPlainTextEdit(mono)/QStatusBar/QToolTip/细滚动条/

- **`applyQtNodesStyle()`**：QtNodes v3 风格 JSON（NodeStyle::setNodeStyle /
  ConnectionStyle::setConnectionStyle / GraphicsViewStyle::setStyle）——节点底 surface-1

## 8. 构建系统

### 8.1 `CMakeLists.txt`（顶层）
