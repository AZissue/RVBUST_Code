# 主程序新旧界面并行接入

2026-10-20。正常运行 `main.py`，启动小窗左侧保留三个现有入口，下方增加三个「新版工作区 · 试用」入口。两组共用右侧设备选择、自动 IP、连接及底部日志摘要。

## 接入方式

界面版本通过 `selected_presentation()` / `set_presentation()` 传递，业务模式仍是 `multi_cam`、`mobile_chain`、`turntable`。相机 ID、会话格式、算法坐标、SDK 及后台任务池没有新增第二套。

新版在 `src/ui_v2/industrial_presentation.py` 装配正式控件，保留同一工作区对象和动作信号。经典布局完整保留；切换时恢复原容器、索引、尺寸约束和渲染组件。不是把原型的模拟采集控制器嵌入正式程序。

## 功能映射

| 模式 | 新版呈现 | 正式业务入口 |
|---|---|---|
| 多相机外参标定 | 左侧设备、标定/扫描控制；中央独立相机网格；右侧3D | 同步/异步拍摄、单卡片预览/拍摄/检测、检测方法、参考相机、外参计算、质量门禁、锁定/回退、扫描、批量采集和会话保存均沿用 MultiCamWorkspace 与 BackendBridge |
| 移动链式拼接 | 左侧采集操作及机位时间线、大3D、右上2D与编码圆、评估卡、底部日志 | 取景、拍摄机位后自动检测/配准、失败帧显示、撤销、重拍、删除、闭环优化、选中机位回放、离线加载及保存沿用 MobileChainWorkflow |
| 转台拼接 | 左侧原有标定及采集控制、大3D、右上2D与编码圆、底部日志 | frame0/frame1采集与标定、间隔、自动/单步采集、实时拼接、清空、导出点云、保存/恢复会话沿用原 TurntableWorkspace 与共享后台 runner |

`bindings.py` 的13项多相机、9项移动拼接及3项主窗口动作不重新绑定。转台仍复用其正式控件、会话、内部动作和保存信号；本阶段没有将转台业务全部拆成独立 presenter。

## 显示组件

- 原型的轨迹球、GPU点缓冲/交互LOD、软件兼容预览、编码圆分类与详情面板提升到 `ui_common/industrial_scene`；原型保留转发导入，避免两份算法漂移。
- `IndustrialViewer` 适配正式 `PointCloudView` 接口：接收原始 Open3D 点云，原始数组不下采样，显示缓存按流畅/均衡/细节预算处理。相机、拼接结果、原色/高度/统一颜色、点大小、视角、网格/坐标轴和最大化均可操作。
- 经典入口继续使用原渲染器；新版切换到新渲染器时回放当前显示数据，退役渲染器在显示任务结束后回收。
- 新版2D编码圆：绿色为2D检出且有有效3D坐标，红色为当前/参考帧共有可配对圆，黄色为仅2D。配准明确失败时不显示可用红圈；正式链式结果没有逐ID内点列表时不将共有圆描述为RANSAC内点。
- 当前编码圆详情使用相机坐标。尚未在本轮把移动链所有历史标记转换到世界坐标并累积绘制，因此不显示该统计，避免把相机坐标圆错误画到拼接坐标中。
- 新版运行日志停靠底部，可拖动分隔条、筛选、复制、导出；原入口保留原日志行为，共用同一日志记录。

## 生命周期

正在处理后台任务或转台自动采集时不允许打开设备切换入口。同模式、同一组设备只切换界面呈现，不重连、不丢弃会话及未保存标记。改变模式/设备时才确认未保存数据；重新连接前停止移动取景和多相机卡片预览，随后由已有 CameraManager 处理设备。连接失败保留原界面版本和未保存标记。连接完成后保留后端已恢复的阶段状态，避免自动恢复的外参锁定被界面初始化重置。新旧入口都不另行初始化SDK。

## 验证及边界

- `test_ui_industrial.py`：六入口、25项动作端口、反复切换不重复接线、真实按钮信号、门禁、机位评估、转台会话身份与保存信号、渲染数据及底部日志、编码圆详情。
- `test_ui_industrial_gpu.py`：原生GPU三模式、拖动不重复上传、最大化/恢复、兼容回退、切回经典、原始点云不变。使用显式 TEST 数据，禁止SDK初始化。
- 原有架构、入口、日志、标记、原型显示与状态回归继续运行。

上述验证不替代实体相机、实测标定/拼接精度、自动采集长时间运行及客户机打包验收。试用入口暂时与经典入口并存，不在本阶段删除原界面。
