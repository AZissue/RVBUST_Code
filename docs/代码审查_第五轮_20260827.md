## 四、P0 / P1 问题清单

### P0-1｜48MB 二进制入库，clone 体积污染（新增，工程化+主代理双重确认）

- **位置**：仓库根 `叶片拼接.ply`（blob `3de6660f`，48,993,519 B）；`.gitignore` 无 `*.ply` 规则
- **问题**：08aad7a 夹带该 PLY 入库，**当前 HEAD 树仍在**（`git ls-tree -r HEAD` 可见，`git check-ignore` exit=1）；历史另有 `test_data/0.ply`（17.8MB，a76c0ca 引入已删但仍占历史）。`.git` 总 62MB，每份 clone 多传 ~50MB 现场演示数据
- **影响**：仓库体积失控；后续 `git add .` 再生成 PLY 会继续入库
- **修复**：`git rm --cached 叶片拼接.ply` + `.gitignore` 追加 `/*.ply`；历史清洗（git filter-repo 移除两枚大 blob）按需排期

### P1-c1｜chain_stitcher.py:346 级联重配准重复边 → BA 双权重（第四轮 P1 遗留，双代理探针实证）

- **问题**：`remove_node` 重配准循环 `reachable.add(sid)` 只加单节点、**不做 BFS 闭包**；下游节点经幸存原边已"事实上连通"仍被判不可达 → 再次 `_try_register` → `self.edges` 与 `_adjacency` 各追加重复边
- **探针实测**（主代理 repro_round5_dup_edges.py + core 子代理 mcc_probe_round5.py E 节，链 s1-s2-s3-s4 删 s2）：
  ```
  edges after: [('s4','s3'), ('s3','s1'), ('s4','s3')]   # 重复
  邻接表 s3 -> ['s4','s1','s4']；s4 -> ['s3','s3']
  ```
- **影响**：BA 残差该约束计两遍（权重翻倍）；get_error_report/get_station_evaluations 重复列边；时间线重建失真。几何/T_world 仍正确，**静默污染**
- **修复（一行级）**：重配准成功后重算 `_compute_reachable()`（BFS 闭包）；或 `self.edges.append` 前查重；`pose_graph.add_edge` 对 (from,to) 已存在时跳过

### P1-c2｜turntable_calibrator.py:180 stitch_pointclouds 原地 transform → 重复拼接数据损坏（本轮新发现，探针实证）

- **问题**：`pcd_t = pcd.transform(T)` —— o3d `transform()` **原地修改并返回 self**，传入的 pcd 列表被永久变换；第 2 次 stitch 对已变换帧再乘一次 -i·θ
- **探针实测**：同一 `[pcd0,pcd1]` 两次 stitch，第 2 次输出 `np.allclose` False（pcd1 被二次旋转）
- **影响**：turntable_workspace.py:716-718 **自动实时拼接每采一帧即调 `session.stitch()`** → 3D 视图逐步错乱；手动多次"拼接并显示"同样出错。**静默产出错误点云**
- **修复**：`pcd_t = o3d.geometry.PointCloud(pcd); pcd_t.transform(T)`（复制后再变换）

### P1-c3｜fixed_multi_cam_workflow.py:92-110 + calibration_engine.py:53-57 换参考重标定后 reference_id 陈旧 → 落盘就错（第四轮 P2 遗留，影响升级）

- **问题**：`start_calibration` 只写 `self._reference_id`，从不调 `calibration_engine.set_reference()`；`_ensure_reference` 仅 None 时设置；ui_v2 全链路零 set_reference 调用（仅旧 src/ui 有）
- **探针实测**（mcc_probe_refid3.py 走真实 calibrate 路径）：重标定(camB)后 `engine.reference_id=camA`（陈旧）→ **保存 JSON reference_id=camA（应为 camB）** → 重新加载后工作流参考回退旧值 → 坐标系原点静默漂移
- **修复**：`start_calibration` 内调 `self.calibration_engine.set_reference(reference_id)`；`reset()` 重置 `engine.reference_id = None`

### P1-u1｜cam_id 映射错位：bridge ordered 连接 vs set_mode raw 顺序（第四轮 P1-3 变异复发，探针实测）

- **位置**：`backend_bridge.py:208-225`（ordered_devices = real + test 连接）vs `main.py:67-69`（set_mode 传 `launcher.selected_devices()` **raw 顺序**）vs `multi_cam_workspace.py:445-462`（按列表**位置**分配 `cam{i}`）
- **探针实测**（probe_v5b.py A1~A5）：选 `[TEST-A, X2, X1]` → bridge `cam0=X2/cam1=X1/cam2=TEST-A`，网格 `cam0=TEST-A/cam1=X2/cam2=X1`；**标题 TEST-A 的卡片收到 X2 的帧**；参考相机 combo 无 cam0 项；选 "X1 (SN1)" 发出 cam2 指向虚拟设备 TEST-A → **标定链打错相机**
- **修复（可抄）**：bridge 暴露 `get_ordered_devices(devices)`（real-first 排序），main.py:69 与 main_window.py:410 的 set_mode 均改用之；或更彻底：`set_devices` 按 `camera_manager.camera_ids`（连接顺序）对齐

### P1-u2｜设备管理重开后旧回调覆盖新选择（新增，探针实测 FAIL）

### P1-u3｜模式 C 工具栏"保存会话"误路由到 mobile 分支（新增，探针实测 FAIL）
