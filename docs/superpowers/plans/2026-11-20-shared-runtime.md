# 公共运行机制改造

按用户确认的顺序实施三个步骤；保留模式专用业务和现有 DB/会话格式。

1. 实时预览：抽取公共采集线程，移动取景保持持续采集，多相机卡片每轮后台串行采集、不重入。回填验证线程身份及活动相机；暂停、断线、关闭丢弃旧结果，并保留在飞线程引用。
   - 回归：慢采集期间 GUI 事件仍能处理；两台相机均回填；暂停后不回填；停预览保留末帧；拍摄暂停与恢复。
2. 后台任务：抽取公共任务启动/回填/退出工具；桥接器保留项目归档包装，后处理保留进度与操作状态；都使用 GUI QObject 投递，线程结束后 join 再释放闭包。转台回退也接入。
   - 回归：工作和回调线程不同、异常仍交付、回调异常不妨碍收尾、关闭后不修改界面、任务结束后恢复操作。
3. 失败提示：公共非阻塞弹窗及建议入口，拼接保留专项建议与设置跳转；后处理主动处理及导出失败统一弹窗，自动加载/识别只记日志。避免重复弹窗，避免将识别类型误称为标定板。
   - 回归：主动失败显示原因和建议；自动任务不弹窗；失败不发布结果且按钮恢复。

按步骤先增加行为测试、确认失败，再实现和验证。交付使用 PATCH 升号，检查差异，仅提交本次文件并推送。
