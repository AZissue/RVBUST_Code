# 后台标记识别

新版工业工作区使用独立的后台识别队列。采集先完成原始 PLY/PNG 入库及点云预览，再提交识别；识别过程不弹出加载框，不占用前台任务门禁。多相机卡片的点云读取也在工作线程完成。

## 执行与查看

- 线程池最多同时处理两帧，每个任务创建独立检测器，复制当前识别类型、编码圆参数和标定板规格/Gamma，避免共享检测器状态竞争。
- 多相机、转台沿用当前工作区的识别类型，移动工作区沿用检测器配置。识别只使用已保存的有序点云和对应图像，不使用显示采样点云，不持有采集 SDK 句柄。
- PyRVC 调用仍遵守 SDK 全局锁；线程池并行不表示允许对同一设备并发调用 SDK。
- DB“数据属性”显示等待、识别中、完成或失败，以及标记数量、有效三维标记、标定板规格和拟合 RMS。选择原始帧后，现有图像标记检查器可查看与比较圆心和编号。
- 识别完成只刷新标注和元数据，不重新上传已加载的点云，也不重置视角。失败可在 DB 右键“重新识别标记物”；后台零检出不写调试图像。

## 缓存与生命周期

缓存绑定工作区、项目目录、帧 UID、原始数据版本和识别配置指纹。删除、重拍、切换项目或改变识别配置后，旧任务不能覆盖新数据。“已完成但检出 0 个”也是有效缓存，不在每次拼接时重试。

识别结果保存在 DB 索引的可选顶层 `recognition` 中，保留 schema 1 的原始记录结构；旧程序可忽略缓存读取原始数据，新程序可打开旧索引。缓存包含全量 2D/3D 标记，以及标定板位姿、规格和 RMS。结果随用户显式保存的会话一起保存；不会自动写正式会话。载入未完成的缓存时重新排队。

移动拼接仅等待输入帧的识别结果，然后直接复用缓存；转台仅等待当前序列的结果。等待期间输入改变则取消本次继续操作。固定多相机已有外参，其扫描拼接不依赖标记识别，因此无需等待扫描帧的识别。

关闭时先停止预览，再停止识别调度并等待在飞识别结束，随后释放 SDK 和项目文件。检测异常与“未检出”分开记录；索引写入失败保留旧数据并停止自动重试。

## 维护入口

- `src/core/frame_recognition.py`：检测器快照、配置指纹、纯结果及帧回填。
- `src/ui_v2/background_recognition.py`：有界队列、优先级、过期结果保护和前台动作续接。
- `src/core/frame_database.py`：缓存提交、回滚、加载与兼容序列化。
- `test_background_recognition.py`：并发、预览优先、缓存、失败、重拍/删除、拼接复用和会话兼容测试。

修改识别计算语义时同步递增配置中的 `algorithm`，使既有缓存失效。离屏与离线数据验证不能替代实体相机持续采集、原生 GPU 流畅度和客户机测试。
