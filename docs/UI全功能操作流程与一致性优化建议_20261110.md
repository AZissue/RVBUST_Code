# MCC 全功能操作流程与一致性优化建议

日期：2026-11-10

核对基线：`MultiCameraCalibration` 分支、提交 `d44705a`、版本 `1.14.3`。

文档性质：全产品 UI/UX 改造建议与验收基线，**不表示相关界面已经修改或能力已经实现**。

## 1. 文档目标

本方案不只优化某一个按钮或某一个工作区，而是覆盖启动、设备、项目、四种采集工作区、离线拼接、数据管理、2D/3D 视图、全部后处理工具、标定结果检查、参数设置、会话管理、实验功能、日志与帮助。

核心目标按优先级排列：

1. **操作位置固定**：所有子功能都遵守同一套界面分区，禁止本步在左侧操作、下一步又转移到右侧或画布浮动栏。
2. **流程连续**：用户始终知道当前对象、当前阶段、下一步动作、任务结果和返回路径。
3. **功能完整**：简化呈现不等于删除高级能力；正式、实验、诊断能力要有清楚边界和固定入口。
4. **业务安全**：保留现有标定与拼接门禁、原始数据保护、显式会话保存、后台任务与设备生命周期约束。
5. **渐进实施**：优先替换呈现和动作组织，不同时重写算法、SDK、会话格式和设备服务。

本方案采用一个明确决策：**左侧只负责数据与导航，中间只负责视图，右侧始终负责当前任务与操作，顶部只保留全局固定动作，底部统一显示状态。**

## 2. 与既有建议的关系

`docs/UI通用操作整合与简化建议_20261022.md` 已识别入口重复、选择语义不清和工具栏分散等问题，其工业视觉保留、动作复用、数据安全和分批实施原则继续有效。

本文根据新的全功能一致性要求，进一步明确：

- 业务操作不再分散到“顶部模式任务区 + 左侧操作条 + 画布分割工具 + 独立参数弹窗”。
- 所有模式的任务操作统一放入**右侧任务操作区**。
- 顶部仅保留跨模块位置不变的项目级动作和视图所属动作。
- 后处理、离线拼接、结果检查和会话管理也使用同一套布局，不再只规范三种采集工作区。
- 若两份文档对操作位置的建议不同，以本文的“固定右侧任务操作区”为后续设计基线；既有文档中的业务安全约束仍然有效。

## 3. 当前问题不仅是按钮多

### 3.1 同类功能使用不同操作模型

- 主工作区通过 `IndustrialRibbon` 平铺项目、设备、采集、拼接、视图和后处理动作。
- 机器人控制面板本身位于工作区左侧，后处理工具则主要位于顶部。
- 多边形分割又在 3D 画布右上提供浮动工具条。
- 下采样、ICP、FPFH、手动配准等使用不同尺寸、不同按钮位置的独立弹窗。
- 离线窗口会隐藏并重新组装 Ribbon，和在线工作区的动作组织不同。

这要求用户每进入一个子功能就重新学习“该看哪里”。

### 3.2 主流程和对象操作混在一起

项目保存、设备连接、当前帧重拍、当前结果导出、点云显示设置、算法执行同时占据高显著性位置。用户难以判断按钮作用于整个项目、当前选中对象，还是仅作用于视图。

### 3.3 选择和输入范围不够直观

DB 树同时存在当前行选择、多选、点云/图像子项勾选和视图叠加。若“查看选择”“参与拼接”“参与处理”“视图可见”共用相似状态，容易造成输入范围误解。

### 3.4 二级工具没有统一闭环

不同工具对“设参—计算—预览—确认—生成结果—继续处理”的组织不同。用户完成一个工具后，不一定知道结果写到了哪里、原始数据是否保留、下一步应返回还是继续。

### 3.5 技术状态多，行动建议不足

连接、标定、质量、过期结果、后台识别、保存状态、日志提示分散在多个区域。仅显示“失败”“未通过”或禁用按钮，不能替代明确的恢复动作。

## 4. 全产品统一信息架构

### 4.1 固定布局

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ A 全局项目栏：品牌 / 工作区 / 项目与保存状态 | 固定项目动作 | 任务 / 日志 / 帮助 │
├───────────────┬──────────────────────────────────────┬───────────────────────┤
│ B 数据导航区  │ C 主视图区                           │ D 任务操作区          │
│ 固定左侧      │ 固定中间                             │ 固定右侧              │
│               │                                      │                       │
│ 项目数据      │ 2D / 3D / 对比视图                   │ 返回与当前位置        │
│ 标定参数      │ 当前对象名称                         │ 当前任务与目标对象    │
│ 原始帧        │ 视图工具（仅视图）                   │ 参数与高级设置        │
│ 拼接结果      │ 结果、候选、标记、预览               │ 质量 / 进度 / 结果    │
│ 后处理分支    │                                      │ 固定主次动作          │
│               │                                      │                       │
├───────────────┴──────────────────────────────────────┴───────────────────────┤
│ E 状态与任务区：当前阶段 | 设备 / 文件状态 | 后台进度 | 下一步或失败恢复       │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 各区域职责

| 区域 | 固定职责 | 可以出现 | 不得出现 |
|---|---|---|---|
| A 全局项目栏 | 项目和应用级动作 | 新建、打开、保存、导出、设备、工作区、任务中心、日志、帮助 | 当前帧重拍、算法参数、多边形分割、某工具专属确认 |
| B 数据导航区 | 找到和选择对象 | 搜索、筛选、树/列表、选择、可见性眼睛、数量与状态标记 | 执行业务处理的按钮、另一套采集面板、算法执行按钮 |
| C 主视图区 | 查看和直接拾取 | 2D/3D、对比、标记、候选结果、视图工具、必要的点/多边形拾取 | 参数表单、项目保存、拼接执行、结果发布、另一套完整工具栏 |
| D 任务操作区 | 完成当前任务 | 当前步骤、输入摘要、参数、主/次动作、进度、结果、恢复动作 | 与当前任务无关的项目树、另一套视图设置 |
| E 状态与任务区 | 全局反馈 | 当前状态、任务进度、简短质量摘要、失败原因入口 | 大段日志、另一套主操作按钮 |

### 4.3 不变量

以下规则应作为自动化和人工验收的硬性检查：

1. 四种在线工作区、离线拼接、后处理、标定检查、会话管理的**业务主操作都在右侧**。
2. 切换步骤只替换右侧面板内容，不把面板移动到左侧、底部或画布上。
3. 主按钮始终位于右侧操作区底部固定位置；执行中在同一位置变为进度或安全停止。
4. 左侧不出现“拍摄、拼接、重拍、删除、处理、发布”等业务执行按钮。
5. 中央视图工具只改变视图或进行直接几何拾取，不承担参数填写和结果发布。
6. 进入二级工具后提供固定“返回上一级”，返回后恢复原输入选择、滚动位置和未提交参数。
7. 专注视图可临时隐藏左右栏，但不得改变任务状态；退出后恢复原布局。
8. 离线模式可以隐藏设备动作，但其余全局动作不得改变相对顺序或跳到另一行。

## 5. 统一操作闭环

除只读查看和明确标注的实时参数外，所有工具统一采用以下路径：

```text
进入功能
  → 选择输入对象
  → 右侧确认目标与参数
  → 中央查看输入或候选预览
  → 右侧执行 / 生成结果
  → 底部显示进度与结果
  → 新结果写入 DB 并被选中
  → 右侧提供下一步：继续处理 / 返回 / 导出
```

### 5.1 每一步必须回答的问题

| 阶段 | 界面必须回答 |
|---|---|
| 进入功能 | 我在哪个工作区、哪个项目、哪个步骤？ |
| 选择输入 | 当前选中什么；多少帧、多少点、是否过期、是否可用？ |
| 设置参数 | 单位和坐标系是什么；哪些是必填；修改后是否需重算？ |
| 执行前 | 将执行什么；是否拍摄设备；是否生成新结果；是否有风险？ |
| 执行中 | 正在做什么；能否安全停止；哪些操作暂时不可用及原因？ |
| 执行后 | 成功还是失败；结果在哪里；原始数据是否保留；下一步是什么？ |
| 返回 | 回到哪里；未提交参数和未保存结果如何处理？ |

### 5.2 主按钮规则

- 同一时刻右侧最多一个品牌红主按钮。
- 主按钮使用动作和目标命名，例如“拍摄标定帧”“计算外参”“生成拼接结果”，避免只有“确定”。
- 不可用主按钮仍保留位置，并在按钮上方显示具体原因和恢复入口。
- 执行后不得无提示地把焦点跳到另一个模块；先展示结果，再由用户选择下一步。
- 自动流程可以串联后台阶段，但必须展示当前阶段、失败停点和分步重试入口。
- 第一批改造优先合并呈现，不强行把现有拍摄、检测、计算合成不可解释的黑盒动作。

### 5.3 返回、取消和关闭

- “返回”用于界面导航，不等于撤销业务结果。
- “取消”用于放弃尚未提交的参数或拾取，不删除已生成的 DB 结果。
- “撤销处理”只针对明确支持的处理历史，不能被理解为通用 Ctrl+Z。
- 系统文件选择器、覆盖确认、永久删除确认可以继续使用模态对话框。
- 参数设置和复杂工具优先作为右侧任务页，不再叠加大中小型参数弹窗。
- 必须完成的后台任务沿用现有等待和关闭门禁，不新增“取消即立即中断 SDK”的虚假承诺。

## 6. 全局项目、启动与设备流程

### 6.1 启动页

建议首屏按用户目标排序：

1. 继续最近项目。
2. 打开项目。
3. 新建扫描项目。
4. 打开本地文件进行离线拼接。
5. 示例与实验功能。

“新建扫描项目”再进入工作区选择和设备连接；已有项目直接恢复到相应工作区，不重复要求选择模式。

### 6.2 设备连接

固定步骤：

```text
选择工作方式 → 搜索设备 → 勾选相机 → 检查数量和网络 → 连接并进入
```

- 左侧/中央显示工作方式与设备列表，右侧固定显示当前工作方式要求、已选数量和“连接并进入”。
- 自动设置 IP 属于选中设备的高级维护动作，放右侧“设备维护”折叠区，并保留明确确认。
- 搜索、刷新、自动 IP、连接状态统一在底部任务区反馈。
- 连接失败保留当前选择，给出单台设备失败原因和重试入口，不返回空白首屏。
- 离线拼接不显示无意义的“0 台设备”，统一显示“本地文件 · mm”。

### 6.3 全局项目栏固定动作

推荐顺序：

```text
项目菜单 | 保存 | 导出 | 工作区/设备 | 任务中心 | 日志 | 帮助
```

- 保存会话和导出点云是两个不同动作，不合并为“拼接并保存”。
- 保存状态始终跟随项目名：未保存、保存中、已保存、保存失败。
- 导出必须显示目标名称；无有效目标时说明原因，不能暗中导出另一项。
- 继续遵守显式项目会话：采集先写私有临时工作区，只有用户主动保存才更新正式快照。
- 不恢复后台外参自动保存/恢复或关闭自动保存，不改变现有回收区和永久删除保护。

## 7. 四种在线工作区

四种工作区共用阶段导航：**准备 → 标定/输入 → 采集 → 拼接/验证 → 完成**。没有标定的模式显示“输入”，不需要的阶段明确跳过，不显示不可用的空页面。

### 7.1 多相机外参标定与扫描

#### 阶段 A：准备与标定设置

右侧内容：

- 已连接相机及缺失状态。
- 参考坐标系相机。
- 星型/链式标定。
- 标定拍摄同步/异步方式。
- 拍摄参数、识别参数入口。
- 主按钮“拍摄标定帧”。

中央显示全部相机 2D 对比；左侧只列出设备、标定数据和历史结果。参考相机变化后继续保留原始帧并使旧外参失效，界面必须明确提示，不静默切换。

#### 阶段 B：识别、计算与质量确认

右侧使用固定三步状态：

```text
拍摄标定帧 → 检测标记 → 计算外参
```

- 每一步仍在右侧原位置执行。
- 主按钮随阶段变为“检测标记”“计算外参”“进入扫描”。
- 质量摘要显示通过数/总数、未通过相机对和建议动作。
- “标定结果与误差”在同一外壳打开检查页。
- 质量未通过时提供“重新拍摄”“重新检测”“查看失败相机对”，不能只禁用扫描。
- 第一阶段保持显式分步；后续可增加“一键引导标定”，但必须保留分步诊断和失败停点。

#### 阶段 C：扫描与拼接

右侧内容：

- 撤板确认和标定有效状态。
- 全部相机 2D 预览开关。
- 主按钮“全部拍扫描”。
- 拼接范围：全部有效扫描帧/明确勾选帧。
- “执行拼接”与“批量采集设置”。
- 最新结果质量、过期状态和“进入后处理”。

批量数量、输出方式等放右侧高级设置。执行批量任务时主按钮位置显示进度和安全停止，不将停止藏入菜单。

### 7.2 单相机移动链式拼接

固定主循环：

```text
开始取景 → 拍摄机位 → 自动识别/匹配/评估 → 查看本步结果 → 移动并拍摄下一机位
```

右侧内容：

- 当前机位编号和本步状态。
- 主按钮“拍摄机位”；后台阶段在原位置显示进度。
- 共视标记、重合比例、本步误差和建议。
- 通过后显示“继续下一机位”提示，但不自动触发物理移动或拍摄。
- 失败时主操作变为“重拍当前机位”，保留已保存原始数据。
- “拼接范围”“执行拼接”“闭环优化”位于后续任务页。

选中历史机位时，右侧变为“机位详情”，提供“重拍机位 N”“删除机位 N”“查看识别详情”。“移除最后原始帧”放入更多操作，不能冒充通用撤销。

闭环优化前后结果在中央对比，右侧确认生成新结果；原始帧和旧结果保留，来源变化后旧结果标记过期。

### 7.3 转台 360° 拼接

#### 标定阶段

```text
拍摄基准帧 → 按提示旋转 → 拍摄旋转帧 → 计算转轴 → 检查标定
```

- 用“基准帧/旋转帧”替代直接暴露 `frame0/frame1`。
- 右侧显示当前物理操作、目标角度和拍摄按钮。
- 标记类型、角度、轴心和识别参数放右侧高级设置。
- “标定结果与误差”及播放变换使用统一检查页。

#### 采集阶段

- 右侧大号显示“当前步 / 总步”和下一目标角度。
- 主按钮“拍摄当前步”；自动采集时同位置显示“停止自动采集”。
- 自动间隔、自动实时拼接、ICP 精修和合并体素放高级设置。
- 停止表示当前在途操作完成后的安全停止，不承诺 SDK 即时中断。
- “新一轮采集”明确保留标定、清理哪些序列数据，并使用确认。
- 拼接结果生成后，右侧固定提供“检查结果”“进入后处理”“导出”。

### 7.4 机器人手眼拼接

右侧保持四步，不在左侧另放控制面板：

1. **手眼矩阵**：导入文件或手动录入，单位、安装方式、矩阵摘要。
2. **机器人位姿**：手动或 CSV，单位、绝对位姿类型、欧拉顺序。
3. **采集与变换**：2D 预览、拍摄并转到基座系、清空采集、帧数。
4. **验证与发布**：戳点记录、戳点门禁、重合度快检、发布 DB、导出。

连续性要求：

- 单位、安装方式、坐标方向始终显示在右侧摘要，不能藏在高级页。
- 矩阵或位姿未就绪时，主按钮说明缺少哪一项并提供跳转。
- 戳点至少三个离面姿态；验证失败时保留采集数据并提供继续记录/重新验证。
- 两帧重合度快检只作参考，不能替代戳点门禁。
- 未验证不得因为界面重排绕过发布和导出门禁。
- 验证通过后，主按钮“发布合并结果到项目”；成功选中 DB 新结果，再提供导出。

## 8. 离线拼接

离线拼接是完整主流程，不是另一个 UI 特例：

```text
选择数据目录 → 检查 PNG/PLY 配对 → 选择配准方式 → 计算与检查 → 生成结果
  → 后处理 → 保存项目 / 导出
```

右侧首页固定包含：

- 数据目录、递归扫描开关和“加载数据”。
- 文件配对数量、失败项和自然排序摘要。
- 两条配准路径：“标记物拼接”“FPFH 几何匹配”。
- 当前输入范围和主执行动作。

两条路径只在算法任务页分化，返回后仍回到同一个离线项目首页。离线窗口不显示设备连接、实时取景和拍摄参数；其他区域位置保持不变。

加载失败逐条列出文件名和原因，已成功数据保留；拼接失败不得静默发布部分结果。源文件只读，正式保存仍默认写入 `sessions`，实验副本写入 `outputs/experiments`。

## 9. 项目数据、选择和视图

### 9.1 三种状态必须分开

| 状态 | 用途 | 推荐控件 |
|---|---|---|
| 当前选择 | 属性查看、重拍、删除、导出目标 | 行选择，右侧显示目标 |
| 处理集合 | 拼接、ICP、FPFH、合并等输入 | 明确复选框和“处理输入 N 项” |
| 视图可见 | 控制 2D/3D 叠加 | 眼睛图标，不影响处理集合 |

执行前右侧再次列出输入名称、顺序、数量和过期状态。只选一项时不能静默回退为“全部帧”。

### 9.2 数据树默认呈现

- 标题统一为“项目数据”，减少对普通用户暴露“DB”术语。
- 默认显示：标定参数、标定帧、扫描帧、拼接结果、后处理结果。
- PLY、2D PNG、中间变换等作为选中对象的详情，不默认全部展开。
- 原始采集统一叫“扫描帧”或“机位”，独立输出叫“拼接结果”，避免两者都叫“拼接帧”。
- 过期、未对齐、识别失败和来源变化使用图标、文字和状态页共同表达，不只依赖颜色。
- 选中结果时显示来源帧和处理历史；结果没有真实曝光时不伪造当前相机图像。

### 9.3 选中对象操作

重拍、删除、移除最后帧、恢复、导出选中、查看来源等全部放在右侧“所选数据”任务页。左侧仅保留导航、筛选和可见性控制。

### 9.4 统一视图工具

中央顶部固定保留：

```text
2D / 3D / 联合视图 | 适配 | 标准视角 | 显示设置 | 专注视图
```

- 截图、网格、坐标轴、点大小、颜色、显示质量和标记编号收进“显示设置”。
- 视图设置只改变显示，不修改原始点云或导出数据。
- 2D 与 3D 查看对象可以不同，但标题必须分别说明，例如“2D：机位 002 / 3D：拼接结果 001”。
- 截图明确仅当前 3D、当前 2D 或联合视图。
- 所有窗口的适配、专注、返回工作视图使用同一位置和快捷键。

## 10. 后处理统一工作台

### 10.1 总体结构

后处理无论嵌入主窗口还是保留独立窗口，都使用相同外壳：

- 左侧：源数据和处理结果。
- 中央：点云、对比和直接拾取。
- 右侧：工具列表或当前工具参数与执行。
- 顶部：当前项目、返回主工作区、保存、导出、任务、日志。
- 底部：当前输入、任务进度、结果和失败恢复。

右侧工具目录按任务分组：

1. 数据：导入点云、导出选中。
2. 清理：下采样、多边形分割、框内颜色过滤。
3. 配准：手动配准、ICP、FPFH、圆点匹配、提取中间帧。
4. 结果：合并点云、撤销处理。
5. 分析：点云探针。
6. 实验：颜色统一、原色对比及其他验证能力。

点击工具后，右侧从“工具目录”进入“工具任务页”；固定返回按钮回到工具目录。不得在另一个工具中把操作栏移到顶部或左侧。

### 10.2 所有后处理工具的共同规则

- 顶部摘要固定显示输入、单位、坐标系、点数和来源修订。
- 参数修改后，旧候选立即标记“需重新计算”，不能继续发布。
- 结果默认生成独立 DB 分支，原始数据保留。
- 成功后选中新结果，中央显示结果；右侧提供“继续处理”“返回工具”“导出结果”。
- 失败保留输入和参数，显示失败阶段与重试，不清空整个工作台。
- 输入或来源在后台任务期间变化时拒绝发布旧候选。
- 只读分析、显示对比和直接处理要有不同动词，不统称“执行”。

### 10.3 各工具具体流程

| 子功能 | 右侧任务页 | 中央反馈 | 完成后与下一步 |
|---|---|---|---|
| 导入点云 | 源单位 mm/m、文件选择、格式说明 | 导入后显示点云和坐标尺度 | 生成独立结果；可继续下采样、配准或探针 |
| 下采样 | 体素/随机、参数回显、预计输出 | 输入与结果点数；必要时对比 | 新增结果；原始点云保留；可继续配准或合并 |
| 多边形分割 | 顶点数、封闭、撤销顶点、保留方向、应用/取消 | 直接绘制多边形，显示框选范围 | 生成框内/框外分支；清除临时拾取；可继续过滤 |
| 框内颜色过滤 | 过滤通道、上下限、待剔除/保留点数、标红开关 | 中央标红或预览去除效果 | 生成保留与剔除分支；可返回分割或导出 |
| 手动配准 | 固定参考、两侧点数、对应表、分别撤销拾取、执行 | 中央固定双视图，Shift+左键拾取共有点 | 共有点计算后进入 ICP 参数页；保持输入顺序 |
| ICP 精配准 | 固定参考、最大距离、计算体素、迭代、最小重叠 | 执行前检查粗对齐；完成后叠加对比 | 两项模式新增移动结果；来源帧重建新增完整分支；再决定合并 |
| FPFH 两帧 | 固定参考、移动点云、参数组、计算候选、确认、发布 | 候选变换叠加与对应关系 | 生成完整拼接结果；可继续 ICP 或后处理 |
| FPFH 多帧链式 | 参与帧、顺序、首帧参考、上移/下移、参数组、逐步指标 | 当前相邻步骤、累计结果和失败帧 | 任一步失败整批不发布；成功后合并全部有效点/颜色 |
| 圆点匹配（实验） | 参考/移动原始帧、极性、阈值、圆点参数、几何容差、确认 | 双 2D 图像、相同编号和三角约束 | 检查无歧义后生成结果；保留实验标识 |
| 提取中间帧 | 来源拼接结果、将提取的中间数据摘要 | 中间帧与目标结果关系 | 写入独立中间数据；可用于两项配准和检查 |
| 合并点云 | 输入列表、顺序、总点数、结果名称 | 合并预览和来源分色 | 新增合并结果；原始项不变；可导出或继续清理 |
| 撤销处理 | 可撤销操作、影响结果、恢复目标 | 预览将恢复的对象 | 仅撤销明确支持的操作；保留审计信息 |
| 导出选中 | 目标、格式、路径、完整点云说明 | 导出对象名称和点数 | 不改变 DB；成功后提供打开目录 |
| 点云探针 | 重合判定距离、单位与对齐确认、分析 | 点间距、重合比例和诊断摘要 | 只读报告；参考值不自动填入其他工具 |
| 颜色统一（实验） | 算法、参考层、尺度、强度、接缝、样本等分组参数 | 处理前后颜色对比和风险提示 | 新增实验结果；可对比原色，保留源会话 |
| 原色对比（实验） | 对比对象和显示方式 | 原色/处理色切换或并排 | 仅改变视图，不生成结果 |

### 10.4 FPFH 参数页专项要求

FPFH 参数较多，不能简单塞进一个长滚动表单：

- 右侧分为“输入与顺序、常用参数、高级参数、诊断与发布”四组。
- 提供参数搜索和“仅显示已修改”。
- 每项保留中文作用说明、单位、建议和合法范围；不只显示内部键名。
- 多帧顺序固定在右侧顶部，首帧明确标识为参考。
- 报告默认显示摘要，完整 JSON 通过“查看诊断”展开。
- “计算候选”和“生成 DB 结果”是两个连续但分离的阶段。
- 输入、顺序或参数改变后，确认勾选和候选同时失效。
- 返回后保留未提交参数；关闭忙时任务继续遵循现有门禁。

### 10.5 手动配准专项要求

手动配准可以保留中央双视图，但操作仍在右侧：

- 参考与移动选择、共有点数量、对应误差、撤销参考点、撤销移动点统一放在右侧。
- 两侧点编号和中央视图标题始终一致。
- 至少三对且不共线才能继续。
- “共有点配准并设置 ICP”成功后进入右侧 ICP 页，不再额外弹出另一套位置不同的确认窗口。

### 10.6 多边形分割专项要求

当前画布浮动的封闭、撤销顶点、保留方向、快捷删除、颜色过滤和取消，全部迁入右侧任务页。画布只负责绘制和显示，避免与主视图右上角的 2D 预览或视图工具重叠。

## 11. 标定结果与误差检查

### 11.1 多相机标定检查

- 中央：标定点云/匹配圆心、参考和待对齐数据。
- 右侧：数据配对、误差筛选、逐点误差、矩阵、拓扑路径和恢复建议。
- 顶部：返回、显示设置、适配、日志。
- 主视图与右侧选中误差行联动。
- 星型与链式误差含义保持明确；链式局部误差不能暗示已完成全局优化。

### 11.2 转台标定检查

沿用相同布局，增加：

- 右侧“变换播放”区：播放/暂停、重播、进度。
- 初始帧与旋转帧、旋转方向、轴心和可信度。
- 播放只改变显示，不回写标定或采集状态。
- 关闭后返回原转台阶段和原选择。

### 11.3 只读检查页的操作规则

只读页右侧主要是筛选和查看操作，没有业务发布主按钮。固定“返回工作区”位于右上方，关闭按钮不再临时出现在另一个窗口角落。

## 12. 参数设置与外部调试工具

### 12.1 拍摄参数

- 统一从右侧“参数”进入，保持当前工作区和选中相机。
- 相机切换、读取、拍摄、2D、3D、投影分组位置固定。
- 该功能保留“调整后自动生效”的现有交互，但必须在底部持续显示读取中、等待生效、已生效和失败。
- 离线状态明确不可写，不显示虚构默认值。
- 切换相机或离开页面前处理在途写入，不能把一台相机的参数回填到另一台。

### 12.2 识别参数

- 编码圆、标定板规格、自动识别和状态均放右侧。
- 参数自动应用后，说明将影响哪些原始帧的后台识别。
- 修改参数、取消自动搜索和切换页面不得产生过期回填。
- 从主流程进入时提供“返回标定/采集”，不丢失当前阶段。

### 12.3 RVCManager 官方调试

这是外部工具跳转，不嵌入普通拍摄参数页：

- 入口固定在“设备维护”。
- 跳转前明确会停止预览、断开相机及未保存数据处理。
- 返回后恢复到设备连接页，由用户明确重连，不能假装工作区采集未中断。

## 13. 会话、存储与回收区

会话管理页采用“中央会话表 + 右侧所选项目操作”：

- 中央显示名称、工作区、占用、保存时间、当前打开/受保护状态。
- 右侧显示选中数量、总占用和路径。
- 固定动作：打开、打开数据目录、刷新统计、删除选中、清空未引用回收区。
- 永久删除默认焦点为取消，确认中列出对象和数量。
- 当前打开或仍被工作流引用的数据必须保护。
- 保存会话只修改用户明确保存的正式快照；临时工作区和回收区语义不变。
- 新建、载入、清空后同步清理旧 2D、3D、时间线和异步结果。

## 14. 实验功能与验证副本

实验功能入口收进全局“帮助/实验”或项目菜单，不与正式主操作争夺注意力。

实验首页列出：

- 颜色统一、原色对比、原始 2D 融合。
- FPFH 与几何特征匹配。
- 几何后处理、框选、下采样、ICP。
- 普通圆点与三角形几何匹配。
- 多相机和机器人验证副本。

进入后仍复用同一外壳和对应工具任务页，并始终显示：

```text
实验验证副本 · 离线 · 保存到 outputs/experiments · 源会话不变
```

- 不显示可连接设备或正式采集的假入口。
- 关闭副本返回原工作区，源项目和源选择不变。
- 实验算法可以与正式工具共用交互规范，但实验标识不能在嵌套页面中消失。

## 15. 任务中心、日志、帮助与异常恢复

### 15.1 任务中心

统一显示后台识别、采集、配准、保存、加载、导出和副本创建：

- 当前任务、阶段、进度、是否可安全停止。
- 已完成、失败和需要用户处理的任务。
- 点击任务可回到对应工作区和工具页。
- 切换视图、打开日志或专注模式不停止任务。

### 15.2 日志

- 默认收起，不遮挡右侧主操作和中央关键结果。
- 普通用户先看底部摘要，技术人员再展开完整日志。
- 错误日志关联对象、时间和恢复动作，避免只有技术堆栈。

### 15.3 帮助

帮助按当前任务页显示：

- 当前物理操作。
- 输入要求。
- 参数含义。
- 常见失败和恢复。
- 指标不能代表什么，例如标记拟合误差不等于点云表面精度。

## 16. 统一文案与状态语义

| 当前容易混淆的表达 | 建议 |
|---|---|
| DB / 项目数据 | 项目数据 |
| 拼接帧（原始输入） | 扫描帧 / 机位 |
| 拼接帧（独立结果） | 拼接结果 |
| frame0 / frame1 | 基准帧 / 旋转帧 |
| 撤销上一步 | 移除最后原始帧 / 撤销指定处理，按真实动作命名 |
| 拼接并保存 | 执行拼接；保存项目；导出点云，三者分开 |
| 执行 | 计算候选 / 开始分析 / 生成结果 / 发布结果，按阶段命名 |
| 最大化视图 | 专注视图 |
| 失败、未通过 | 失败对象 + 原因 + 建议 + 可执行恢复动作 |

状态颜色不能单独承担含义：成功、警告、失败、离线、实验、过期、忙状态同时配文字和图标。品牌红用于当前主操作，危险操作用明确文字和确认，不让所有按钮都成为红色。

## 17. 视觉、密度与可访问性

保留现有 MCC 红色标识、SCAN STUDIO、深灰背景、灰白线性图标和小圆角工业风格，不改成营销页或另一套浅色 SaaS 主题。

- 以 8px 为布局基础间距，工具内部可用 4px；减少无意义嵌套卡片。
- 正文建议 12–13px，区域标题 14px，关键阶段 16px；不通过继续缩小字号解决空间不足。
- 桌面输入和常规按钮建议至少 32px 高，主操作 36–40px；触摸工位另提供 44px 以上目标。
- 图标使用现有语义图标体系，不用 emoji 代替功能图标。
- 键盘焦点清晰，Tab 顺序与视觉顺序一致；所有悬停功能也可通过键盘和菜单访问。
- 正文与关键状态对比度至少 4.5:1；禁用态也要可读禁用原因。
- 动效只用于面板内容切换和任务状态，150–250ms，不能让操作位置发生移动。
- 1366×768 优先折叠高级设置和预览，不隐藏停止、失败原因和主操作。
- 1920×1080 不无限加宽右侧表单；保持约 320–380px 的可读操作列，可拖动调宽。

## 18. 推荐的实现结构

以下为后续实施建议，不是本轮代码改动：

| 组件 | 单一职责 |
|---|---|
| `AppShell` | 固定全局栏、左右栏、底部状态和页面导航 |
| `ProjectDataPane` | 项目树、筛选、选择、处理集合、可见性 |
| `WorkspaceViewport` | 2D/3D/联合视图、视图工具和直接拾取 |
| `TaskPane` | 当前任务、参数、固定主次动作、结果和返回 |
| `TaskCenter` | 后台任务、进度、失败恢复和跨页面定位 |
| `Command/QAction` | 一个动作的唯一业务分发、启用状态、原因、快捷键 |

实施时应复用现有工作流、信号和控制器，逐渐把重复按钮收口到同一 Command。不能同时保留旧 `clicked` 与新 `triggered` 业务回调，避免一次点击执行两次。

优先复用或调整：

- `src/ui_v2/main_window.py`：全局外壳和状态。
- `src/ui_v2/industrial_ribbon.py`：从全功能 Ribbon 收敛为固定项目动作。
- `src/ui_v2/industrial_presentation.py`：固定三栏挂载。
- `src/ui_v2/frame_database.py`、`widgets/db_properties.py`：选择语义与数据详情。
- 四个 `workspaces/*_workspace.py`：只提供任务页内容和公开动作，不改变核心门禁。
- `offline_stitch.py`：移除特殊布局重组，接入统一外壳。
- `postprocess/window.py` 及各 `*_dialog.py`：迁移为右侧任务页。
- `ui_common/calibration_result.py`：复用统一检查页。

核心算法不得依赖 QWidget；显示设置、业务动作和后台结果仍通过公开契约连接。

### 18.1 次级动作统一归位表

以下能力不得因主流程简化而遗漏，也不得在迁移时重新变成临时浮动按钮：

| 次级能力 | 固定入口与连续操作 |
|---|---|
| 设备断开、重连、查看连接详情 | 右侧“设备”任务页；断开前说明预览和采集影响，保留项目草稿 |
| 多相机单路预览、单路 3D 拍摄、单路检测 | 右侧“设备诊断”页；先选目标相机，全部相机采集与单路诊断明确分开 |
| 2D 布局、裁边、冻结、保存图像 | 中央固定“显示设置”；冻结持续显示状态，保存图像不写入扫描帧 |
| 转台定位轴心、显示旋转轴与中心 | 定位轴心属于右侧标定参数；旋转轴/中心显示属于中央显示设置，两者不得混为一个开关 |
| 手眼矩阵导出 | 右侧“手眼矩阵”页的次要动作，沿用当前单位、安装方式和验证状态 |
| FPFH 参数与诊断 JSON 导出 | 右侧“诊断与发布”页的次要动作，不改变候选和 DB；发布仍是独立主动作 |
| 旧机位/旧会话导入 | 启动页“打开项目”内的“导入旧数据”；识别目标工作区，导入后回到对应项目首页 |
| 会话命名与保存路径确认 | 全局保存任务的统一确认页；保存成功后返回原工作区和原选择 |
| 当前数据返回工作视图 | 右侧“所选数据”页固定返回动作，恢复进入历史预览前的 2D/3D 状态 |

## 19. 分批实施顺序

### 批次 0：动作和流程清单

- 为所有可见动作建立唯一 ID、目标对象、输入要求、执行结果和失败恢复表。
- 明确当前选择、处理集合和视图可见性。
- 为位置不变量和重复分发补回归测试。

### 批次 1：统一外壳与四种在线工作区

- 建立固定左侧数据、中间视图、右侧任务和底部状态。
- 迁移项目动作、四种工作区和选中数据操作。
- 不改变算法、会话格式和设备生命周期。

### 批次 2：离线拼接和基础后处理

- 迁移离线加载、标记拼接、导入、下采样、分割、颜色过滤、合并、撤销、导出和探针。
- 建立统一“输入—参数—执行—DB 结果—下一步”闭环。

### 批次 3：复杂配准和检查工具

- 迁移 ICP、手动配准、FPFH 两帧/多帧、圆点匹配、中间帧和颜色实验。
- 迁移多相机与转台标定检查页。
- 保留候选失效、来源修订和整批失败门禁。

### 批次 4：项目、实验和收尾

- 统一启动、会话管理、实验副本、任务中心、帮助和快捷键。
- 删除已迁移的重复入口；任何旧能力在删除前必须有明确新入口。
- 完成全尺寸、离屏、真实数据和实机分层验收。

不建议一次性重写全部窗口和业务服务，也不建议只做主工作区后继续新增不符合规范的二级弹窗。

## 20. 全功能验收矩阵

### 20.1 位置与连续性

- [ ] 四种工作区切换时，左侧始终是数据，右侧始终是任务。
- [ ] 多相机从拍摄到检测、计算、扫描，主按钮没有跨区域移动。
- [ ] 移动拼接从拍摄到评估、重拍、闭环和导出，返回路径清楚。
- [ ] 转台自动采集的停止始终可见，专注视图和日志不会意外停止任务。
- [ ] 机器人矩阵、位姿、采集、戳点、发布均在右侧完成。
- [ ] 离线与在线工作区除设备差异外布局一致。
- [ ] 后处理每个工具的参数和执行均在右侧，画布没有第二套业务工具栏。
- [ ] 标定检查、会话管理和实验副本没有操作栏左右跳转。

### 20.2 业务闭环

- [ ] 多相机质量失败能定位相机对并重拍/重检，未通过门禁不能扫描。
- [ ] 移动拼接失败帧保留原始数据，成功、谨慎、失败的后续动作不同。
- [ ] 转台标定、单步、自动、新一轮和拼接结果状态一致。
- [ ] 机器人未验证不能发布或导出，单位和位姿定义始终可见。
- [ ] 离线部分文件失败不会清空成功输入，整批拼接失败不发布部分结果。
- [ ] 所有后处理结果明确写入 DB 的位置，原始数据是否保留可解释。
- [ ] FPFH 输入/参数变化使候选失效，多帧任一步失败整批不发布。
- [ ] ICP、手动配准和合并的固定参考、移动对象及顺序始终一致。
- [ ] 探针和颜色对比不会误修改数据或自动填参数。
- [ ] 过期结果不能被当作最新有效结果继续发布或导出。

### 20.3 项目与生命周期

- [ ] 单击任何动作只触发一次后台操作。
- [ ] 保存、打开、新建、关闭遵守显式会话和未保存确认。
- [ ] 后台忙时切换、关闭和重试遵循原门禁，无过期异步回填。
- [ ] 永久删除和回收区清理保护当前打开及被引用数据。
- [ ] 不新增隐式正式会话保存，不改变原始点云、单位和坐标定义。

### 20.4 显示与可访问性

- [ ] 1366×768、1600×1000、1920×1080 和系统缩放下无关键按钮被挤出。
- [ ] 键盘可完成导航、参数输入、执行、返回和日志查看。
- [ ] 所有禁用主操作都有可见原因，不只依赖 tooltip。
- [ ] 状态不只靠颜色，图标、文本和焦点清晰。
- [ ] 视图设置不改变原始数据，2D/3D 当前对象名称准确。

## 21. 验证层级与成功指标

实施后的验证必须分层记录：

1. 动作分发、状态门禁和会话单元回归。
2. Qt 离屏布局、导航、键盘和窗口尺寸检查。
3. 项目内真实离线数据的完整任务链。
4. 实体相机、多相机、转台和机器人分别验收。
5. 原生 GPU、性能、打包和客户机分别验收。

离屏通过不能写成实机通过，单次算法成功不能写成重复稳定性或真实精度通过。

建议用以下指标判断改造是否有效，而不是只看按钮减少数量：

- 新用户不看开发说明能否完成每种模式的一次完整任务。
- 用户能否在固定位置找到主操作、停止、返回和失败恢复。
- 是否还存在同一动作的多个常驻入口或一次点击重复执行。
- 完成工具后，用户能否说清结果位置、原始数据去向和下一步。
- 跨模块操作错误、误选输入、误导出和找不到停止入口的次数是否下降。
- 高级用户是否仍能访问全部分步诊断、参数和报告。

## 22. 明确不改变的内容

- 不改变标定、配准、质量门禁和机器人戳点验证的数学定义。
- 不改变原始数据保留、独立 DB 结果、来源修订和过期结果规则。
- 不改变显式项目会话、临时工作区、正式快照和回收区边界。
- 不改变设备 SDK 锁、线程、在途任务、断开连接和关闭等待语义。
- 不把实验能力伪装成正式验收能力。
- 不为了简洁删除 FPFH 高级参数、分步标定、单路诊断、矩阵和详细质量报告。
- 不恢复旧版 UI 或双入口，正式工作区继续使用 industrial。
