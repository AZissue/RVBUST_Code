# 工作记录循环联动（工单 ↔ 工作记录 ↔ 工作事项）

时间：2026-09-16
分支：`crm_system_v2`
对应提交：`b8e761d`

## 目标

让「工作记录 ↔ 工单 / 工作事项」形成单向、闭环、可预期的自动联动，以工单为轴心串起三块数据。

## 原则

- **联动单向、追加式**：监听器/事务内永不自动改业务状态（工单状态的唯一来源是用户操作），从机制上杜绝 A→B→A 死循环
- **事务原子**：worklog 与联动写入同一 Prisma 事务，失败一起回滚，无半联动状态
- 复用现有枚举（`TicketEventType.WORK_RECORD`）与软删模式（`metadata.timelineDeleted`），零迁移

## 实现（apps/api/src/worklogs/worklogs.service.ts）

- **create()**：同事务内 ① 有 ticketId → 回写 TicketEvent（WORK_RECORD、INTERNAL、`工作记录：{summary}`、metadata `{ worklogId, durationMinutes }`）；② 有 workItemId → 事项 TODO→IN_PROGRESS、进度兜底 ≥10（COMPLETED 不动、不改 completedAt、不自动完成）
- **update()**：联动事件 content 同步更新；ticketId 变更时旧工单事件打 timelineDeleted 软删、新工单补建事件；裸记录首次关联也补建
- **remove()**：联动事件软删（保留审计痕迹）后删 worklog
- createDrafts / confirmDrafts 不联动（草稿不进入时间线）

工单详情查询本就过滤 `metadata.timelineDeleted === true`，前端零改动。

## 前端

- WorklogsPage、WorkItemsPage（列表 + 抽屉详情）共 3 处 `useRemote` 开启 `live=true`：任何页面写入后自动刷新（同标签页事件广播 + 跨标签页 BroadcastChannel）

## 效果

- 在工单详情登记工作记录 → 时间线立即出现条目，回顾工单全过程只看时间线即可
- 给 TODO 事项填记录 → 事项自动「进行中」且进度 ≥10，看板不再误导；完成仍须人工确认
- 修改/删除记录 → 时间线保持一致，软删可追溯
