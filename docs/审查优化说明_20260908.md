## 已修复

1. Docker Compose 明确 UPLOAD_DIR=/app/uploads，与持久卷一致；API 镜像默认路径同步修正。
2. 管理员无法通过用户编辑接口修改自身角色，避免误操作失去管理权限。
3. 用户审批、拒绝、启用、停用使用带预期状态的条件更新；并发状态变化返回冲突。
4. 工单和返修附件元数据与时间线事件放入同一数据库事务，事件失败不会单独提交附件记录。

回归结果：生产构建通过；46 项单元测试、54 项 API 集成测试通过。

## 对报告的补充

- 用户 update DTO 无 status 字段，所以“通过 update 停用自身”不适用于此版；自行降权问题存在并已修复。
- 附件数据库事务不能自动撤销已经写到磁盘的文件；失败上传的物理文件清理仍需单独完善。
- 保留已有 Permission/RolePermission 表；直接删除会影响未来权限配置和迁移兼容性。
- 工单软删除需要同时确定列表、报表、关联记录、附件与审计查询口径，不宜仅替换一条删除语句。
- 借测归还清空公司样机客户挂靠符合已有“临时挂靠”规则；若要恢复历史挂靠应先保存借出前归属。
