### 6.1 @lead 口径裁定（2026-09-24，依 @verify `docs/W13W14预探报告_verify_20260924.md`）

**裁定 A —— 字体类判据改口径（采纳 @verify 建议 + @dev 修法）**
- 旧口径 `grep -nE 'font-family|setFont\('` 命中 0 **作废**：自绘文字唯一 API 是 `painter.setFont(...)`，实测 2 命中 ⇒ 原口径**必假失败**（数值存档：`cc_gl_viewer.py:89,133`）。
- **新口径**：`grep -nE 'QFont\(\s*["'']|font-family:' app/*.py` 命中 **0**（含单引号写法；实测 dev 现实现 0 命中）。
- **自绘字体取值口径**（采纳 @dev W13-5 修法）：`_app_font()` 取**控件自身 `self.font()`**（`GLOBAL_QSS` 已作用到 widget → 字族 `Segoe UI`），**不用** `QApplication.font()`（实测 YaHei UI，不吃 QSS）；copy 后显式 `setPointSize()`（实测 `pointSize()` 可能为 `-1`）。
- 判据连带调整：S1② 类清单补 `QToolButton` / `QTreeView` / `QHeaderView`（本轮返工面全落在 `QToolButton`）；S2 档位按**实测 `grab()` 尺寸**锚定（真机当前 1400×1105，`minimumSizeHint` 高），沿用 M2"只判主档"先例；S3 采样前必须 `show() + processEvents()`（未 show 的控件字体为 YaHei UI，会假失败）。

**裁定 B —— S4 保留四态 + 8 张图清单按本原型重定义**
- **否 @dev 拟的三态**（idle/loaded/processing）：会正好抹掉 `STATUS_ERR`，而 G-S3.5-d 已要求"载入失败不静默" ⇒ failed 是必现分支、且是最该被用户看见的一态。四态色值：idle→`TEXT_MUTED`、loaded→`STATUS_OK`、processing→`STATUS_WARN`、failed→`STATUS_ERR`。
- 取色纪律沿用 D1 口径：**窗口整图内取 + `visibleRegion()` 非空**，**禁** `statusbar.grab()`。
- 8 张图固定命名（§4.1 与脚本实产对账）：`proto_idle` / `proto_loaded` / `proto_processing` / `proto_failed` / `proto_min_size_resized`（记录实际 `grab()` 尺寸）/ `main_ref` / `cmp_side_by_side` / `proto_panel_zoom`；手眼四张状态图作废。
- 状态构造须走真实分支：failed 由**真坏文件**触发（禁改 label 文本伪造）；processing 优先在真实载入中抓帧，若不可得，允许经公开状态入口（`state_changed`）构造，但报告须标注"经公开 API 构造"。

**裁定 C —— W13-4 / W14 口径沿用**：截图锚定实际 `grab()` 尺寸并记录；拖拽验收断言"拖拽与对话框两入口产出**完全相同的 `_load_files` 实参元组**"，真机手动拖一次作为残留风险的补证，不进 CI。
