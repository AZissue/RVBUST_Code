# 功能扩展规划：离线拼接 + 机器人手眼标定配合拼接

> 规划日期：2026-08-07 ｜ 状态：部分实现中——模式 D core 已落地（2026-08-13：`src/core/handeye.py` / `robot_interface.py` / `robot_stitch_workflow.py` + `test_handeye.py` / `test_robot_stitch.py`，UI 未接线）；模式 C 原型已建（`prototypes/offline_stitch/`）
> 范围：功能选择页（LauncherDialog）扩展 + 两个新功能（模式 C 离线拼接 / 模式 D 机器人手眼配合拼接）的 UI 与功能设计
> 关联文档：《两种拼接方式改进方案.md》（A/B 模式架构）｜《代码整体审查与完善建议.md》（现状问题）｜ `D:\RVC_SRC\hand-eye-tools`（手眼标定数据采集助手）

## 1. 背景与目标

现有功能选择页提供两个入口：**模式 A 多相机外参标定拼接**、**模式 B 单相机移动链式拼接**。后续需要扩展：

- **离线拼接（模式 C）**：不连接相机，直接加载已保存的会话数据（帧/外参/误差报告）做检测→标定→拼接→导出。适合：产线离线复盘、现场数据带回办公室处理、演示。
- **机器人手眼标定配合拼接（模式 D）**：相机（通常单目/双目）配合工业机器人做多视角扫描拼接——用机器人位姿 + 手眼标定结果直接给出每帧变换，**不依赖标记物**（无纹理工件可拼），适合自动化产线。

**目标**：功能选择页从 2 入口扩展为 4 入口（卡片式）；两新功能复用现有 core 能力最大化，新增代码最小化。


设计要点：
1. **卡片元数据扩展**：每卡片带 `requires_device`（A/B/D 需要、C 不需要）→ 选择 C 时设备区自动隐藏并显示"会话文件选择"区
2. **模式 C 启动流**：选卡片 → 文件选择器选会话目录 → 校验 meta.json → 进入离线工作区
3. **模式 D 启动流**：选卡片 → 设备区变为「相机 + 机器人连接配置」双区 → 连接校验 → 进入机器人工作区
4. 占位策略：D 卡片先展示但置灰 + "规划中"角标，避免用户误入半成品

## 4. 功能 C：离线拼接（模式 C）

### 4.1 定位
在线模式 A/B 的**重放/后处理视图**：同一套工作区 UI（步骤条/3D 查看器/日志），数据源从"相机"换成"会话目录"。无 PyRVC 依赖（纯离线）。

### 4.2 用户流程
```
选择会话目录 → 加载会话信息卡片 → 步骤条：
  ① 加载（帧数/相机数/点云预览）→ ② 检测（重跑或加载已存标记）
  → ③ 标定（重算或加载已有外参）→ ④ 拼接（重拼+误差报告）→ ⑤ 导出（PLY/报告）
```

### 4.3 功能设计
| 项 | 方案 |
|---|---|
| 会话来源 | `offline_data/` 下 `session_时间戳/` 目录（OfflineSession 落盘格式）；兼容将来 `scans/` 统一会话（《两种拼接方式改进方案.md》§8） |
| 信息卡片 | 目录名、相机数、帧数（标定帧/扫描帧）、外参状态（有/无）、已存误差报告摘要 |
| 可重跑环节 | 检测/标定/拼接均可"重跑"（改参数后重新计算，不覆盖原文件，导出到新目录） |
| 3D 预览 | 复用 viewer_3d；加载后先显示点云，再叠加标记/坐标轴 |
| 导出 | 拼接 PLY + error_report.json + 可选"外参表"（A 模式） |
| 批量 | 支持一次选多会话目录批量导出（产线复盘） |

### 4.4 复用清单
- ✅ `OfflineSession`（load_session/detect_all/calibrate_multi/stitch_all）——数据层全套
- ✅ `marker_detector` / `calibration_engine` / `stitch_engine` / `point_cloud_processor`
- ✅ `viewer_3d` / `floating_log_panel`
- ➕ 新增：`OfflineWorkspace`（UI 壳，复用 multi_cam_workspace 的步骤条骨架）+ bridge 接线（~200 行）
- ⚠️ 前置修复：会话加载残缺（M6）、会话保存只存最新帧（P1-18）——离线模式的价值取决于**会话数据完整性**

## 5. 功能 D：机器人手眼标定配合拼接（模式 D）

### 5.1 原理与坐标链
```
Eye-in-Hand（相机装机器人末端）：  T_base2cam = T_base2tool × T_tool2cam
Eye-to-Hand（相机固定安装）：      T_base2cam = T_base2tool × T_tool2board × T_board2cam（标定板固定机器人上）
```
- **T_tool2cam（手眼标定结果）**：采集 N 组（机器人位姿 T_base2tool + 相机检测标定板位姿 T_board2cam），OpenCV `cv2.calibrateHandEye` 求解
- **拼接**：每帧点云 `p_base = T_base2cam × p_cam` 变换到基座系后 merge——**无需标记物**（区别于模式 B）
- **可选精配准**：机器人位姿给初值 → 局部 ICP/标记精配准，补偿机器人重复定位误差（粗-精两级）

### 5.2 标定流程（复用 hand-eye-tools + 新增求解）
```
① 采集（复用 hand-eye-tools 思路）：机器人示教 N 个位姿（≥10，覆盖不同角度/距离）
   → 每位置记录 T_base2tool（机器人控制器读出）+ 相机拍标定板 → 检测得 T_board2cam
② 求解：cv2.calibrateHandEye(R_gripper2base,t_gripper2base, R_target2cam,t_target2cam)
   → 输出 T_tool2cam（Eye-in-Hand）或 T_cam2base（Eye-to-Hand）
③ 结果标准格式 handeye_result.json：{method, T_cam2tool/T_base2cam, rms_error_mm, n_samples, timestamp}
④ 验证：标定误差可视化（重投影误差/平移残差）
```

### 5.3 拼接流程
```
连接相机+机器人 → 导入/标定手眼结果 → 设置拼接参数（站位规划：角度步进/数量/重叠率）
→ 自动流程：机器人移动到站位 i → 触发拍照 → 记录 T_base2tool → 点云变换+增量合并
→ 每步显示重合度/误差 → 闭环检测可选（回到起点补拍）→ 全局优化 → 导出
```

### 5.4 机器人接口规划（抽象层）
| 协议 | 适用 | 实现 |
|---|---|---|
| TCP Socket（文本/JSON 指令） | UR/发那科/埃斯顿等主流 | `RobotClient` 基类 + UR 实现（`/movej`, 读 `actual TCP pose`） |
| Modbus TCP | 简易控制器/转台（如 EPR60 经验） | 读保持寄存器位姿 |
| 离线位姿列表（无实时通信） | 演示/仿真 | CSV/JSON 导入位姿序列，手动触发拍照 |

**接口抽象**：`RobotInterface.get_current_pose() -> (R_base2tool, t_base2tool)` + `move_to(pose)` + `is_moving()`；支持 mock（合成数据测试）。

### 5.5 UI 流程
```
启动卡片 D → 连接区（相机 IP + 机器人 IP/协议/位姿文件）→ 工作区：
  步骤条：① 手眼标定（采集引导/导入结果）→ ② 扫描（站位列表+进度+每步误差）
  → ③ 精配准（可选）→ ④ 全局优化 → ⑤ 导出
面板：机器人位姿实时显示（TCP 时）、站位规划表（角度/增量）、误差卡片（同模式 B 绿黄红）
```

### 5.6 与模式 B 的关系
| 维度 | 模式 B（现有） | 模式 D（新增） |
|---|---|---|
| 变换来源 | 共有标记自动配准 | 机器人位姿 + 手眼标定（+可选精配准） |
| 适用 | 有纹理/可贴标记的场景 | 无纹理工件、自动化产线 |
| 精度依赖 | 标记检测精度 | 机器人重复定位精度 + 手眼标定精度 |
| 自动化 | 半自动（人工移动） | 全自动（机器人执行） |
| 可复用 | — | 拼接/优化/导出管线、误差卡片、时间线 |

## 8. 风险与开放问题

| # | 风险/问题 | 影响 | 应对 |
|---|---|---|---|
| R1 | 现有会话格式不完整（只存最新帧、无外参 round-trip）→ 离线拼接可用性打折 | 高（模式 C 前提） | 先修 M6/P1-18 再上线 C |
| R2 | 机器人 SDK 种类多，实时位姿读取协议差异大 | 中（模式 D） | RobotClient 抽象 + 先支持 UR（TCP）和离线位姿列表 |
| R3 | 手眼标定精度验证手段缺失（标定误差≠拼接误差） | 中 | 输出重投影误差 + 拼接重叠区 RMS 双指标 |
| R4 | 机器人触发拍照与位姿记录的时序同步（到位判定→触发→读位姿） | 中 | 用"到位信号 → 拍照 → 读位姿"严格序列；每帧记录时间戳 |
| R5 | 相机装机器人末端时线缆/震动影响 | 低 | 预留"到位后稳定延时"参数 |
| R6 | 模式 C 与《改进方案》§8 的 `scans/` 统一会话格式未落地——两套格式并存 | 中 | C 先支持现状格式，`scans/` 落地时做迁移适配层 |

## 9. 结论

- **离线拼接（C）**：复用度最高（OfflineSession 数据层已 90% 就绪），是纯软件功能，**建议优先做**；前置条件是把会话保存/加载补完整（M6/P1-18）。
- **机器人手眼配合拼接（D）**：价值高（自动化产线刚需）但依赖机器人资源；手眼标定采集可复用 `hand-eye-tools`，求解用 OpenCV 现成算法，**建议先 M2 标定（可独立交付验证），再 M3 拼接**。
- **功能选择页**：现卡片结构扩展成本低，按 §3 规划加 2 卡片即可，D 先置灰占位。
