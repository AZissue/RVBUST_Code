# 移动拼接低 RMS 但点云分层：复现与修复

日期：2026-10-21（Asia/Shanghai）。对应用户截图：4 帧、1 个结果、4,128,233 个有效点。

## 结论

已确认是全局优化造成的真实配准错误，且界面显示了优化前的局部标记误差。并非仅凭截图推断，也不是用更宽松的显示参数消除分层。

读取该次临时工作区的完整只读副本，重新从每帧 PNG 和有组织 PLY 检测编码圆。保存的各帧标记 2D/XYZ 与本次重新检测结果逐项一致；前3帧视角基本一致，第4帧发生移动。各帧局部配准本来正常。

| 同一批原始数据、同一组已接受共有标记 | 世界坐标下共有标记 RMS |
|---|---:|
| 初始逐帧配准，尚未全局优化 | 0.004854849 mm |
| 原全局优化后的结果 | 6.179230968 mm |
| 修复后的全局优化 | 0.004752841 mm |

将原结果 PLY 按源帧的有效点数分段，与原优化后的位姿变换逐点抽样比对，最大差异约 `7e-14 mm`。由此确认保存的结果确实使用了错误的优化位姿；不是查看器额外变换或降采样造成的现象。

## 根因

1. `ExplicitStitching.execute()` 对三帧以上移动拼接自动调用 `MobileChainWorkflow.optimize_global()`。
2. 原 `PoseGraph.optimize_global_ba()` 用相对位姿误差构造残差，直接把弧度旋转与毫米平移放入同一最小二乘目标。该数据的微小平移不一致被优化器用较大角度变化补偿，平移残差从约 0.048 降至 0.040，却让距相机原点约320 mm的标记严重错位。第二帧相对原正确变换的抽样点位移最大达到约12.06 mm。
3. 原 `_se3_exp()` / `_se3_log()` 将小于 `1e-6` 的旋转直接归零，小扰动的有限差分也被截断，进一步影响数值优化。
4. 旧门禁依然来自 `ChainEdge.rms_mm`，它是独立 pair 求解时的标记内点残差，不是最终全局位姿的实际误差。累计值也来自这些局部误差，无法揭示优化造成的旋转失配。

局部拟合误差和表面配准精度本来就不是同一指标，但本例另有可复现的算法缺陷，不能仅以“标记少/表面有噪声”解释。

## 修改

- `src/core/pose_graph.py`：保留原相对位姿接口，新增可选 `point_constraints`。移动流程以已接受的共有标记在世界系下的三维距离为目标，各残差统一毫米，旋转也由实际观测位置约束；用 SciPy Rotation 保留微小旋转和数值导数。
- `src/core/mobile_chain_workflow.py`：根据已测量 pair 的 2 mm RANSAC 判据冻结内点，不把已剔除标记重新加进全局目标。用同一组观测复核优化前后 RMS；结果变差、非有限、非刚体或锚点改变时保留原位姿及点云缓存，最终误差超限不应用。
- 报告增加 `global_marker_rms_mm`，计算的是最终实际位姿；旧的局部 pair 残差继续保留供诊断，不改已有会话格式。无标记 XYZ 的旧位姿会话仍能导出报告，不伪造全局精度数值。
- `src/ui_v2/explicit_stitching.py`、移动工作区与评估卡片：显式拼接后显示最终的“全局标记误差”，保留3位小数，提示其不代表整个表面精度；后续单步评估及重置恢复本步口径。

## 使用与限制

当前程序进程不会自动加载新的 Python 源码。先保存当前会话，再重启到本次修复版本，打开会话并重新“执行拼接”，生成新结果；已有错误结果不会自动被替换。也可直接查看上述独立修复 PLY。

修复解决了本数据中全局优化引入的毫米级分层。约0.005 mm仍是这些标记的拟合残差，不等于整幅点云具有0.005 mm绝对精度；点云噪声、标记几何分布及表面一致性仍需按实际测量任务验证。
