# 标准文档（Excel）导出/导入功能设计说明

状态：待实现（后期完善功能）｜ 日期：2026-09-08
关联代码：`apps/api/src/tickets/quick-input.parser.ts`、`ai.parser.ts`、`quick-tickets.service.ts`、`apps/web/src/components/QuickTicketInput.tsx`

---

## 1. 功能目标

1. **导出**：从工单生成一份带固定表头的 Excel 标准文档，供线下填写（如客户现场记录、外发协作）。
2. **导入**：上传填好的 Excel 标准文档，系统自动解析字段并填入工单数据，经用户确认后创建或更新工单。

核心原则：**导入不直接落库，必须经过与"快速记录"相同的确认弹窗**，人工校对后才创建。

## 2. 为什么用 Excel

- 固定表格结构稳定，按表头/单元格取值，不受格式漂移影响（Word 自由文本解析不可靠）；
- 微信/钉钉传输不易损坏，客户和协作方都能打开填写；
- 解析库成熟（`exceljs`，纯 JS，无原生依赖，符合树莓派轻量部署目标）。

## 3. Excel 模板设计（数据契约）

单个 Sheet，两行表头结构：**第 1 行中文表头（给人看），字段以固定列顺序为准**。建议布局：

| 列 | 表头 | 对应工单字段 | 必填 | 说明 |
|---|---|---|---|---|
| A | 客户公司 | organization.name | 是 | 支持模糊匹配，匹配不到时确认弹窗可新建 |
| B | 问题标题 | title | 是 | |
| C | 问题描述 | description | 是 | 支持多行文本 |
| D | 问题分类 | category | 否 | 下拉选项同创建表单：售前咨询/客户培训/点云调试/SDK开发/手眼标定/硬件故障/其他 |
| E | 负责人 | assignee.name | 否 | 姓名模糊匹配，空则默认为当前用户 |
| F | 优先级 | priority | 否 | 低/普通/高/紧急，空则普通 |
| G | 相机型号 | cameraModel | 否 | 如 M2600 |
| H | 序列号 | serialNumber | 否 | SN 码 |
| I | SDK 版本 | sdkVersion | 否 | |
| J | 系统环境 | systemEnvironment | 否 | OS/网络/运行环境 |
| K | 计划完成时间 | plannedAt | 否 | YYYY-MM-DD HH:mm |
| L | 原始记录 | rawText | 否 | 整段原始描述，原样保留 |

规则：

- **从第 2 行起每行 = 一张工单**（支持一次导入多单，逐单弹确认）；
- 表头行文本必须与模板完全一致，导入时先校验表头，不符则拒绝并提示模板版本；
- 模板文件本身由"导出空模板"功能生成（见 4.3），保证表头永远正确。

## 4. 导出设计

### 4.1 工单导出（详情页按钮）

- 入口：工单详情页加"导出 Excel"按钮；
- 后端 `GET /tickets/:id/export` 用 exceljs 生成 xlsx，Content-Disposition 附件下载；
- 文件名：`{工单编号}_{客户名}_{YYYYMMDD}.xlsx`；
- 内容：第 3 节表格的 A~L 列，已填字段填入当前值，未填留空。

### 4.2 批量导出（可选，后做）

工单列表勾选导出多行一个 Sheet，或每单一文件打 zip。首期不做。

### 4.3 空模板导出

- 入口：创建工单弹窗/工单列表页"下载 Excel 模板"链接；
- 生成仅含表头行 + 一行填写示例（示例内容标注"示例，请删除"）；
- 表头内嵌版本标识（如模板生成时间在文档属性或隐藏单元格），便于将来模板升级时提示用户换模板。

## 5. 导入设计（核心）

### 5.1 流程

```
上传 xlsx
  → 后端校验表头（版本/列序）
  → exceljs 逐行读取，按列映射成原始字段
  → 每行组装成 ParsedTicket 结构（与快速记录解析输出同构）
  → 前端打开"解析结果确认"弹窗（复用 QuickTicketConfirm）
  → 用户逐行校对/修改/跳过
  → 确认后走既有创建/更新通道（requestKey 幂等、相似工单检查、新建客户确认全部复用）
```

### 5.2 关键复用点

| 现有能力 | 复用方式 |
|---|---|
| 客户模糊匹配 `matchCustomers` + `choose` | 导入时直接调用，复用归一化与歧义保护 |
| 负责人匹配 `matchPeople` | 同上 |
| 确认弹窗 `QuickTicketConfirm` | 解析结果即 `Parsed` 结构，弹窗无需改动 |
| 相似工单检查 `/tickets/quick/similar` | 确认弹窗内自动触发 |
| 创建幂等 `requestKey` | 导入每行生成新 requestKey |
| 快速更新通道 `quick-update` | 用户选择"更新现有工单"时走原接口 |

### 5.3 逐行确认交互

- 左侧（或顶部）行选择器："第 2/5 行"，每行状态标记（待确认/已创建/已跳过/失败）；
- 每行确认后标记状态，全部处理完给汇总（成功 N、跳过 M、失败 K 及原因）；
- 后端接口拆两个：
  - `POST /tickets/import/parse`（上传文件 → 返回解析后的行数组，不落库）；
  - 创建仍走现有 `POST /tickets` / `POST /tickets/:id/quick-update`，前端逐行提交（简单且完全复用权限与校验）。

### 5.4 解析容错

- 单元格空白 = 字段缺省（走默认值），不报错；
- 优先级值不在选项内 → 标红提示，弹窗中用户改；
- 日期格式容错：Excel 日期对象 + 字符串 `YYYY-MM-DD HH:mm` 都收；
- 客户列多行内容里若有换行描述，提示拆行。

## 6. 安全与权限

- 导入/导出仅内部角色（复用 `requireInternal`）；
- 文件大小限制（建议 ≤ 2MB、≤ 200 行）；
- 服务端解析不过度依赖文件内容长度，防止畸形文件拖垮内存；
- 附件不落库，解析完即弃。

## 7. 实现清单（供排期）

1. 后端 exceljs 依赖 + `tickets/export.service.ts`（生成 xlsx：详情导出 + 空模板）；
2. `POST /tickets/import/parse`：exceljs 读表 → 行映射 → 复用 parser 的 matchCustomers/matchPeople 做实体匹配 → 返回 ParsedTicket[]；
3. 前端：详情页/列表页导出按钮、模板下载链接；
4. 前端：导入弹窗（文件选择 → 逐行确认，复用 QuickTicketConfirm 或在其基础上包一层行导航）；
5. e2e：模板导出→导入回环（导出的文件原样导入，字段无损）；表头错误拒绝；模糊匹配命中。
