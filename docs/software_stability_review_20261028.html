1交接摘要

先修发布链路，再修生命周期，最后扩展功能

已经证明可用

  • 多相机：标记检测、外参计算、拼接、DB 入库、PLY 导出均跑通。
  • 移动拼接：2 机位自动配准并生成独立结果。
  • 转台：离线标定算法可执行；机器人：离线界面与数据加载正常。
  • 关闭会话时的保存/放弃/取消保护有效。
  • 核心算法与工作流自动测试总体稳定，未发生本轮 GUI 崩溃。

距离稳定版的主要差距

  • 交付物不一致：当前压缩包仍为 v1.6.1，与源码 v1.13.17 严重错位。
  • 质量门禁未全绿：UI 架构测试有 1 项失败。
  • 验证覆盖不足：实体相机、真实转台/机器人、打包客户机与长稳测试未覆盖。
  • 退出与任务生命周期仍有结构性风险：存在强制退出与无限等待路径。
  • 细节完成度不足：重复文案、内部英文状态、空元数据、静默操作等。
发布建议：先形成 v1.13.18 稳定修复候选版，完成全部 P0/P1 和发布验收；崩溃恢复、表面质量报告等完整新增能力再进入 v1.14.0。不要在当前版本上继续叠加机器人运动控制等大范围功能。

P1STB-003退出路径同时存在强制结束进程与无限等待的稳定性风险

代码风险（本轮未复现崩溃）

普通后台任务等待 3 秒后仍运行时，main.py 会调用 os._exit()；必须完成的任务则使用无超时 worker.wait()。前者可能跳过正常析构和缓冲刷新，后者可能让关闭窗口永久卡住。

影响

在 SDK 卡死、原生调用异常或慢磁盘场景下，用户可能遇到“直接消失”或“永远无法退出”；诊断信息与未完成任务状态也不完整。

代码位置

main.py:167-172 — pending 非空时强制退出src/ui_v2/backend_bridge.py:2612-2654 — 3 秒有界等待与 B 类无限等待src/ui_v2/backend_bridge.py:2656-2669 — 用户放弃后任务降级

修改方向

为任务提供协作取消、状态机和明确的关闭阶段；写盘任务给出进度、超时诊断与可恢复临时文件。正常退出不再走强制终止；确需最后兜底时，应生成完整转储、明确提示并限制在不可恢复异常路径。

验收：注入慢 SDK、永不返回任务、写盘失败和关闭竞争；窗口可预期退出或给出明确恢复选择，无 QThread 析构崩溃、无静默数据丢失。
P1ARC-004后台任务语义依赖字符串判断，BackendBridge 职责过度集中

5新增功能建议

优先补足稳定性与质量可信度，而非扩大功能面

F1 · 高优先级 / 数据安全

崩溃恢复与会话检查点

利用私有临时工作区定期保存轻量检查点；异常重启后提供“恢复 / 放弃”选择。只有用户显式保存才更新正式 sessions/，不恢复后台外参自动保存。

验收：模拟进程被杀后可恢复原始帧、识别状态、外参和结果来源；正式快照不被静默改写。

F2 · 高优先级 / 可观测性

统一任务中心与安全取消

展示任务阶段、进度、耗时、目标项目和失败详情；支持安全取消与重试，关闭窗口时复用同一任务状态机。

对应 UX-006、STB-003；先覆盖识别、拼接、保存、导出。

F3 · 高优先级 / 质量可信

表面拼接质量报告与导出门禁

现有 RMS 主要是标记拟合误差，不等于整个表面精度。新增重叠覆盖率、双向最近距离分布、偏差热图、有效点数与来源信息；报告随会话和 PLY 导出。

验收：低重叠、局部错位、离群点能被发现；报告明确测量范围和近似误差，不将标记 RMS 宣称为表面精度。

F4 · 中优先级 / 支持效率

一键诊断包

导出基础版本、Git 提交、操作系统、GPU/OpenGL、SDK/DLL 版本、设备状态、任务日志和最近崩溃信息；默认不包含原始图像、点云及敏感路径，需用户确认后生成。

验收：诊断包可定位版本错配、缺库、设备占用、超时和原生崩溃；不上传、不自动联网。

F5 · 中优先级 / 发布自检

启动环境自检

检查必需 DLL、SDK 初始化、项目目录可写性、OpenGL 可用性和版本一致性；失败时给出具体修复建议，不只显示“未知错误”。

验收：缺失运行库、只读目录和软件 OpenGL 环境均有确定行为与可执行提示。

F6 · 中优先级 / 可测试性

完整离线验收夹具与一键验收

为四工作区提供确定性的成功/失败样例和期望结果，尤其补足机器人 3+ 离面姿态、转台已知角度和坏帧；统一生成离线验收报告。

验收：无硬件环境可重复执行完整核心流程，结果可比较，默认不初始化真实 SDK。

6实施与回退计划

建议 2 个短迭代，不并行扩张大型新功能

第 1 阶段 · 候选版止血（1–2 天）

  • 修正 UI 架构测试并覆盖 robot，达到 13/13 回归脚本通过。
  • 修复重复文案、英文状态、空元数据、静默导出和过期注释。
  • 隔离默认测试中的真实 SDK；让构建在缺少 DLL 时立即失败。
  • 生成与源码一致的 v1.13.18 候选包，保留测试和哈希证据。

第 2 阶段 · 生命周期与端到端补口（3–5 天）

  • 引入 TaskSpec 和任务状态机，先消除正常路径强制退出与无限等待。
  • 补齐机器人完整夹具、转台已知角度样例和真实失败路径。
  • 建立 CI 与干净 Windows 安装冒烟；执行实体相机/断连/占用/多网卡矩阵。
  • 完成 2 小时长稳与目标 DPI/GPU 测试，再决定是否发布稳定版。

第 3 阶段 · 稳定后增强（下一个 MINOR）

  • 交付崩溃恢复、任务中心、表面质量报告、一键诊断包。
  • 按测试覆盖逐步拆分 BackendBridge，不做一次性大重写。
  • 机器人品牌 TCP/运动控制等独立大功能另行立项，不阻塞当前稳定版。
回退要求：每个修复批次必须保留可运行的上一提交和上一安装包；出现数据损坏、核心流程阻断或无法启动时立即停止发布并回退。回退不得删除用户会话或私有工作区，数据库格式变化须先验证向前/向后兼容性。
