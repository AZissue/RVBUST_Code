# 会话提示词（Session Prompts）

> 本项目提交策略：**本地提交照常**（每个阶段都有本地提交，便于回溯与审计）；
> `git push` 只在用户明确说“推送”时执行。

## 一次性初始化（已完成）
```bash
git init
git add -A && git commit -m "chore: git 初始化基线（文档迁移前工程状态）"
```

## 下次会话启用（每次新会话开头粘贴）
```text
新会话启用：请先读取 AGENTS.md 并遵守其中的规则。然后依次：1) 读取 STATUS.md
顶部的“交接块”；2) 读取 PLAN.md 的当前阶段；3) 读取 PROJECT.md 中与当前任务
相关的约束。最后复述你对当前进度和下一步的理解，确认无误后直接执行。若发现
文档与代码矛盾，停下说明再继续。
```

## 会话收尾（每次结束前执行，或直接并入 AGENTS.md 的会话仪式）
```text
会话收尾：请按以下顺序收尾：
1. 更新 STATUS.md：刷新交接块（当前状态、下一步、风险），把本次完成内容移入
   “已完成”，记录新发现的 BUG、失败尝试及原因；
2. 检查 PROJECT.md / PLAN.md 是否因本次工作需要同步修改（需求变更、技术决策、
   阶段完成），需要则一并更新；
3. 运行 `ctest -C Release` 与冒烟（`start.bat --demo <ply> --autoquit N`），
   确认无回归；
4. 本地 git 提交本次改动（Conventional Commits）；不 `git push`，除非用户明确
   说“推送”。
全程禁止破坏性命令，除非用户明确要求。
```

## 推送触发（仅当用户明确说“推送”时执行）
```text
推送触发：1. 最后检查并刷新 STATUS.md 交接块；2. `git status` 确认无敏感 /
大文件被加入（对照 AGENTS.md 边界）；3. 需要时先本地提交，再 `git push`；
不执行 push，除非用户明确要求。
```
