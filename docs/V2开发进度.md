# 技术支持系统 V2 开发进度

更新时间：2026-09-16

## 工单-借测/维修联动闭环 M1–M4（2026-09-16）

- 工单分类「售前咨询/借测需求」可勾选自动创建借测单入队，「硬件故障」可勾选自动创建维修单；随时可在工单详情补建，幂等防重（部分唯一索引 + P2002 兜底）。
- 双向时间线：借测评分/借出/归还/逾期、维修流转、双方跟进自动回写工单时间线（LINK_* 事件）；工单「客户回复」自动同步为子单 SYSTEM 跟进；syncedFrom 标记 + SYSTEM 跳过防回声。
- 状态汇聚：有进行中子单时拦截关单并提示单号；子单全部完结显示收尾横幅；维修关闭写闭环事件（含结论）。
- 6 类联动通知 + 每小时超时催办 cron（阈值可在系统设置页配置）；创建工单勾选默认值走 `linkage.defaultCreate` 配置。
- 仪表盘新增「联动待办」区（待完善/待评分/维修超时/借测逾期，按归属过滤）。
- e2e 两条完整业务闭环实测通过；单测 136 项全过。详见 [工单借测维修联动_20260916.md](工单借测维修联动_20260916.md)。

## 统一 AI 接口管理（2026-09-04）

- 新增 AI Provider、功能分配、调用日志三张独立表和管理员配置页面。
- 支持 DeepSeek、Kimi、OpenAI、自定义 OpenAI-Compatible 的统一 Gateway/Adapter；模型名称可编辑。
- API Key 提交前公钥加密，后端 AES-256-GCM 加密存储；配置读取只返回掩码。
- 快速工单优先 AI 解析，严格原文/JSON 校验后再匹配真实数据；失败自动降级规则解析。
- 共享总超时、最多一次重试、并发保护、地址校验、Token 与错误元数据日志。
- 验证：单元测试 40 项、API 集成 39 项、Playwright 3 条流程通过，生产构建通过。
- 实际服务商连接待用户配置真实 API Key；未伪造外部连通性结果。其他 AI 业务仅预留。
- 完整安全边界、文件位置、接口及使用方式见 [AI集成说明.md](AI集成说明.md)。本轮代码对应 GitHub 的 `crm_system_v2` 分支。
- 已部署至本机原 V2 目录，API 健康检查与页面只读验收通过；正式库仍为 1 张工单、2 条工作事项、1 条工作记录，未配置任何模拟 Provider。

## 工作台与事项交互优化（2026-09-03）

- 首页重构为“今日工作台”，顶部精简为五个横向指标。
- 桌面采用 70% 推进区与 30% 快速记录/时间线布局，移动端自动单列。
- 工作事项由传统表格改为任务列表，增加状态点、进度条、截止时间和轻量完成操作。
- 进度支持 5% 步进滑杆及 0/25/50/75/100 快捷选择，全部通过 API 持久化。
- 进度到 100% 时提示是否完成，不自动改变状态；完成操作统一写入 100% 和 completedAt。
- 增加右侧事项详情抽屉，可编辑事项字段并查看下一步及关联工作记录。
- 增加列表/看板视图，按待开始、进行中、等待反馈、已完成分列。
- 统计报表从每日工作台拆出，新增七日趋势、工作类型和工单状态可视化。

## 已完成

- React + NestJS + PostgreSQL + Prisma 模块化单体骨架与 Docker Compose。
- Session 登录、bcrypt 密码哈希、退出失效、登录限流、账号停用、RBAC 与对象级权限。
- 用户、团队、客户公司、联系人、设备、项目、站内通知、系统设置和操作审计基础能力。
- Ticket 工单：完整核心字段、负责人/协作人、状态流转、可见级别和事件时间线。
- Work Item 工作事项：独立状态、优先级、进度、负责人/协作人、客户/项目可选关联。
- Work Log 工作记录：可独立记录，或关联工单、工作事项、客户和项目。
- 数据库维护的 17 类工作分类及系统设置维护界面。
- “我的工作台”：事项统计、工单统计、今日记录和快速记录入口。
- `rawText -> 多条草稿 -> 用户确认` 的完整前后端数据流。
- 浅色、深色、跟随系统三种主题及桌面/移动端响应式导航。
- V1 lowdb 默认预检、显式应用且不迁移明文密码的导入工具。

## 已知限制

- 快速记录目前按标点确定性拆分，不做真正语义识别；用户必须确认草稿。
- 报表页面当前仅复用阶段一工作台数据，不代表最终日报/周报/月报实现。
- `customer` 门户用户体系已于 2026-09-15 移除；如未来需要客户在线提交借测/报修，需重建账号体系（见 [移除customer门户用户_20260916.md](移除customer门户用户_20260916.md)）。
- `test/` 下 3 个存量 e2e（app / quick-ticket / ticket-workbench）仍引用已删除的 customer 账号，运行时失败待清理，不影响构建与单测。
- 本机便携 PostgreSQL 仅用于开发验收，不是生产部署方案。
