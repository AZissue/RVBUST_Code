# 客户板块功能实现方案

> 背景：客户模块框架已建好（列表+分级+详情页+关联数据），但**内容侧基本空白**——背景/场景/需求无人填、联系人录了改不了、负责人没入口。本文档给出补齐方案。
> 内容来源优势：手头已有《重点客户档案_20260903.md》（25 家 S/A/B 级客户的互联网调研：官网/行业/规模/3D 视觉相关线索），正是最初需求里"类似百度百科的词条描述"，可直接作为首批填充内容。

---

## 一、现状盘点

### 已有（不用动）
- 客户列表：分页、搜索、S/A/B/C 分级筛选与徽章（本次新增）
- 详情页框架：等级徽章、官网/百科链接、背景介绍/应用场景/项目需求三张卡片、联系人/设备/进行中工单摘要、工单/借测/返修/设备四个记录页签
- 数据模型：`background / applicationScenarios / projectNeeds / websiteUrl / wikiRef / notes / region / industry / technicalOwnerId / businessOwnerId` 字段全在，**只是 UI 没有编辑入口或内容为空**
- 后端 API：联系人改/删、客户 PATCH 全字段、AI 网关（features 配置机制，目前只挂了 quick_ticket_parser）

### 缺口
| 缺口 | 说明 |
|---|---|
| 编辑资料字段不全 | 弹窗只有名称/等级/官网/百科/三段长文本，**缺地区、行业、备注、技术负责人、商务负责人** |
| 联系人只能加不能管 | 无编辑/删除/设主要联系人的 UI（API 已具备） |
| 三段长文本全靠手填 | "待补充"是默认状态，没有辅助手段 → 填不动 |
| 无跟进机制 | S 级"重点跟进"没有载体：联系记录、下次跟进时间都没有 |
| 无统计视角 | 客户活跃度、月度工单趋势、问题分布看不到（重点客户档案里的画像指标就是证据：这些正是想看的） |

## 二、目标形态

客户 360 = **资料**（背景/场景/需求/链接，AI 辅助生成+人工修订）+ **关系**（联系人卡片化管理、内外部负责人）+ **关联数据**（工单/设备/借测/返修，已有）+ **分级**（已有）+ **跟进**（新增：记录+提醒）+ **统计**（新增：画像指标）

## 三、分期实施

### 一期：资料补全与编辑能力（零数据库改动，纯前端 + 现有 API）

1. **编辑资料弹窗补字段**：地区、行业、备注、技术负责人、商务负责人（下拉选工程师，同工单负责人机制；API 已支持）
2. **联系人卡片化**：摘要区展开为联系人小卡片（姓名/职位/电话/微信，电话可点击复制），支持编辑、删除、设为主要（API 已有 `PATCH /contacts/:id`、`DELETE /contacts/:id`）
3. **创建客户弹窗补官网/百科链接入口**
4. **长文本粘贴优化**：三段卡片支持一键粘贴 markdown 纯文本（现状已可编辑，仅加提示）

### 二期：AI 辅助填充 + 存量内容导入（复用 AI 网关，改动小）

5. **AI 生成客户画像**：AI 网关注册新 feature `customer_profile_writer`（providers/features 机制现成，照 quick_ticket_parser 模式加一个 key + prompt 模板）。输入：公司名 + 官网/百科链接 + 该客户历史工单标题摘要；输出：背景介绍/应用场景/项目需求三段草稿。**前端在编辑弹窗加"AI 生成"按钮，生成后人工修订再保存**（与"AI 总结标题"同一交互模式，不自动落库）
6. **首批内容导入**：把《重点客户档案》25 家的调研结果导成种子格式（每家的背景/行业/官网/规模段落 → 对应字段），写成一次性脚本从 markdown 灌入，或做个管理员的"粘贴导入"入口。没有 AI 网关密钥也能先把 S/A 级客户填满
7. **无 AI 时的降级**：保留手动粘贴，AI 按钮在未配置网关时隐藏（现有 features 机制已支持按功能开关）

### 三期：跟进机制 + 客户画像统计（需要新表）

8. **客户跟进记录**：新表 `customer_followups`（id, organizationId, userId, content, nextFollowAt, createdAt）；详情页加"跟进"页签（时间线样式，复用工单跟进记录交互）；支持"下次跟进时间"→ 复用现有通知服务到期提醒
9. **客户画像看板**：详情页顶部加迷你统计——本月/累计工单数、问题分类分布条、近 6 月工单趋势、设备/借测/返修汇总（指标口径直接参考重点客户档案：活跃度、分类分布、等级分布）
10. **S 级客户工作台**：首页/仪表盘加"重点客户"区块（S 级列表 + 最近跟进时间 + 待跟进提醒），支撑"重点跟进"的落地

## 四、数据库变更评估

- 一期、二期：**零迁移**（字段和 AI 配置表都已存在）
- 三期：`customer_followups` 一张新表 + migration；通知复用现有表

## 五、验证方式

- 一期：编辑弹窗全字段往返、联系人增删改/设主要、创建客户带链接
- 二期：AI 生成（有/无网关密钥两种路径）、25 家档案导入后抽查 3 家与调研原文对照
- 三期：跟进记录写入/时间线展示/到期通知触发；画像数字与 SQL 抽查核对

## 六、建议启动顺序

一期先做（一两天工作量，立刻解决"录了改不了"的痛点）；二期第 6 条（档案导入）不依赖 AI、随时可做，建议紧跟一期——这样 S/A 级客户先有人味儿；AI 生成等网关配好再接；三期跟进机制看实际使用反馈再排期。
