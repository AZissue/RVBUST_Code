## 3. 实施顺序的候选排法（路线对比）

| 排法 | 做法 | 优点 | 代价/风险 | 结论 |
|---|---|---|---|---|
| **① 门禁串行、按依赖推进**（推荐） | S0 提交 → S1 修缺陷 → S2 ICP → S3 合并 → S4 裁切/ROI → S5 UI 冒烟 → S6 性能 → S7 并入 | 每步一个可机械判定的小门；diff 干净可审；verify 每步有独立复现对象 | 总时长＝各步之和，无并行压缩 | **采用** |
| ② P0 五项一起做、一次性交 verify | 一轮做完 P0-1/2/4/5 | 交付轮次少 | 同文件（cc_properties/cc_workspace）多处改动混在一个 diff；出问题无法定位是哪项；verify 只能整体判"不通过"，返工面大 | 否 |
| ③ 先并壳（P3）后补功能 | 先把 workspace 搬进 `src/ui_v2/workspaces/` 再补 ICP/裁切 | 最早看到"进主程序"的效果 | 违反项目既定口径"验证形态=交付形态"（v2 目前零 UI 级测试）；门禁从 1 处变 2 处（原型 + src 双份回归） | 否 |
