## 内存口径（命题 3）

- 原样跑 committed `tools/perf_probe.py`（station_9.ply）：`read=0.27s ... RSS=0MB`、`[LOD] 1.27s RSS=0MB peak=0MB`、`[法线] 7.04s RSS=0MB` → @lead 的 0MB 现象**可复现**（同时也说明该探针的 LOD/法线耗时数字有效，只有内存列无效）。
- 最小对照（`mem_min.py`，干净进程，先占 500MB）：committed 写法 `[0.0, 0.0]`；修正写法 `rv=true, RSS=539.0MB, Peak=539.0MB`；第三方 oracle `tasklist` 同刻读数 `219,492 K` vs 修正后 224.7MB（±2%，见 run1.log）。
- 根因：`ctypes.windll.kernel32.GetCurrentProcess()` 未声明 `restype`，默认 `c_int` 返回 **-1**，作为 32 位实参传入 → 句柄无效 → `GetProcessMemoryInfo` 返回 FALSE 且**返回值未检查** → 结构体保持 0。
- 修法（一行）：`k32.GetCurrentProcess.restype = ctypes.c_void_p`（建议另加 `psapi.GetProcessMemoryInfo.argtypes/restype` 并断言返回真）。oracle 备用：`tasklist /FI "PID eq <pid>" /FO CSV /NH`。
- 影响面：仅 `tools/perf_probe.py`；`app/`、`core/` 全仓未使用 `psapi` → 对程序本身无影响（备注级）。

- 观察 vs 期望：根节点 `center=[nan,nan,nan]`、`half_size=nan`（`core/cc_octree_lod.py:89-92` 用**未过滤**点算 mins/maxs）；同一相机位 query 只返回 **500 点，其中 212 点(42%)是 NaN**；对同文件清洗后的 872,946 点建树，同参数 query 返回 **369,286 点、0 NaN**。期望：显示与输入点云一致。

- 归属：`core/cc_octree_lod.py:89-92` 未过滤非有限点（同文件 `app/cc_workspace.py:472`、`app/cc_gl_viewer.py:377/722` 都做了 `isfinite` 过滤 → 口径不一致）。
