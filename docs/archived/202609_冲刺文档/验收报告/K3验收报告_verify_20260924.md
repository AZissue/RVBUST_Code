## 一、缺陷清单

### D1′（测试缺陷，中）判据 5「导出前后 `can_undo/can_redo` 不变」的断言无判别力

复现三件套：
1. **入口**：`D:/Program Files/Anaconda/envs/rvc/python.exe C:/Users/jingz/AppData/Local/hermes/profiles/verify/cache/scratch/probe_k3_assert_power.py`（变异：`export_cloud` 追加一条历史 + `_history_index += 1`，等价于"导出误入历史"；`--no-mut` 为对照）
2. **步骤**：复刻 smoke 主链（载入 → 可见性 → `estimate_normals` → 右键导出），比较两种断言。
3. **观察**：

```
[变异=开] 布尔对 前=(True, False) 后=(True, False) → 现判据漏判(PASS)
[变异=开] 栈深   前=(1, 0) 后=(2, 1)             → 建议判据捕获
[变异=关] 布尔对 前=(True, False) 后=(True, False) → 现判据漏判(PASS)
[变异=关] 栈深   前=(1, 0) 后=(1, 0)             → 建议判据漏判（无假阳性）
```

**根因**：主链里 `estimate_normals` 先入历史，导出前已是 `(can_undo=True, can_redo=False)`；此时再 append 一条并使 idx+1，布尔对不变 → `assertEqual` 恒真。断言**存在**（`tests/test_ui_smoke.py:117-118,137-138`，非只写不报错），但只覆盖"历史被清空/被 reset"这一种污染。
**修法（一行）**：把快照改为 `(len(self._ws._workflow._history), self._ws._workflow._history_index)`（或 `list(_history)`）导出前后相等。实测该写法对同一变异捕获、无变异时不误报。
**产品行为**：**正确** —— 未污染历史，verify 独立实测 `前=(False,False) 后=(False,False)`（空历史场景）与栈深 `(1,0) 前后相等`。
