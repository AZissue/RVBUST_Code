## 结论 2（W14）：**能**（offscreen 合成拖拽可覆盖同一条载入路径）

spike 结构：`WS(QWidget)` 内 `setAcceptDrops(True)`，`dialog_load()` 走 `QFileDialog.getOpenFileNames`（monkeypatch）→ `_load_files(paths)`；`dropEvent` 解 `mimeData().urls()` → 同一 `_load_files`；两入口共享同一绑定函数。

| 探针 | 结果 |
|---|---|
| 对话框路径 | `DIALOG calls: [('_load_files', ('D:/tmp/a.ply','D:/tmp/b.ply'))]` |
| 合成 `QDragEnterEvent`+`QDropEvent` 经 `QApplication.sendEvent` | `sendEvent ret: True True`，`dropEvent` 被调用，路径完整：`DROP calls: [..., ('_load_files', (...))]`，`dragEnter` 命中 1 次 |
| 未 `show()` 的裸 widget | 同样收到（`NOSHOW calls: [...]`）→ CI 可无窗口 |
| 空 `QMimeData`（无 url） | **不触发载入**（调用数不增）→ 边界行为正确 |
| 直接 `w.dropEvent(ev)`（绕过分发的写法） | 也可行（备选写法） |
| 两入口同函数 | `same fn shared: True` |

**建议验收口径（G-S3.5-c）**：断言拖拽与对话框两入口产出**完全相同的 `_load_files` 实参元组**（本 spike 已示范），而不是只断言"树多了节点"。

**残留风险 1 条（低成本）**：合成 `sendEvent` 是直投 workspace，覆盖不到 Qt 真机拖拽的**落点命中测试**（`childAt` 落在 GL viewer/树子控件上时是否被吞）。→ 真机做一次手动拖拽即可（并入 G-S3.5-a 真机步，≈0 成本），不必为此加 CI 复杂度。
