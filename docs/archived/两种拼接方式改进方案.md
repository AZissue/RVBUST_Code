# MultiCameraCalibration 项目改进方案：多相机外参标定 + 单相机移动链式拼接

> 文档性质：设计思路梳理（未改动任何源码）
> 适用项目：`D:\RVC_SRC\Python\MultiCameraCalibration`
> 日期：2026-08-05

---

## 1. 背景与目标

当前系统要支持两种截然不同的场景拼接方式，但软件操作流程被抽象成了同一条流水线（「虚拟相机」把单相机多机位伪装成多相机），导致两种方式在软件里走同一套「拍摄 → 检测 → 手动标定 → 手动拼接」流程，与真实使用逻辑严重不符。

本方案把系统重构为**两种主体功能**，各自拥有**独立的 UI 设计与工作流程**：

- **功能一：多相机外参标定拼接**（多台相机固定安装，先标定后扫描）
- **功能二：单相机移动链式拼接**（一台相机移动拍摄，边走边拼）

---

## 2. 现状梳理：项目现有能力

| 模块 | 现有能力 | 对应需求 |
|---|---|---|
| `camera_manager.py` | N 相机统一管理（camera_id 键），软触发同步/异步拍摄 | 功能一步骤 1、2 ✅ |
| `marker_detector.py` | 编码圆 2D+3D 检测 + 非对称圆标定板检测（含位姿估计） | 功能一步骤 3 ✅（两种标记物均支持） |
| `calibration_engine.py` | RANSAC+SVD Kabsch pair 标定、多帧四元数平均（已修 q/-q 歧义）、标定板位姿法、JSON 保存/加载 | 功能一步骤 4 ✅ |
| `pose_graph.py` | 链式拓扑 BFS 复合变换；全局优化目前仅 BFS 生成树（真 BA 留 TODO） | 功能二链式基础 ✅ |
| `stitch_engine.py` | N 路点云变换到参考系合并、后处理、批量拼接、PLY 保存 | 功能一步骤 6 ✅ |
| `station_manager.py` | 单相机多站位：拍一帧即存盘、注册为虚拟相机 `station_N` | 功能二的帧管理部分 ✅ |
| `offline_session.py` | 拍摄帧落盘 → 批量检测/标定/拼接，可离线重放 | 数据缓存与重放 ✅ |

**关键现状问题**：`StationManager` 的设计哲学是「站位 ID 与相机 ID 在框架中完全等价」，把功能二**伪装成**功能一，于是两种模式共用同一套 UI 流程，产生三个具体痛点：

1. 功能二的用户被迫理解「参考相机」「pair 标定」等面向功能一的术语；
2. 功能二没有「自动识别共有标记 → 链式拼接 → 重合度评估」的引导，全靠手动；
3. 功能一缺少「撤板重拍（扫描阶段）」的独立工作流，标定帧与扫描帧混在一个 `frames` 字典里。

## 3. 核心矛盾：两种流程的本质差异

| 维度 | 功能一：多相机外参标定 | 功能二：单相机移动链式拼接 |
|---|---|---|
| 相机 | 多台**固定**，位置不可变 | 一台**移动**，机位可任意 |
| 标定时机 | **一次性**：先标定外参（可存盘复用），之后反复扫描 | **无预标定**：边走边算，每次拍摄即时配准 |
| 标记物角色 | 标定板**可撤**：标完撤板再拍被测物 | 标记物**常驻**：它就是配准锚点，靠相邻机位共有标记衔接 |
| 共视假设 | 星型：所有相机共视同一块板（或链式相邻共视） | **只要求相邻机位共有 ≥3 个编码圆**，无需全局共视 |
| 拼接触发 | 手动，全量一次性 | 增量、实时，每加一机位自动更新 |
| 误差评估 | pair RMS / 内点率（已有） | 需要**重合度评估 + 链式累积误差**（目前完全没有） |
| 核心算法 | 外参标定（两阶段：先标后扫） | **增量配准 + 位姿图**（类似视觉 SLAM 关键帧机制） |
| 用户操作心智 | 「一次装好，重复使用」 | 「边走边拍，实时看结果」 |

### 3.1 现有代码的具体差距

1. **功能一的「撤板重拍」没有工作流支持**：`frames` 是「当前帧」语义，标定帧与扫描帧没有分开管理，撤板后重拍会覆盖标定数据。需要**标定阶段/扫描阶段的显式状态机**。
2. **功能二缺少「自动识别共有标记」的驱动逻辑**：`_match_markers`（code 交集匹配）已存在，但只被「手动选 pair → 标定」调用。
3. **功能二缺少增量/实时拼接**：现有拼接是手动触发、全量一次性；功能二需要「每拍一帧 → 自动配准 → 更新位姿图 → 刷新拼接点云」。
4. **功能二缺少误差评估与漂移控制**：「重合度评估误差」零实现；`pose_graph.optimize_global` 只是 BFS 复合，真正的全局 BA 未做。
5. **UI 没有按操作心智分流**：功能二用户被迫使用功能一的术语和面板，缺少实时反馈与引导。

## 4. 总体架构：两种主体功能

```
┌────────────────────────────────────────────────────────────────┐
│                    MultiCameraCalibration                       │
│                    主窗口（模式切换器）                           │
│         ┌──────────────────────┬──────────────────────┐         │
│         │  功能一（多相机）      │  功能二（移动拼接）    │         │
│         │  FixedMultiCamWorkflow│  MobileChainWorkflow │         │
│         │  标定阶段 ↔ 扫描阶段   │  机位累积 + 实时拼接  │         │
│         └──────────────────────┴──────────────────────┘         │
│           共用底座：设备管理 / 3D查看器 / 日志 / 会话保存          │
└────────────────────────────────────────────────────────────────┘

共用核心（现有模块复用）：
  CameraManager（多相机） / StationManager（拍帧即存盘）
  MarkerDetector（检测） / CalibrationEngine（pair 标定）
  PoseGraph（链式 + 全局优化） / StitchEngine（合并）
```

**设计原则**：
- 两种功能是**平级的两个主体**，不是同一功能的两个选项——入口处明确区分，避免用户混淆；
- 共用底座（设备管理、3D 查看器、日志、会话）抽为公共区域，避免两套重复代码；
- 算法层继续复用现有模块（见 §8 复用清单），工作流层与 UI 层各自独立。

## 5. 功能一：多相机外参标定拼接（FixedMultiCamWorkflow）

### 5.1 工作流程（状态机）

```
[标定阶段] 连接多相机 → 同步/异步拍摄(标定板全共视)
        → 检测标记/标定板 → 标定外参 → 保存外参JSON
              │（外参锁定, 相机不可移动）
              ▼
[扫描阶段] 撤掉标定板 → 重新拍摄被测场景 → 一键拼接 → 保存PLY
              │
              ▼
      （可反复扫描多次，外参复用；或回到标定阶段重新标定）
```

状态机要点：
- **标定阶段（Calibration Phase）**：目标产物是 `calibration.json`；允许修改相机连接、重新拍摄、重新标定；
- **扫描阶段（Scan Phase）**：目标产物是拼接点云；外参只读（锁定图标），拼接不要求检测到标记物，纯几何变换 + 合并；
- 两阶段共享同一批相机帧缓存，但**帧数据分区存放**（`frames_calib/` 与 `frames_scan/`），互不覆盖；
- 标定质量不达标（RMS 过高 / 内点率过低）时，禁止进入扫描阶段。

### 5.2 UI 设计

```
┌─────────────────────────────────────────────────────────────────────┐
│ [功能一:多相机外参标定] [功能二:移动链式拼接]   模式切换器(顶部)       │
├─────────────────────────────────────────────────────────────────────┤
│ ① 步骤条:  连接相机 → 拍摄标定 → 检测 → 标定 → 扫描 → 保存          │
│             (当前步骤高亮, 前置未完成步骤置灰, 点击可回退)            │
├──────────────┬──────────────────────────────────────────────────────┤
│ 左面板        │  中央: 相机取景网格(多卡片, 同步/异步拍摄)            │
│ ▪ 设备列表    │   ┌──────┐ ┌──────┐ ┌──────┐                        │
│ ▪ 添加/移除   │   │cam0  │ │cam1  │ │cam2  │  每卡片角标:            │
│ ▪ 同步拍摄按钮│   │标记数:12 │标记数:9 │标记数:0 │  ●共视正常           │
│ ▪ 参考相机选择│   └──────┘ └──────┘ └──────┘   ●标记缺失(红)          │

│ ▪ 多帧标定    │   cam0→cam2  1.24   71%    🟡良                     │
│ ▪ 保存/加载   │   标定质量评分条 + 逐点误差详情列表                    │
├──────────────┤──────────────────────────────────────────────────────┤
│ 扫描阶段Tab   │  撤板提醒横幅 → 「开始扫描」→ 重拍 → 「拼接并保存」    │
└──────────────┴──────────────────────────────────────────────────────┘
```

### 5.3 UI 优化建议

1. **向导式步骤条（Wizard）**：把六个动作固化为步骤条，完成才点亮下一步——把「该做什么」直接变成 UI 约束，替代现在的分散按钮。
2. **共视就绪检查**：标定前自动检测每台相机的标记数，任何相机检测到 0 个编码圆就提示「该相机未看到标定板」，避免标定失败后才回头排查。
3. **标定质量可视化**：pair 表格用绿/黄/红配色（RMS < 0.5mm 优 / < 1.5mm 良 / 以上差），扫描按钮在质量不达标时禁用。
4. **外参锁定指示**：进入扫描阶段后显示「🔒 外参已锁定，请勿移动相机」横幅；相机若意外断线重连，提示外参可能失效需重新标定。
5. **标定帧/扫描帧分区展示**：中央网格用 Tab 或颜色区分「标定帧」与「扫描帧」，扫描帧不再挤占标定帧卡片。
6. **扫描批量模式**：支持「连续拍摄 N 次 → 批量拼接保存」的一次性操作（复用 OfflineSession 批量逻辑），适合产线巡检场景。

## 6. 功能二：单相机移动链式拼接（MobileChainWorkflow）

### 6.1 工作流程（状态机）

```
连接相机 → 拍摄机位1(自动检测) → 移动 → 拍摄机位2
        → 自动匹配共有标记 → 求相对位姿 → 评估(重合度/误差)
              │ 通过(绿)            │ 不通过(红/黄)
              ▼                     ▼
        加入位姿图 → 实时拼接刷新    提示重拍/调整移动距离
              │
              ▼
      拍摄机位3 → ... → 完成 → 保存(会话+点云)
              │
              └→ 检测到与早期机位共有标记 → 提示「可闭环」→ 全局优化
```

状态机要点：
- **无预标定**：每拍一帧即配准，配准成功才入图，失败帧直接拒绝并提示；
- **自动候选匹配**：新帧与「最近 N 个机位 + 参考机位」逐一匹配，取最优（标记数最多且残差最小）；
- **评估门限**：共有标记 ≥6、内点率 ≥0.7、RMS ≤ 阈值，三条件同时满足才接受；
- **实时性**：每帧配准 + 位姿图更新 + 拼接刷新应在 1~2 秒内完成（单帧点云变换合并量小，满足实时要求）；
- **闭环（可选进阶）**：检测到新帧与早期机位（非最近 N 个）共有标记时，提示用户可闭环，触发全局 BA 消除累积漂移。

```
│ ① 机位时间线(左侧竖排):  #1→#2→#3→#4                                │

│    当前机位高亮; 失败机位显示「重拍」按钮                             │
├──────────────┬──────────────────────────────────────────────────────┤
│ 左面板        │  中央上部: 实时取景(当前相机)                         │
│ ▪ 查找/连接   │   ┌──────────────────────────────┐                   │
│ ▪ 拍摄机位    │   │  编码圆检测叠加(绿框+code号)   │  上一机位标记      │
│ ▪ 撤销上一步  │   │  上一机位共有标记: 蓝圈提示     │  的位置提示        │
│ ▪ 自动/手动   │   └──────────────────────────────┘                   │

│ 当前步:       │  └──────────────────────────────┘                    │
│ 共视标记: 9   │                                                     │
│ 内点率: 94%   │  底部状态栏: 链长/累计误差/建议                        │
│ RMS: 0.42mm  │  「重合度充足, 可继续移动」                            │
└──────────────┴──────────────────────────────────────────────────────┘
```

### 6.3 UI 优化建议

1. **机位时间线（核心创新）**：以「链」的形态展示拍摄进度，每个机位节点实时显示质量色标——用户一眼看出哪一步接得不牢，可点击任意节点「重拍该机位」或「删掉该节点」（删除后自动重算后续链）。
2. **实时重合度评估弹窗**：每拍一帧立即弹出评估卡片（共视标记数 / 内点率 / RMS / 建议动作），绿=继续、黄=谨慎（可继续但建议减小移动距离）、红=重拍。**评估结果同时写入机位时间线**，形成可回放的误差报告。
3. **上一机位标记位置提示**：在实时取景上叠加「上一机位检测到的编码圆在当前视野中的位置」（蓝圈）——引导用户移动时保持足够重叠区域，从源头减少配准失败。这是移动拍摄模式下最实用的交互。
4. **实时 3D 增量预览**：拼接视图每加一帧刷新一次，按机位分色显示（`viewer_3d` 已支持多路点云叠加，直接复用），用户「边走边看结果」。
5. **链质量仪表盘**：底部状态栏常驻显示「已接 N 机位 / 累计误差 X mm / 平均单步误差 Y mm」，超过阈值变红并建议做全局优化。
6. **闭环提示**：检测到新帧与早期机位共有标记时，弹「发现闭环，可优化全局精度」按钮，点击执行全局 BA 并显示优化前后误差对比。
7. **自动/手动模式切换**：默认自动（全流程自动配准）；手动模式保留现有「手动选 pair 标定」能力，兼容高级用户与旧习惯。
8. **防误操作**：拍摄按钮与「移动到下一机位」分离；拍完一帧在评估通过前，物理相机移动不会覆盖已拍机位（StationManager 拍帧即存盘已保证）。

## 7. 两种功能 UI 对比与共用组件

| 组件 | 功能一（多相机标定） | 功能二（移动链式） |
|---|---|---|
| 核心视图 | 多相机取景网格 | 单相机取景 + 实时 3D 拼接 |
| 进度呈现 | 横向步骤条（Wizard） | 纵向机位时间线（Chain） |
| 关键反馈 | 标定质量表（pair RMS/内点率） | 重合度评估卡片（实时弹窗） |
| 主要动作 | 同步拍摄 / 标定 / 扫描 / 保存 | 拍摄机位 / 重拍 / 闭环优化 / 保存 |
| 标记物要求 | 标定阶段要求，扫描阶段不要求 | 每帧都要求（常驻锚点） |
| 术语体系 | 参考相机、pair、RMS、内点 | 机位、重合度、链、漂移 |
| 防误操作 | 外参锁定横幅、质量门禁 | 时间线重拍/撤销、移动提示 |

**共用组件（保持一套实现）**：
- 设备查找/连接（`device_panel` 改造为两种模式共用的连接向导）
- 3D 查看器（`viewer_3d`，已支持多路分色叠加）
- 日志面板、加载遮罩、会话保存入口
- 后处理参数面板（裁切/下采样/离群点，两种模式拼接后共用）

**模式切换规则**：顶部模式切换器在「无未保存工作时」允许切换；切换时保留各自独立的工作区状态（两个模式的会话互不干扰），防止误切丢失数据。

## 8. 数据层：两种模式统一的可重放会话

```
scans/<mode>_session_时间戳/
  meta.json              # mode: fixed_multi | mobile_chain, 相机信息, 参考系
  calibration.json       # 功能一：外参结果(复用现有格式)；功能二：位姿图全部边+质量
  frames_calib/ frame_0001/ ...   # 功能一标定帧（分区）
  frames_scan/  frame_0001/ ...   # 功能一扫描帧（分区）
  stations/     station_1/ ...    # 功能二机位帧(复用 StationManager 目录格式)
  error_report.json      # 每步重合度评估 + 链累计误差，可回放复盘
```

- 功能一保存外参后，扫描阶段只需 `calibration.json` + 扫描帧，不依赖标记物；
- 功能二的 `error_report.json` 记录每一步的评估结果，支持事后复盘（哪个机位接得不好、全局优化前后误差对比）。

## 9. 落地路线图（先算法后界面）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P1 算法验证** | 参照 `test_station.py` 合成数据思路，写 ChainStitcher + PoseGraph 增强（增量边/质量评估/全局优化），**不动现有代码**，新增独立模块 | 合成数据链式拼接 RMS 曲线、漂移对比（优化前 vs 后） |

## 11. 关键设计决策备忘

- 共有标记匹配阈值：最少 3 对可解刚性变换，工程上建议 **≥6 对** 才接受该边（RANSAC 更鲁棒）
- 标记物类型：功能一建议标定板（非对称圆标定板，已有位姿法可交叉验证）；功能二建议编码圆（场景中可贴多个，靠 code 唯一性自动识别）
- 误差单位统一为 mm（现有 `rms_mm` 语义；`ransac_threshold` 默认 0.002 对应米单位输入，调用时注意）
- 全局优化参数化：SE(3) 李代数（旋转 so(3) 轴角 + 平移），`scipy.optimize.least_squares` 即可，无需引入 g2o/Ceres
- 实时性预算：功能二单帧配准+拼接刷新目标 ≤2s（RANSAC 100 次迭代 + 单帧点云变换，Open3D 毫秒级，可达标）
- UI 文案语言：面向现场操作员，功能二避免「参考相机/pair/RMS」等标定术语，用「机位/重合度/误差」口语化表达
