# MultiCameraCalibration UI 层审查报告（ui_v2 新 UI + ui 旧 UI）

> 审查日期：2026-08-07 ｜ 范围：`src/ui_v2/*`（含 workspaces/widgets/backend_bridge）、`src/ui/*`、`main.py`、`run_shell.py`
> 验证方式：源码审查 + 关键路径实际执行（conda rvc 环境、offscreen 平台）
> 结论：新 UI 的 shell 层（控件/门控/样式）质量不错，问题集中在 backend_bridge 接线层与两套 UI 并存处；smoke_test 只测 shell 不测 bridge，以下问题全部在冒烟覆盖之外。

## 一、严重问题（功能不可用 / 崩溃 / 数据安全）

### S1 模式 A 后端全流程断裂：标定阶段状态机从未启动 【bug｜功能缺失】
- **位置**：`src/ui_v2/backend_bridge.py:189-214, 216-249, 251-282, 304-322, 324-351` + `src/core/fixed_multi_cam_workflow.py:102-108, 129-137, 196-209`
- **问题**：bridge 的 `_on_multi_capture/_on_multi_detect/_on_multi_calibrate/_on_multi_capture_scan/_on_multi_stitch_save` 直接调用 `fixed_workflow.add_calibration_frame()/calibrate()/add_scan_frame()/stitch()`，但**从不调用 `start_calibration()` / `start_scanning()`**，工作流 `_state` 永远是 `idle`。实测：`add_calibration_frame → False "当前不在标定阶段"`、`calibrate → False`、`stitch → False`。bridge 又无视这些 False 返回值（如 `backend_bridge.py:206`），于是「拍摄」后日志显示成功但 `frames_calib` 为空 → 检测 0 标记 → 标定失败 → 扫描帧/拼接全部落空。
- **建议**：`_on_device_manager_reopened` 连接成功后调用 `fixed_workflow.start_calibration(reference_id)`；`_on_multi_capture` 检查 `add_calibration_frame` 返回值并置 `ws.set_state("captured")`；`_on_multi_calibrate` 成功后调用 `start_scanning()`（或质量门禁通过后显式转入扫描态）；所有 `_work` 返回值不得静默丢弃。

### S2 「重拍当前」按钮恒失败：`station_-1` 不存在 【bug】
- **位置**：`src/ui_v2/workspaces/mobile_chain_workspace.py:152-157`（emit `-1`）+ `src/ui_v2/backend_bridge.py:509-512`（`station_id = f"station_{index}"`）+ `src/core/mobile_chain_workflow.py:217-218`
- **问题**：信号注释写明「-1 表示当前机位」，但 bridge 不处理该约定，直接拼出 `"station_-1"`，`recapture_station` 判 `station_id not in nodes` 恒为真 → 每次点击都返回「指定机位不存在」。
- **建议**：bridge 收到 `-1` 时取 `mobile_workflow.get_station_list()` 最后一项的 `station_id`（或链尾节点 ID），再调 `recapture_station`。

### S3 时间线索引与后端机位 ID 错位（失败拍摄产生空洞） 【状态管理 bug】
- **位置**：`src/core/mobile_chain_workflow.py:120-121, 133`（配准失败 `remove_station` 但 `_station_seq` 不回退）+ `src/ui_v2/workspaces/mobile_chain_workspace.py:257-267`（时间线 index 连续计数）+ `src/ui_v2/backend_bridge.py:509-563`（用 index 直接拼 `station_{index}`）
- **问题**：若第 2 次拍摄配准失败（station_2 被删），第 3 次成功生成 `station_3`；时间线只显示 2 个节点（#1=station_1, #2=station_3）。此时点击节点 #2 → `station_2`（不存在）→ 选中/重拍/删除全部失败。删除中间节点后后续节点索引同样整体错位。
- **建议**：bridge 不再用 index 拼 ID，改为从 `get_station_list()` 按时间线序号取真实 `station_id`；或时间线节点数据携带 `backend_ref`（`StationNodeData.backend_ref` 字段已预留）。

### S4 重拍不替换节点，反而追加新节点 【状态不同步】
- **位置**：`src/ui_v2/backend_bridge.py:526-536`（重拍成功也走 `on_evaluation_done`）+ `src/ui_v2/workspaces/mobile_chain_workspace.py:257-268`（`_station_count += 1` 后 `add_station` 追加）+ `src/ui_v2/widgets/station_timeline.py:192-206`（`update_station` 从未被任何调用方使用）
- **问题**：重拍 station_2（共 3 机位）→ 工作流删除旧节点再拍摄生成新节点，但 UI 侧 `_station_count` 不减反增 → 时间线出现 **4 个节点**，旧 #2 数据仍残留，链顺序与后端不一致。
- **建议**：重拍完成回填时区分「追加」（新机位）与「替换」（重拍），重拍走 `update_station`；bridge 需把「本次是重拍哪个 index」传给 workspace。

### S5 离线演示入口 `run_shell.py` 启动即崩溃 【bug】
- **位置**：`src/ui_v2/run_shell.py:177`
- **问题**：`launcher.network_config_requested.connect(...)` 引用了 `LauncherDialog` **不存在的信号**（`launcher_dialog.py:49-57` 只定义了 `refresh_requested/auto_ip_requested/connect_requested`）。实测：`AttributeError: 'LauncherDialog' object has no attribute 'network_config_requested'`。
- **建议**：删除该行（信号本就不存在），或按设计在 LauncherDialog 中补 `network_config_requested` 信号与「网络配置」按钮。

### S6 `LauncherDialog.set_busy()` 引用不存在的控件 【bug】
- **位置**：`src/ui_v2/launcher_dialog.py:306-312`（`self._btn_net_cfg`）
- **问题**：`set_busy()` 遍历 `(self._btn_connect, self._btn_refresh, self._btn_auto_ip, self._btn_net_cfg)`，但 `_setup_ui` **从未创建 `_btn_net_cfg`**（头部文档声称的「网络配置」按钮也未实现）。实测：`AttributeError`。
- **建议**：删除该引用，或补实现网络配置按钮；`set_busy` 改为只遍历已存在的按钮。

### S7 参考相机下拉数据与后端 camera_id 体系不一致 【状态管理 bug】
- **位置**：`src/ui_v2/workspaces/multi_cam_workspace.py:383`（combo data 用 `d.serial`）+ `src/ui_v2/backend_bridge.py:353-357`（把 serial 当 camera_id 直接赋给 `calibration_engine.reference_id`）+ `src/core/fixed_multi_cam_workflow.py:135-137`（`calibrate()` 用 workflow 自己的 `_reference_id` 查 `frames_calib`，key 是 cam0/cam1）
- **问题**：下拉框 data 是设备序列号，而帧字典/工作流用的是 `camN`。用户切换参考相机后：① `calibration_engine.reference_id` 被设为序列号（永无匹配）；② workflow 的 `_reference_id` 根本没被设置（`start_calibration` 从未调用，见 S1）。参考相机功能形同虚设。
- **建议**：统一 ID 语义——combo data 用与网格一致的 `cam{i}`（`set_devices` 里与 `set_cameras` 同源生成），并通过 `fixed_workflow.start_calibration(reference_id)` 同步设置。

### S8 标定通过后永远进不了「外参锁定」状态，扫描/拼接按钮不可用 【状态机断链】
- **位置**：`src/ui_v2/backend_bridge.py:276-281`（标定成功只 `set_state("calibrated")`）+ `src/ui_v2/workspaces/multi_cam_workspace.py:363-366`（`scan_capture` 需 `locked or (calibrated and quality_passed)`，`stitch_save`/`batch` 需 `locked`）
- **问题**：bridge 中没有任何路径在标定通过后调用 `set_state("locked")`（run_shell 靠 Tab 切换的 mock 逻辑 `run_shell.py:97-100` 在真实接线中不存在）。正常标定完成后「拼接并保存」「批量拼接保存」永远置灰，撤板横幅永不显示。
- **建议**：`_on_multi_calibrate` 质量门禁通过后显式 `ws.set_state("locked")`（并保持 `_btn_save_ext` 可用）；或在工作流事件驱动下统一状态迁移。

### S9 「批量拼接保存」是死按钮 【功能缺失】
- **位置**：`src/ui_v2/workspaces/multi_cam_workspace.py:316-319`（emit `batch_scan_requested`）+ `src/ui_v2/backend_bridge.py:97-108`（`_wire_multi_cam_workspace` 未连接该信号；仅 run_shell mock 连接）
- **问题**：真实应用中点击「批量拼接保存」→ 信号无接收者，**毫无反应**。
- **建议**：bridge 实现 `batch_scan_requested` 槽（循环 N 次 capture_scan + stitch + 保存，后台执行）。

### S10 主窗口「设备管理」重开后无法枚举新设备 【功能缺失】
- **位置**：`src/ui_v2/main_window.py:289-321`（`open_device_manager` 只 `restore_state`，从不 `set_devices`；`refresh_requested` 仅连 lambda 打日志）+ `src/ui_v2/backend_bridge.py:131-147`（`enumerate_devices` 存在但未接线）
- **问题**：重开启动小窗只回显**已连接设备**，看不到其它可用相机；点「刷新」只打一行日志。现场想加相机必须重启程序。
- **建议**：`open_device_manager` 里 `dialog.set_devices(bridge.enumerate_devices())`，并把 `refresh_requested` 接到真实枚举（带 try/except 与失败提示）。

### S11 模式 B「保存拼接数据」是假保存 【功能缺失｜数据安全】
- **位置**：`src/ui_v2/backend_bridge.py:582-588`（`_on_mobile_save` 只 `get_error_report` 后打日志）+ `:635-641`（`_save_mobile_session` 返回「已保存」字符串但**不写任何文件**）
- **问题**：点击保存显示「会话已保存: N 机位」，实际 PLY、error_report.json、会话目录均未生成；用户以为数据已落盘。
- **建议**：调用 `mobile_workflow` 的会话/点云导出（如 `station_manager` 目录归档 + `get_merged_pointcloud()` 写 PLY + 误差报告写 JSON），失败时返回明确错误。

## 二、中等问题（功能不完整 / 状态错乱 / 阻塞）

### M1 模式 B 拍摄/评估期间无门控，可并发连点 【数据竞争】
- **位置**：`src/ui_v2/backend_bridge.py:465-499`（`_on_mobile_capture_station` 全程不设 busy 状态）+ `src/ui_v2/workspaces/mobile_chain_workspace.py:185-203`（`busy` 分支永远不生效）
- **建议**：bridge 在 `_work` 开始前 `ws.set_state("capturing")`，`_done` 里恢复。

### M2 预览定时器在模式切换/断开相机时不停 【资源泄漏/健壮性】
- **位置**：`src/ui_v2/backend_bridge.py:149-153`（`_on_device_manager_reopened` 先 `disconnect_all()`，未先 `_pause_2d_preview()`）+ `:384-393`
- **建议**：`_on_device_manager_reopened` 开头调用 `_pause_2d_preview()`；`set_mode` 切换工作区时停止预览。

### M3 撤销/删除不扣减累计误差 【状态不同步】
- **位置**：`src/ui_v2/workspaces/mobile_chain_workspace.py:288-295`（`on_undo_done` 只删节点、count-1，`_total_error_mm` 不减）
- **建议**：撤销/删除时同步减去该节点 rms（在 `StationNodeData` 里保留 rms 供扣减）。

### M4 全局优化回填假数据且不刷新 3D 【功能缺失】
- **位置**：`src/ui_v2/backend_bridge.py:565-580`（`on_optimize_done(0.0, 0.0)` 硬编码）+ `src/ui_v2/workspaces/mobile_chain_workspace.py:277-286`（用假 `after_mm` 重算累计误差）
- **建议**：`optimize_global` 返回优化前后累计误差（`get_error_report` 对比），成功后刷新 3D。

### M5 重连后相机 ID 无限增长，网格缩略图对不上 【状态不同步】
- **位置**：`src/ui_v2/backend_bridge.py:160`（`f"cam{len(camera_ids)}"`）+ `src/core/camera_manager.py:438`（`disconnect_all` 不清 `_cameras`）+ `src/ui_v2/workspaces/multi_cam_workspace.py:385-386`（网格固定建 cam0..camN-1）
- **建议**：重连前 `remove_camera` 全部旧 ID 或复用旧 ID；`set_devices` 与 bridge 连接用同一 ID 生成规则。

### M6 会话加载残缺：模式 B 空操作、模式 A 丢数据 【功能缺失】
- **位置**：`src/ui_v2/backend_bridge.py:670-685`（模式 B 只打日志「时间线恢复待实现」；模式 A 只取每相机最新帧当标定帧，不恢复扫描帧/外参/标记数/共视状态）
- **建议**：模式 A 恢复 frames_calib + frames_scan + `load_calibration` + 标记叠加；模式 B 按 meta.json 重建时间线节点。

### M7 `_dirty` 脏标记从未置 True，退出/切模式确认框形同虚设 【功能缺失】
- **位置**：`src/ui_v2/backend_bridge.py:611`（唯一一次 `set_dirty(False)`）+ `src/ui_v2/main_window.py:294, 350-352, 418-428`
- **建议**：拍摄/检测/标定/扫描/时间线变化后置脏；保存成功后清脏。

### M8 `_on_multi_step_back` 只打日志，步骤回退无实际功能 【功能缺失】
- **位置**：`src/ui_v2/backend_bridge.py:359-362` + `src/ui_v2/workspaces/multi_cam_workspace.py:467-469`
- **建议**：按 index 回退状态机（清对应阶段的帧/结果并 `set_state`），或暂时禁用可点击回退。

### M9 拼接结果与 PLY 写入在主线程执行 【性能】
- **位置**：`src/ui_v2/backend_bridge.py:324-351`（`_done` 中 `import open3d` + `o3d.io.write_point_cloud` 主线程；大点云写盘可阻塞数秒）
- **建议**：`_work` 里完成写盘，`_done` 只负责日志与刷新 viewer。

### M10 主线程频繁做整链点云合并 【性能】
- **位置**：`src/ui_v2/backend_bridge.py:494-496, 539-541, 556-558`（每拍一帧/撤销/删除后在 `_done` 主线程 `get_merged_pointcloud()`，含全部机位变换+后处理）+ `src/ui/viewer_3d.py:865-882`（`set_pointcloud_merged` 触发 VBO 重建）
- **建议**：合并计算放后台，仅把结果数组传回；viewer 数据量大时降采样上传。

### M11 测试设备按钮进入生产 UI，且可能误连真实设备 【健壮性】
- **位置**：`src/ui_v2/launcher_dialog.py:145-149, 257-272`（`TODO(TEMP)` 测试按钮）+ `src/ui_v2/backend_bridge.py:159`（`backend_ref` 非 int 时默认 `0`）
- **建议**：测试设备仅由 `run_shell` 注入；bridge 对无 `backend_ref` 的设备直接报错并跳过。

### M12 `cleanup()` 可能在线程存活时销毁相机 【健壮性】

- **建议**：wait 超时后记录警告并拒绝强制关闭（或先 shutdown 相机再等线程）。

### M13 旧 UI 拍摄/点云加载全在主线程 【性能】（旧 UI）
- **位置**：`src/ui/main_window.py:975-985, 987-1009, 1054-1062`（capture_all/串行/单拍直接主线程调用）+ `:1086-1091`（主线程 `load_pointcloud_o3d`）

### M14 旧 UI `closeEvent` 无超时等待 【健壮性】（旧 UI）

### M15 ui_v2「纯 UI 空壳、可离线运行」声明与事实不符 【代码质量/维护性】
- **位置**：`src/ui_v2/widgets/__init__.py:13`（导入 camera_grid）+ `src/ui_v2/widgets/camera_grid.py:26-27`（导入 `core.frame_data`、`ui.camera_card`）+ `src/ui_v2/widgets/viewer_panel.py:16`（导入 `ui.viewer_3d`，OpenGL）

- **建议**：要么补齐环境声明（ui_v2 依赖 numpy + ui.viewer_3d），要么把 `numpy_to_qpixmap`/`AspectRatioLabel` 下沉为 ui_v2 自有实现，解除对旧 ui 的依赖。

### M16 新旧 UI 并存、交叉依赖 【架构/维护性】
- **位置**：两套 Launcher（`src/ui/launcher_window.py:217行` vs `src/ui_v2/launcher_dialog.py`）、两套主窗口/日志/遮罩；`src/ui/main_window.py` 2110 行仍在被 `test_ui.py` 维护；新 UI 直接 import 旧 `ui.camera_card`/`ui.viewer_3d`

### M17 预览抓帧在主线程 + 无异常保护 【健壮性/性能】
