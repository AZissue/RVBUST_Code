## 三、需要你决策的问题

### 🔴 决策 1：`min_common_markers` 从 6 降到 3（`mobile_chain_workflow.py:94`）
- 现状：编码圆标记 **3 对**即可解刚性变换（数学下界），但工程建议 ≥6。RANSAC 有 `min_inlier_ratio=0.7` 兜底，但 **3~4 个点对时模型退化风险高**（标记近似共线/共面时解不稳定，0.7 内点率也可能匹配到错误模型）。
- **✅ 用户决策（2026-08-07）**：**保持 3**，接受可靠性下降，现场成功率优先；由用户在 `error_report` 中**增加几何质量指标**（inlier 点空间分布/条件数）用于现场追溯。

### 🟡 决策 2：locked 状态点「拍摄」= 重新标定，**无确认弹窗清空扫描数据**
- `backend_bridge._on_multi_capture`：locked 状态下点拍摄 → `start_calibration()` 清空 `frames_calib/frames_scan/pair_results` + `clear_calibration_results()` + viewer 清空。误点即丢已扫描数据。
- 上轮"重拍参考机位"都有 QMessageBox 确认，这里反而没有——**建议加同样风格的确认框**（"重新标定将清空已扫描数据，是否继续？"）。
