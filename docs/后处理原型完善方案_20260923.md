## 4. 推荐路线与阶段划分

**推荐 A**：目标形态 = `cloudcompare_like`；postprocess_test 降级为参考实现（保留其**已验证**的 ROI 索引映射测试与显示预算设计作为对拍基准）。

### P0 功能与文档闭环（G1/G2/G3/G5）— 必达

2. 合并接线：DB 树多选 → `workflow.merge_clouds`；合并必须走 v1 已验证的"属性对齐"路径，规避 open3d `+=` 属性丢失（v1 README:19 已记录该坑）。
3. core 测试补齐（R1）：为 33 个 public 方法逐一补断言；ICP 用合成已知变换（真值断言，参照 `test_postprocess_workflow.py` 的 fitness/rmse 口径），合并断言颜色/法线属性保留数。
4. README 重写对齐（R3）：已实现的写"已实现 + 测试名"；未实现的（多边形套索/Brush/分段/距离测量/Poisson/Ball Pivoting/圆柱 RANSAC）移入"未实现 backlog"，并删除 `core/cc_processor.py` 一类不存在的条目。
5. `set_undo_enabled/redo_enabled` 接线到 `can_undo/can_redo`（G5）。

### P1 UI 级验证（G4/G8）— 必达
6. 新增 `tests/test_ui_smoke.py`（offscreen；可复用 v1 的实例化 + 本项目 `sync_run` 探针手法）。
7. ROI / 选择交互回归：补 v1 `test_roi_mapping` 口径的用例到 v2——**v2 改为 LOD 显示后，"显示用点集"与"后处理用原始点集"的索引是否仍精确对应，必须有断言**（→ 见 §6 V1）。

### 9.4 V1 口径决策（@verify 提的门）

**决策：ROI 语义 = "投影落在矩形内的全部点"（不含遮挡剔除），本轮不做"可见面"语义。**

理由与连带动作：
1. 索引口径已被证明**精确**（400k 全量/400k LOD/2M LOD 三档 `sel_idx_max=1999999`、`recall_front=1.0`）→ 语义边界清晰，可直接作为 P1 断言基线。
2. 现 `cc_gl_viewer.py:800-829` 的深度可见性判据（`:828 tol = 0.005 + 0.01*sampled`，近远平面 `:405-406 near=extent*0.001 / far=max(extent*5,100)`）在 10M 实测下**恒真**（NDC z 前后层差 1.6e-4，tol ≈ 0.015，差 94 倍）→ 是"看起来支持遮挡剔除、实际不生效"的**假能力**，与 R3「零漂移」直接冲突。**P1 必须处理：删除该判据，或改为显式开关 `include_occluded`（默认 True）并在 README 写明不做遮挡剔除。**
3. 「可见面选择」若要真做，需重做近远平面与深度精度（NDC z 在 extent 量级下被压缩到 1e-4），属独立子任务 → 进 backlog，本轮不排。
