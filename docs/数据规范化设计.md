# 工单系统数据组织与规范化设计

> 视角：系统架构师 + 数据库设计师
> 日期：2026-09-08
> 基线：crm_system_v2 分支（schema.prisma 725 行，25 张表）

## 一、总体评估

当前 schema 整体已达到第三范式（3NF）：

- 主外键关系完整，关联删除策略明确（内部对象 Cascade、外部引用 SetNull/Restrict）
- 多对多均通过中间表（`TicketCollaborator`、`TeamMember`、`LoanItem` 等）实现，无数组外键
- 状态类字段大多使用 PG enum（`TicketStatus`、`LoanStatus`、`RepairStatus` 等），索引覆盖主要查询路径（`assigneeId+status`、`priority+status` 等）
- 审计（`AuditLog`）、通知（`Notification`）、AI 日志（`AIUsageLog`）已与核心域解耦

结论：**不需要结构性重构**，规范化工作是"收敛自由文本字段 + 明确快照语义 + 统一编号/日期格式"的治理性优化。

## 二、问题清单与处置建议

### P0 已落地（本次）

| 字段 | 问题 | 处置 |
| --- | --- | --- |
| `Ticket.category` | 自由文本，已产生 "123"、"技术问题" 等脏数据 | 建立 7 项白名单（售前咨询/客户培训/点云调试/SDK 开发/手眼标定/硬件故障/其他），后端 DTO `IsIn` 强制校验（`common/ticket-categories.ts`），前端统一从 `TICKET_CATEGORIES` 常量取值，快速记录按关键词自动推断分类 |

### P1 建议下一迭代

| 字段 | 问题 | 建议 |
| --- | --- | --- |
| `Ticket.category` | 仍是 VarChar 而非 enum | 观察白名单运行一个迭代后，迁移为 PG enum 或字典表 `TicketCategory(code, label, sortOrder)`（参照 `WorkType` 模式），需配数据清洗 SQL：非白名单值 → `其他` |
| `Ticket.source` 与 `Ticket.category` | 语义重叠（早期需求中两者曾要求合并），并存导致录入困惑 | 建议保留 `category` 作为唯一分类维度，`source` 仅表示工单来源渠道；或反向保留。二者取一为主，另一字段标注废弃 |
| `Ticket.cameraModel / serialNumber / sdkVersion` | 与 `Device` 表字段重复，属冗余 | 明确为**创建时快照语义**（设备信息后续可变，工单需保留事发时环境）。建议：详情页展示时若关联了设备，以设备表为准并标注快照差异；长期可去掉 Ticket 上的重复列 |
| `CustomerOrganization.level` | 自由文本 VarChar(20) | 收敛为字典：战略/重点/普通 或 A/B/C，存字典表或 enum |
| `Project.status` | 自由文本 VarChar(40) | 收敛为 enum：进行中/已交付/已暂停/已终止 |
| `RepairEvent.type` | 自由文本 VarChar(60) | 收敛为 enum，参照 `TicketEventType`（收货/检测/维修/寄回/关闭/备注） |
| `Notification.type` | 自由文本 VarChar(80)，代码中以字符串字面量散布 | 建立后端常量模块（`common/notification-types.ts`）集中定义，禁止字面量 |

### P2 中长期

| 项 | 说明 |
| --- | --- |
| 编号规范 | 工单 `RVC-YYMMDD-NNN`、借测/返修已有独立编号列，建议统一编号生成服务（含并发安全：数据库序列或唯一索引 + 重试），并写入本文档作为唯一标准 |
| 日期/时间语义 | DB 层区分 `@db.Date`（纯日期：借测起止、保修期）与 DateTime（时刻：创建、更新时间），禁止混用；前端展示统一经 `formatDate` 出口 |
| `TicketEvent.metadata` / `AuditLog.metadata` | Json 字段内容无 schema 约束 | 按事件类型定义 metadata 结构（TS 类型 + 文档），写入时校验 |
| 历史数据清洗 | 存量脏分类（"123" 等）在非生产库重建时丢弃；生产迁移时执行 `UPDATE tickets SET category='其他' WHERE category NOT IN (...)` |
| V1 迁移入口 | `migration/import-v1.ts` 的 category 直接取旧值，接入前需加白名单映射，防止脏数据重新进入 |

## 三、规范化约定（新增代码必须遵守）

1. **枚举优先**：新字段若取值可数，一律 PG enum 或字典表，禁止自由文本
2. **单一事实源**：前后端共享的取值列表，后端 `common/*.ts` 为准，前端 `lib/labels.ts` 镜像，注释互相引用
3. **编号、状态、分类、时间格式**以本文档和 `common/`、`lib/labels.ts` 为准，禁止在组件内联新字面量
4. 字典表模式参照现有 `WorkType`（code + label + isActive + sortOrder），支持后台维护与排序
