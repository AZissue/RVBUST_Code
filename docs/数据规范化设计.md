# 工单系统数据组织与规范化设计

> 视角：系统架构师 + 数据库设计师
> 日期：2026-09-08
> 基线：crm_system_v2 分支（schema.prisma 725 行，25 张表）

## 一、总体评估

当前 schema 整体已达到第三范式（3NF）：

- 主外键关系完整，关联删除策略明确（内部对象 Cascade、外部引用 SetNull/Restrict）
- 多对多均通过中间表（`TicketCollaborator`、`TeamMember`、`LoanItem` 等）实现，无数组外键
- 状态类字段大多使用 PG enum（`TicketStatus`、`LoanStatus`、`RepairStatus` 等），索引覆盖主要查询路径（`assigneeId+status`、`priority+status` 等）
- 审计（`AuditLog`）、通知（`Notification`）、AI 日志（`AIUsageLog`）已与核心域解耦

结论：**不需要结构性重构**，规范化工作是"收敛自由文本字段 + 明确快照语义 + 统一编号/日期格式"的治理性优化。

## 三、规范化约定（新增代码必须遵守）

1. **枚举优先**：新字段若取值可数，一律 PG enum 或字典表，禁止自由文本
2. **单一事实源**：前后端共享的取值列表，后端 `common/*.ts` 为准，前端 `lib/labels.ts` 镜像，注释互相引用
3. **编号、状态、分类、时间格式**以本文档和 `common/`、`lib/labels.ts` 为准，禁止在组件内联新字面量
4. 字典表模式参照现有 `WorkType`（code + label + isActive + sortOrder），支持后台维护与排序
