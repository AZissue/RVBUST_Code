## 1. 目标与验收标准（可量化）

### A10 手眼矩阵落文件

| 项 | 内容 |
|---|---|
| 目标 | 矩阵不再靠"复制粘贴"传递：可导出为带元数据的文件，可被本原型与外部工具读回，读写无损且可复核 |
| 验收 A10-1 | **写→读→逐元素比对**：`max｜Δ｜ < 1e-12`（用 Python `repr` 全精度写出时实测应为 **0.0**）；比对对象含 4×4 全部 16 元素，非只比平移 |
| 验收 A10-2 | 文件必含字段：`format` / `version` / `created_at`（ISO8601 带时区）/ `source`（产出工具名+版本或 `manual`）/ `eye_in_hand` / `unit` / `matrix`（16 个，**行优先**，与官方 MAT 口径一致）/ `rms_t_mm` / `rms_r_deg` / `n_samples` / `euler`（`order` / `intrinsic` / `output_format` / `angle_unit`）；缺任一必填字段 → **拒绝加载**，不许补默认值 |
| 验收 A10-3 | **单位单一真相源**：文件含 `unit` 时以文件为准；UI 单位选择若与文件**冲突** → 拒绝并提示（禁止静默取其一）。文件缺 `unit`（= MCC `handeye.py` 旧 JSON）→ UI 单位**仍必选**（主方案 A2 ⑤、D4 不变） |
| 验收 A10-4 | 负向用例（至少 4 类必须被拒）：缺 `unit`；`unit` 与 UI 冲突；`eye_in_hand` 与矩阵键（`T_cam2tool`/`T_cam2base`）不一致；矩阵非刚性（det=−1 / 非正交 / 末行错）—— 后三类复用 `unit_guard.check_rigid_4x4()`，**禁第二份实现**（主方案 §4.2） |
| 验收 A10-5 | 与既有加载器**并存不回归**：MCC 旧 JSON（键 `T_cam2tool/T_tool2cam/T_cam2base/T_base2cam`，无 `unit`）仍按原路径加载；`test_handeye_result.py` 全绿 |

### A11 位姿数据列表 + 欧拉角顺序自动判定

| 项 | 内容 |
|---|---|
| A11-① 去品牌先验 | 数据列表 UI **没有**品牌下拉、没有机型预设；判定只用数值本身 |
| A11-② 数据列表 | 每行 = 一条记录（`xyz` 原文 / `rpy` 原文 / `unit` / 来源 / 时间）；支持追加、编辑、删除、清空、导入 CSV；行号是**判定结论的唯一索引**（结论必须指回行号，不许只给"第 3 组"这类模糊说法） |
| A11-③ 自动判定 | 候选集**全枚举** → 每组做**完整 6DOF 手眼最小二乘拟合** → 输出**全部候选的 rms 排名表**；**只有唯一通过**才给结论；否则输出"激励不足/多解"并**并列**候选 |
| A11-④ 输出格式 | `xyz` = 平移（mm，单位按 A2 归一）；`Rx Ry Rz` = 按判定出的 `order` 换算，单位**度**，全精度（`repr` 级）；同一屏同时显示 `order`、rms、通过判据、以及该结论对应的数据行号集合 |
| 验收 A11-1（正） | 合成 oracle：真值约定注入（12 个 Tait-Bryan 逐一），**必须唯一挑出真值**，其余候选 rms 全部超阈；**[V-spike] 真值 XYZ 实测 rms=0.000000，其余最差 103.5** |
| 验收 A11-2（位数下限） | n=3/4/5 一般位姿均唯一通过（`[V-spike]` 1/12）；工具硬下限 **n ≥ 3**（与 A3 戳点门禁同为 3），<3 直接拒绝执行 |
| 验收 A11-3（退化必报多解） | 只绕单轴旋转的激励 **必须报"多解"**，不许给答案：`[V-spike]` 纯 Z 轴 8 位姿 → **4/12 通过（XYZ / YXZ / xyz / yxz）**；把 Y 向激励加到 **±3°** 才回到 1/12 |
| 验收 A11-4（弱判据禁用） | 禁止用"相对旋转角不变性"类弱判据定案：`[V-spike]` n=3 时 **6/24 通过**、n≥5 仍 **3/24 通过**，残差全是 1e-16 → 无法定案。代码里如出现该判据的**定案分支**（而非诊断打印）即判不合规 |
| 验收 A11-5（稳定性） | **留一检验**：逐个剔除一条记录后重跑，结论（`order`）必须不变；发生翻转 → 按"激励不足"处理并给出需要补的激励方向 |
| 验收 A11-6（单位先行） | 判定前先把平移**统一归一为 mm**（复用 A2 入口 + 范数窗口）。理由：残差向量是**混合量纲**（旋转 deg 与平移 mm 同权），同一批数据用 m 还是 mm 会**改变排名与阈值比较结果** → 不归一 = 不可复现 |

**判据口径钉死（A11-③ 细则）**

1. 残差 = 对每条记录，`E = inv(T_target2cam) @ (X @ inv(T_base2tool) @ T_target2base)`，取旋转部分转 rotvec（**度**）与平移部分（**mm**）拼接；对 12 参数（X 6 + T_target2base 6）做 `least_squares(method='lm')`，多起点取最优（`[V-spike]` 用 3~4 个随机起点）。
2. **阈值分引擎、且是"噪声底"不是魔数**（**v2.2 修正，真实数据实测驱动**）：
   - **合成/离线路径（自研拟合 rms）**：合成无噪时 `rms < 0.05`；真实噪声下取 `pass_tol = max(0.05 mm, 3σ)`（σ = 真值分支上留一/子集重采样的离散度，B ≥ 10）。
   - **现场路径（SDK `totalMeanError`）**：同式。真实数据集实测 **σ = 0.0642（留一）/ 0.1110（子集）→ `pass_tol = 0.333 mm`**。
   - **⚠️ `0.05 mm` 不是绝对门限**：它的正确含义是"与 `poseType=0` 基线的**差值**"（KB §4.4 原意）—— 真实数据真值分支 `tme = 2.05 mm`，按绝对 0.05 判会把**真值自己判失败**。可用时优先用它：`|tme(候选) − tme(poseType=0)| < 0.05 mm`（实测真值差 **0.000000**、错约定 **78~440 mm**），是近乎确定性的确认；DLL 自动判断不覆盖该顺序（真值 ∉ {RXRYRZ, RZRYRX}）时退回排名判据。
3. 定案附加条件：**第一名/第二名 ≥ 10 倍，且只用全量数据判**（**v2.2 修正**：留一掩码下错约定的误差会掉到真值附近——实测剔除 #13/#25 时降到 **9.77× / 9.98×**，若允许在掩码上判倍数差，A11 四条门禁会互相打架：同一批数据一边"唯一通过"、一边"边界需补数据"）。**留一检验只断言"冠军不变"**（实测 27/27 不变）。
4. 结论一律**带排名表**（全部候选，含未通过者），禁止只输出一个答案 —— 这是 @verify 对主方案的硬要求，也是与"品牌先验"划清界限的证据。
5. **SDK 调用参数固定**（v2.2，@verify 真实数据实测驱动）：`poseType=3` / `markerType=0` / `isPointCloudMm=false` / `isPoseMm=true` / `isEyeInHand=false` / **`autoRemoveLargeErrorData=false`**，并把**保留组数**一起进排名表。**厂商默认 `true` 会让排名失效**：错约定靠丢数据刷出比真值更低的误差 —— 实测 `yxz`/deg **1.422 mm（仅保留 10/27）** vs 真值 `xyz`/deg **2.052 mm（27/27）**。用默认值 = 判错顺序。

**激励质量前置校验（A11-③ 前置，硬条款）**

在排队候选之前，先判数据能否支撑定案；不满足则**直接拒绝出结论**：

| 检查 | 判据（初值，@dev 实现时取值须与 @verify 一致） | 依据 |
|---|---|---|
| 位姿数（**去重后**） | **去重后的不同旋转条数 ≥ 3** —— 逐位相同的重复位姿对顺序判定零贡献，按总条数计会虚高 | @verify 真实数据集实测（27 组内含逐位相同的位姿） |
| 旋转轴张成维数 | **存在性判据**：至少有两个主轴方向夹角 ≥ 5°（即旋转轴集合张成 ≥ 2 维）→ 通过；张不成 ≥2 维 → 判"只绕单轴" | `[V-spike]` 纯 Z 轴反例 + @verify 真实数据集反证（轴夹角分布 0~90°，"任意一对 <5° 即拒"会把这套真实数据误判为激励不足） |
| 平移散布 | 平移点集 PCA 最小奇异值 < 5 mm（近共线/共面）→ 判"平移激励不足" | 退化几何 |
| 阈值可分辨 | 上述通过后再查第 3 条倍数差 | 本条 |

> **口径说明**：激励不足时程序**只输出"多解 + 需要补什么方向的数据"**，绝不"猜一个最像的"。`[V-spike]` 的 4/12 反例正是"给了答案但答案是错的"的形态 —— 这是本功能最危险的失败模式。

## 3. 候选路线对比（顺序判定的求解引擎）

### 路线 1 —— 自研最小二乘（`[V-spike]` 的 40 行实现）
- 做法：把 @verify 的 `full_handeye.py` 收编为 `core/order_detect.py` 的拟合内核（12 参数，LM，多起点）。
- 优点：已验证（唯一性、位数下限、退化反例全部实测过）；纯 numpy/scipy，零外部依赖；残差口径完全可控（混合量纲、阈值口径由我们定）。
- 代价：多一份求解实现（主方案 D1 原本"不含标定求解"）；需明确它**只用于判定顺序**，不产出交付矩阵。
- 风险：现场噪声下阈值需重标。

### 路线 2 —— 复用厂商 `HandEyeSDK`（跑 N 次枚举）
- 做法：24 个约定各跑一次 SDK 求解，比 `rms_t_mm/rms_r_deg` 排名。
- 优点：引擎与交付链路同源（现场拿到的矩阵就是这个引擎产的）；不新增算法代码。
- 代价：SDK 的 `rms` 是**内符合**指标（主方案 A3：退化数据下**恒为 0**，不能当可用性判据）→ 单独用它排名，在激励不足时会给出"多个候选都很好"甚至"错的候选更好"的结论，正是 A11-3 要拦的形态。
- 风险：**只靠内符合排名就定案 = 把 A3 已经关闭的坑重开一遍**。

### 路线 3 —— 不判定，保留手选顺序
- 优点：零风险。代价：正是 @user 明确要消掉的操作负担（U4），且现场最容易错的一步就是这里（主方案 K1/D4 的同类错误）。

### 推荐：**路线 1 为判定引擎 + 路线 2 作交叉复核（两者结论必须一致）**

- 判定用路线 1（残差口径可控、已验证、能出排名表与激励检查）；
- **定案前必须与路线 2 交叉**：用判定出的 `order` 喂 SDK 求解一次，其内符合指标与路线 1 的残差同向；两引擎结论冲突 → 不出结论，转"需人工/补数据"。
- 为什么不选路线 2 单跑：`[V-spike]` 的退化反例（4/12 通过）说明"能拟合上"≠"判对"，而 SDK 的 `rms` 在退化数据上恒 0（A3 已实证），单引擎排名无判别力。
- 为什么不选路线 3：直接违背 U4。

**v2 裁决（依据本机 KB 实读，见 §10.2）**：**现场路径以厂商 SDK 为主判据**（候选约定各转矩阵 → `poseType=3` 喂 `HandEyeCalibrationMarker` → 比 `totalMeanError`），这**不是**我新发明的办法，而是 KB `手眼标定SDK集成指南.md` §4.4 已写明的官方判定法；**自研拟合（路线 1）退为离线/合成单测引擎 + 交叉复核**（现场目录里的 png/ply 无法合成，路线 1 是唯一能跑单元测试与 oracle 的引擎）。两口径结论必须一致才定案。
