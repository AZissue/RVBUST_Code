# 《设备维修借测管理工具 V22》分析与复用方案

> 分析对象：`设备维修借测管理工具_V22_演示版(1).html`（单文件演示工具，1709 行）
> 目的：评估可复用代码/设计，吸收进 crm_system_v2 现有借测/返修/设备模块
> 结论先行：**该工具最有价值的是「语义粘贴智能解析」的正则体系，其次是设备健康度/到期状态等纯函数规则和返厂单版式；其数据层（localStorage）和编号实现（扫全表取 max）不可直接用，现有系统在这两块已更优。**

---

## 一、V22 工具概况

- **纯前端单文件**，无后端，数据全部存 localStorage（图片为 base64），注释里也自认"正式使用应改服务器存储"
- 原生 JS 约 70 个全局函数平铺，无框架无模块化；CDN 依赖 html2canvas / jsPDF / tesseract.js(OCR) / jszip
- 布局：左侧 240px 侧边栏 + 4 个页签（设备总览 / 维修管理 / 借测管理 / 回收站）+ 隐藏的新建工单表单页 + 5 个浮层（详情抽屉/设备弹窗/到期提醒/图片灯箱/打印页）
- **数据模型**：工单合一表用 `type` 区分维修/借测；设备档案从工单派生 upsert；无独立联系人实体
- 已有功能：语义粘贴录入、协议 PDF 识别（文字层→OCR 回退）、六面图+配件图槽位、到期提醒（每天首次弹一次）、返厂单 PDF、JSZip 图片打包、回收站、演示数据一键种入

## 二、与现有系统能力对照

| 能力 | V22 工具 | crm_system_v2 现状 | 差距 |
|---|---|---|---|
| 编号生成 | 内存扫全表 max+1，无并发保护 | 事务内 `nextSerial`，原子生成 | **现有更优，无需动** |
| 借测逾期 | 前端按日期实时算标签 | 服务端逾期检测 + 通知（loans.service.ts:33） | 现有更优 |
| 返厂单 PDF | html2canvas 截图版 | pdf-lib 服务端生成 + 存附件（return-pdf.ts） | 现有更优，**版式可对齐 V22** |
| 状态机 | 维修三态/借测二态，无校验 | DB 枚举 + 独立模块 | 模型不同，不照搬 |
| 语义粘贴解析 | ✅ 一整套高质量正则 | ❌ 仅工单有快速解析，借测/返修没有 | **最大缺口，建议吸收** |
| 协议 PDF 识别 | ✅ pdf.js + tesseract 回退 | ❌ 无 | 可选，二期 |
| 设备健康度 | ✅ 维修≥2/借测≥10 阈值 | ❌ 无 | 低成本吸收 |
| 客户流转链 | ✅ A→B→C 节点链 | ❌ 无 | UI 亮点，可选 |
| 图片压缩 | ✅ 前端压到 ≤700KB | 仅 BUG 反馈页有压缩 | 可吸收复用 |
| 图片打包下载 | ✅ JSZip | ❌ 单张下载 | 小功能，可补 |
| 六面图槽位 | ✅ 固定标签槽位 | 返修有照片但无固定槽位 | 可选 |

## 三、复用清单（按性价比排序）

### P0 — 语义粘贴智能解析（强烈推荐，一期做）

**来源**：V22 行 930–1136（`detectPhone/detectModel/detectSN/detectAddress/detectName/detectCompany/detectLogistics` + `KNOWN_MODELS` 型号表 + `semanticParse` 汇总）。

- 纯函数、零 DOM 依赖，可近乎原样搬进前端
- 正则质量高：手机/固话、中文地址分级、公司后缀识别、物流单号排除（排除手机号/SN/日期干扰）
- **落地方案**：在借测管理、返修管理的新建弹窗顶部加一个"粘贴智能填充"输入框（与工单快速记录同风格），前端本地解析直接回填表单字段，不走高亮——解析失败不阻塞手动录入
- 注意：V22 行 1110–1114 的物流回填 id 与实际表单 id 不一致是其自身 bug，搬运时按正确 id 映射

### P1 — 返厂单 PDF 版式对齐（一期，工作量小）

- 客户实际在用的返厂单格式：大字居中标题 + 日期角标 + 黑框表格（报修单位/报修人/电话/SN/外观/原因/回寄地址/销售/售后）+ 注意事项
- 现有 `apps/api/src/repairs/return-pdf.ts` 是 pdf-lib 实现，**只需按 V22 `#pdfSheet`（行 545–562 + 样式 92–102）调整版式字段和排版**，生成方式不动
- 单据里的销售/售后姓名、回寄地址来自设置默认值（V22 行 1616），落地时对应到系统设置表

### P2 — 设备健康度 + 流转链（二期）

- 健康度规则（V22 行 1394–1399）：维修≥2 或借测≥10 = 建议检查；维修=1 或借测≥6 = 关注；否则正常
- 落地为后端派生字段（设备列表/详情接口返回），前端用 tag 展示
- 客户流转链（A→B→C 节点）作为设备详情页视觉增强，React 实现简单

### P3 — 图片体验优化（二期）

- 前端压缩（V22 行 678–689，压到 1600px/≤700KB）抽到公共上传组件，借测/返修/BUG 反馈共用
- JSZip 打包下载该单全部图片（现有是单张下载）
- 返修照片增加"六面图+配件图"固定槽位标签（V22 `photoLabels`）

### P4 — 协议 PDF 字段识别（三期，看实际需求）

- pdf.js 文字层提取 + 字段数 <4 或文字 <80 字符时 tesseract OCR 回退 + 正则抽取（公司名称/地址/授权代表/电话/型号/归还日期/配件/协议号）
- 建议放后端异步任务，识别结果回填借测单；先确认实际使用频次再投入

## 四、不建议吸收的部分

- **localStorage 数据层、回收站结构、视图状态恢复**：现有 Postgres + deletedAt 软删除 + NestJS service 已覆盖
- **编号生成扫全表取 max**：并发必撞号，现有事务内生成已解决
- **维修/借测合一表模型**：现有三模块独立建模更合理，不为对齐而重构
- html2canvas 截图式 PDF：现有 pdf-lib 矢量生成质量更高

## 五、实施建议

一期（借测/返修新建体验 + 返厂单版式）：
1. 前端抽取 V22 语义解析正则为独立模块（如 `apps/web/src/lib/paste-parse.ts`），配单测
2. LoansPage / RepairsPage 新建弹窗加"粘贴智能填充"区
3. return-pdf.ts 版式按 V22 单据重排，销售/售后/回寄地址读系统设置

二期：设备健康度后端派生字段 + 流转链 UI + 图片压缩/打包公共组件

三期（可选）：协议 PDF 识别后端异步任务

## 六、验证方式

- 语义解析：把 V22 演示文本样例（seed/addDemoData 里的地址、电话、公司组合）做成前端单测用例
- 返厂单 PDF：生成后与客户现用纸质/打印版逐字段对照
