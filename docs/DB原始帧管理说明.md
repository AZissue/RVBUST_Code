# 新版 DB 原始帧管理

新版三个工作区左侧增加 DB 树，上方管理原始数据，下方保留功能参数，两者高度可拖动调整。
旧版不新增 DB 界面，也不改变原有会话文件格式。

## 数据组织

按“采集批次 → 单帧”两层显示；相机、用途、状态与图像尺寸可在帧提示中查看，多相机帧名同时显示相机 ID。
每个单帧绑定原始 PLY 和对应 PNG，不再逐层展开文件节点；移动机位保留物理相机 ID 和逻辑机位名。
点数为有序点云的原始点槽位数，包含无效深度占位点，以保留 2D 像素与 3D 索引对应。

新版每次 3D 拍摄先在采集线程内保存完整数据对、提交索引，再向工作流返回无 SDK 句柄的稳定帧引用。
保存期间与采集共用 SDK 锁，保存失败不报告拍摄成功。连续 2D 实时取景不逐帧入库。
标定、拼接和重拍产生的处理结果不覆盖 DB 原始数据；配准失败、撤销机位或重新标定也不删除原始帧。

项目自带离线数据先入 DB 再拼接；现有离线会话加载的有效帧也会归档。
DB 自动保存于项目内 `offline_data/frame_db/<模式>_<时间>_<项目ID>/`：

```
index.json
frames/<稳定帧ID>/pointmap.ply
frames/<稳定帧ID>/image.png
```

索引保存会话、相机、用途、逻辑帧名、点数及识别记录，不持有 SDK 资源；大量点云按需读取。
整目录可移动或复制，使用“打开 DB 项目”选择 `index.json` 恢复数据树。
打开 DB 只浏览原始数据，不恢复标定外参或当前拼接状态；原有“保存/打开会话”仍用于工作流程快照。

## 单帧查看

选择帧节点，会同时载入该帧点云与 2D 图像，仅在右侧显示图像，左侧不再重复预览。
多相机归档图像在右侧独立预览，相机卡片仍保存业务帧供采集/检测使用；单相机/转台复用已有右上角2D窗口。
3D 下拉框明确显示“DB原始单帧 / 相机坐标”，避免将未配准的原始帧误认为全局拼接结果。
点击“返回工作视图”恢复原来的显示；重新执行采集/处理动作也会先退出 DB 单帧预览。
显示采样和无效点过滤只发生在预览中，原始数据对不下采样、不裁剪。

DB 保存成功不等于重建配准成功，后者仍使用正式质量门禁。
单帧读取或索引打开失败会显示原因，并保留当前工作视图。

## 删除与恢复

选中单帧或整个批次，点击 DB 标题旁“删除”。支持 Ctrl/Shift 多选。
右键菜单提供“删除选中数据”“清空当前 DB”“恢复上次删除”和展开/折叠；空白处右键也能清空 DB。
删除前显示本次帧数及工作流影响，正在采集/计算或转台自动采集期间禁止删除。

删除将成对数据移入同一 DB 目录的 `.trash/<删除批次>/<帧ID>/`，并从树中移除。
回收记录随索引保存，重新打开项目仍可恢复最近一批删除；连续恢复可找回更早批次。
删除归档不代表退出当前拼接，当前工作流及标定结果继续保留；需要退出拼接时使用原有机位删除功能。
工作流仍引用该归档时，路径同步跟随移到回收区，后续保存/处理仍可读取，也不会把该帧自动重新加入 DB。
离线测试源文件及独立工作流副本不会删除。回收区仍占磁盘空间，本次不提供永久擦除。

## 验证边界

单元及界面检查使用小型离线数据和模拟 SDK 保存接口；真实凳子原始数据验证树、图像和点云联动及源文件保留。
没有实体相机、转台或客户安装包验收；新增原始归档的磁盘写入耗时需在目标硬件上测量。
