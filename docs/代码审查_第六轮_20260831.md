## 四、P0 / P1 问题清单（本轮新增）

### P0-1｜离线加载会话后删除/撤销/失败帧任一操作 → rmtree 删除整个会话目录（数据丢失，core 子代理探针 D + 主代理交叉验证实锤）

- **位置**：`mobile_chain_workflow.py:182`（load_session_dir 构造 FrameData `offline_dir=session_dir` **会话根目录**）+ `station_manager.py:184-185`（remove_station `shutil.rmtree(frame.offline_dir)`）
- **问题**：30a390a 新增的 `load_session_dir` 把每帧 `offline_dir` 设为会话根目录，而在线拍摄路径 capture_station 设置的是 **station 子目录**（station_manager.py:153-155 `frame.save(self._session_dir, frame_dir=frame_dir)`）。语义不一致 → 离线加载后走 `remove_station`（三条 UI 可达路径：mobile_chain_workflow.py:240 配准失败自动删、:296-298 删除机位、:330 撤销上一机位）时，`rmtree(frame.offline_dir)` 直接**删除整个会话目录下所有站位的 png/ply/meta.json**。
- **探针实测**：构造含 3 个 station 子目录的会话 + offline_dir=会话根的 FrameData → `remove_station('station_2')` 后会话目录整体消失（3 站数据全灭）。
- **影响**：**P0 数据丢失**。UI 链路真实可达：`_on_mobile_offline_load` 加载 → 用户删除/撤销任一机位 → 全会话被删；离线加载后继续拍摄的失败帧同样引爆（attach_session 已设 `_session_dir`，新站写入同一会话）。
- **修复（可抄，一行级）**：load_session_dir 里 `offline_dir` 改为各站 `station_dir`（与在线路径一致）；或 remove_station 改为按 `frame.offline_pointmap_path` 的父目录删除。推荐前者。
- **验证**：探针 D 修复后重跑 → remove_station 后会话目录仍在、仅目标 station 子目录消失。
